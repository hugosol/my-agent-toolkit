# 04: connect-bot 登记失败、恢复与准入约束

**What to build:** 自动登记失败后，用户仍可继续 agent 工作和原有手动操作，实际 State 不错误开启。启动恢复旧会话不能把旧开启载荷当作本次已连接；自动模式与命令模式遵循相同的既有准入条件，不为子代理或无 UI 场景绕过限制。

**Delivers:** P19, P22, P23；P24 的 connect-bot 分区。

**Test owner for:** P24 的 connect-bot 分区；codebase-tools 分区由 02 编写测试，全部分区满足后 P24 才完成。

**Blocked by:** 03: connect-bot 非阻塞自动登记成功路径。

**Status:** ready-for-agent

依据：[已批准契约](../contract.md)、[Spec](../spec.md)。

- [ ] 用受控登记失败场景核对原有关闭和反馈规则；失败后无错误开启、无 heartbeat，仍可完成真实模型请求及原有手动操作。
- [ ] 不新增自动重试、失败恢复编排或放宽业务成功判定，也不通过抑制原有反馈让检查通过。
- [ ] 独立进程启动恢复带旧开启载荷的首次会话，仅新的有效登记 receipt 可以开启；保持 memory，不新增连接记忆或启用偏好写入。
- [ ] 覆盖无有效旧开启载荷的启动恢复对照，确认进程启动恢复仍参与首次启动策略，而非被当作运行中导航跳过。
- [ ] 分别驱动子代理、无 UI 及其他既有登记拒绝条件，维持原有反馈或静默规则，无登记请求及无启用效果；不改变 none 继承策略或放开准入。
- [ ] 经 S1 公共装配 interface 控制错误与准入，使用 S2 真实 OMP 和隔离进程观察请求、恢复及反馈效果，不以私有 State 或模拟客户端调用代替要求的真实观察。
- [ ] 为 P19 准备失败场景、隔离启动命令、终端截图或录制与自动结果；仅 OMP 实际终端的失败反馈及关闭显示留给用户确认，其他可执行检查先完成。
- [ ] 完成受影响用例、所属分区、受影响消费者与真实宿主验证；TypeScript 变更执行类型检查及相关静态检查。记录命令、结果及验证限制，遵守测试协调规则并更新对应说明。
