# 06: 配置拒绝、显式加载与公共装配一致性

**What to build:** 用户通过真实 harness 显式单选或组合加载 extension，配置只影响已加载消费者的启动选择，不隐式加载代码。无效配置拒绝对应绑定并给出可见诊断，有效邻接绑定继续工作。两种模式共享原业务连接参数；从其他项目目录启动仍使用入口明确选择的配置。互斥选择模式入口时不会产生双绑定。

**Delivers:** P1, P5, P6, P28, P29, P31, P34。

**Blocked by:** 01: codebase-tools 双模式首次启动；03: connect-bot 非阻塞自动登记成功路径。

**Status:** ready-for-agent

依据：[已批准契约](../contract.md)、[Spec](../spec.md)。本票不等待失败／准入或 Owner 竞争票；配置与加载闭环可独立验证。

- [ ] 真实 harness 单选及组合加载仅绑定所选 extension；观察命令可用性、所选消费者效果与未选消费者无业务请求，配置中存在条目不能触发代码加载。
- [ ] 文档可解析时，未加载块的错误字段不影响有效已加载块；所加载块的非法值仍被识别，不把局部字段校验与整份文档解析混淆。
- [ ] 覆盖已加载启动配置缺失、类型错误和不可解析场景，产生绑定拒绝和可见诊断，不静默降级；被拒绝者无业务副作用。
- [ ] 在拒绝场景提供配置有效的邻接 extension，确认仍可加载并执行原有操作；需要隔离来源的不可解析场景使用各入口明确选择的独立配置来源，不声称同一不可解析文档仍可解析有效块。
- [ ] 两模式使用同一既有业务配置的受控 endpoint 与请求预算；观察发送目标和受控超时，而不是只比较配置对象。不复制业务连接参数到启动配置。
- [ ] 同一入口从不同临时项目工作目录运行，放置不同干扰配置，通过实际贡献或面板请求确认采用入口所选来源，不只核对计算出的路径。
- [ ] 两真实消费者均由同一公共 framework 装配能力驱动；codebase-tools 纯声明 State 路径无需空业务初始化函数，connect-bot 保留业务登记职责。现有静态检查补充依赖方向和声明可检查性证据，不替代运行证据。
- [ ] 对支持组合真实加载互斥的手动／自动入口集合，确认命令与业务效果唯一；使用说明明确加载来源是追加语义，同一 extension 的两模式不可同时选中。
- [ ] 不为误用增加重复加载检测、自动合并、更改 extension 身份或新的支持组合；不增加热加载、运行时配置档参数或新 runtime。
- [ ] 完成受影响配置／加载用例、所属分区及两个消费者检查，TypeScript 变更执行类型检查、authoring 和 integration 静态检查；真实宿主观察独立记录。遵守共享工作树协调规则并更新对应配置和入口说明。
