## 1. [高] S1 用例停在公共 adapter factory 之下，装配接线只由最慢的真实宿主用例覆盖
**类别**：自动化检查 / 测试 seam
**事实**：契约 S1 的 seam 是“公共 adapter factory 消费的启动配置”，但 `tests/codebase-tools/startup-modes.test.ts` 通过 `portDouble()` 直接调用 `bindExtension`；`tests/framework/support/harness-port-double.ts` 自己把 `startupPolicy` 转发给 `bindExtension`。生产代码中唯一把 `ExtensionAssembly.startupPolicy` 接到 binding 的地方是 `framework/behaviors/assembly.ts`，而框架的 pi surface double（`boundPiSurface`）没有 `startupPolicy` 选项。该接线目前只由 `tests/codebase-tools/startup-modes-dock.test.ts`（约 9 秒）和 pi smoke（约 22 秒）验证。
**推断**：如果 `createAssemblyBinding` 停止转发该选项，S1 与 `bun run typecheck` 都会继续通过，只有真实宿主套件会失败；test double 还复制了生产接线，二者可能漂移。
**建议**：给 `tests/framework/support/pi-surface-double.ts` 的 `boundPiSurface` 增加 assembly 的 `startupPolicy`（必要时加 `configBaseDir`），并加一个经由 `piAdapter` 的廉价用例：首次 start 后值生效、首轮 run 有贡献、持久化记录存在。这样公共 factory 的接线在秒级套件中被覆盖。
**未验证**：该 double 目前是否已完整建模启动写入所需的 branch/`appended` 读取路径——本会话未尝试。

## 7. [低] 既有工具规则在负载下未生效，造成可度量的返工
**类别**：工具经济 / No-ops
**事实**：会话规则明确“NEVER use `sed`|`perl`|`python` via `bash` to issue individual edits；MUST use `edit`”，但本次用 `sed -i` 批量插入 `persist: () => {}`、用 `python` 改票据复选框。行号在插入后漂移，导致三轮带错误的 `typecheck`（8 → 3 → 3 个错误）和额外检查。另：`tests/connect-bot` 首次输出被 `tail` 截断，为分类 5 个失败又完整重跑一次（18 秒）；`docs/agents/testing.md` 已要求长输出落盘。
**推断**：规则文字中的“individual edits”被理解为不含“多处相同插入”，与规则要防止的错误同类；`tail` 重跑本可通过首次就 `tee` 到 run log 避免。
**建议**（harness/规则侧）：对 `sed -i`/`python -c` 写 tracked 文件给出明确警告或拒绝，或在规则里补一个反例（“在 N 个文件插入同一行也算 individual edits，用 N 次 `edit`”）。仓库侧可在 `testing.md` 的“keep runs attributable”处给一条可直接复制的 `… 2>&1 | tee .cache/logs/<run>.log` 示例。
**未验证**：无——返工轮数与重跑均可在记录中核对。
