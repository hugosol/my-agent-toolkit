# 02: 统一收口截止与准确保存诊断

**What to build:** 正常收口从进入时共享默认 15 秒总预算，保存竞争或故障不造成无限等待；截止诊断如实区分可靠未提交与保存结果未确认。

**Delivers:** P30, P31

**Blocked by:** 01：正常处置时完成或截断 Round，并保存自身消费

**Status:** ready-for-agent

- [ ] 使用可控时间验证默认总预算为 15 秒，从进入收口开始计时；已在途保存使用剩余预算，不重新计时或叠加固定等待、额外自动重试。
- [ ] 覆盖截止前后临界点、已消耗部分预算及已完成路径；已完成路径立即收口，不等待预算耗尽。
- [ ] 受控阻塞排队或取锁，在能够可靠取消时报告未提交；受控进入实际更新但无法确认结果时报告保存结果未确认。
- [ ] 两类截止均不发布成功提交提示；对照实际消费文档和诊断，不将停止等待解释为写入已停止或必然未写。
- [ ] 仍由实际更新持有的锁不被提前释放，不改变通用文件更新既有取消含义，不引入事务日志或强杀恢复协议。
- [ ] 真实故障运行记录实际等待、调度误差与退出结果；不以确定性时钟替代真实进程计时，也不要求 OS 毫秒级硬实时。
