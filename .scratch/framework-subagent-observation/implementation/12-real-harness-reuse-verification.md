# 12: 两种进程模式的真实宿主复用验收

**What to build:** 在实际 OMP、pi 前台和 pi 后台中对照验证共同观察含义、同进程零端点路径和 adapter 复用边界，发布可归因的全自动验收报告。报告严格区分确定性检查、真实进程、真实宿主和视觉观察，不把缺失平台／版本或历史结果计为本次通过。

**Delivers:** P24, P34, P35

**Blocked by:** 06 — State follow 与会话观察独立运行；07 — 观察按事件去重，展示合并采用最新值；09 — 合并同步不漏更新，并保护周期与在途累计；11 — 退出总截止有界，准确报告保存结果。

**Status:** ready-for-agent

依据：[已批准 contract](../contract.md)、[spec](../spec.md)。本票为 P24、P34、P35 的唯一完整验收与测试所有者，阻塞关系传递覆盖全部实现贡献。前序票仍拥有各自 promises 的全部测试和真实运行验收，不得把缺失 coverage 转移到本票；本票不是补齐未完成实现的兜底票。

- [ ] 同进程运行通过实际资源／通信观察证明不创建接入端点或定位记录、不执行序列化通信；独立给定事实在同进程与真实跨进程路径得到等价共同观察。
- [ ] 取得本次实际 OMP、pi 前台及 pi 后台回归证据，覆盖实际 detail 表面、首轮提交前读数及后台退出前提交；不能由后台通过推断前台或 OMP 通过，不能以内部 registry 或提供方完成通知替代实际表面。
- [ ] P34 的行为覆盖对照实际同进程与跨进程 adapter 的共同 interface 使用；维护性审查确认原生映射留在 adapter，通信和来源管理在 framework，计费及展示规则在扩展 shared logic，不按 harness 复制这些规则。不为验收实现第三个 harness。
- [ ] 收集并关联各票确定性检查、真实进程、真实宿主、文件提交及视觉观察证据；覆盖 contract 所需正常退出、重连、断连、嵌套、并发、计费归属、失败／截止结果，缺失证据标为未验证而非通过。
- [ ] 分别记录采集／通知、绘制和退出等待测量，不只提交最终截图，不宣称未经测量的性能或零开销。
- [ ] 报告记录源代码／环境状态、harness／第三方版本、操作系统、命令、退出状态、结果、计时及日志；区分执行、通过、失败、未验证。Windows 证据不认证 POSIX，未执行的其他平台和版本显式保留限制。
- [ ] 复用隔离本机兼容端点与临时存储，不依赖付费模型调用，不写操作者真实消费或会话数据；Full automation 下环境阻塞不自动转为人工例外或通过。
- [ ] 按共享工作树协调约定取得稳定验证窗口，故障注入恢复后顺序执行最终 typecheck、全仓测试及契约要求的实际宿主／终端 smoke。记录实际命令、退出状态及失败；前序结果仅在源码、依赖、fixture 和环境均未变化时引用，测试期间变更的树不能作为最终证据。
