# 04: 将上下文采集迁移到 framework 共同消费 interface

**What to build:** OMP 与 pi 通过 framework 的共同 interface 提供各实际会话的上下文 tokens 及采集时模型，model-cost 只消费共同读数，不再并行订阅宿主原生采集事件。

**Delivers:** P11, P12

**Blocked by:** 03：通过共同观察展示正确 Working/Idle

**Status:** ready-for-agent

- [ ] 在会话启动、消息结束及宿主可靠的执行收敛位置采集；每个读数携带该次采集对应的 provider/model，不从当前查看位置借用模型。
- [ ] 同一独立给定的 tokens/model 序列经 OMP 与 pi 映射得到相同共同观察，并在两种实际 harness 路径取得运行证据。
- [ ] 实际显示对照该模型渠道的固定显示预算，不将宿主 context window 作为显示预算。
- [ ] 原生采集留在 adapter，扩展经共同 interface 订阅变化；迁移所有相关消费者并移除扩展并行原生采集路径，不保留双重交付。
- [ ] 不扩大为所有原生模型切换事件的逐事件即时保证；若已承诺采集点无法提供对应模型，报告契约阻塞，不静默缩减 P11。
