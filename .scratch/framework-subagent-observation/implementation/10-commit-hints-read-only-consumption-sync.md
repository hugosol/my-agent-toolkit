# 10: 成功提交后只读采用消费，保持写者、周期与清理顺序

**What to build:** 实际执行会话只累计和保存自己的 usage，保存确认成功后提示 Owner 只读采用文件事实；同步保护本地未提交量和周期边界，正常处置按完整顺序恰好一次地结束、保存、提示并释放资源。

**Delivers:** P16, P17, P20, P29

**Blocked by:** 01：正常处置时完成或截断 Round，并保存自身消费；08：重连恢复快照并隔离迟到、失效来源

**Status:** ready-for-agent

- [ ] 独立给定两会话 usage 算例核对各自记录和含后代总量，每笔响应只计一次；真实子进程提交与 Owner 同步证据证明写者归属，远端观察及重连不重复累计或使 Owner 代写。
- [ ] 只有确认成功的消费提交产生成功提示，提示不携带可替代文件权威的消费累计；失败提交无成功提示。
- [ ] 阻止 Owner 自身提交，子保存后 Owner 仍只读采用文件实际内容；存储访问记录证明接收提示不取写锁、不创建临时文件或发布文档。
- [ ] 独立给定同周期本地未提交量，刷新既不提交也不丢弃该量；采用外部新周期后，旧周期在途量不进入新周期，仅出现新周期允许记录。
- [ ] 只读同步不当作初始化，不改变既有不可用基线、缺失文档与失败政策，不新建账本或观察持久化 schema。
- [ ] 完整拥有 P29 测试：控制异步 handler 和保存完成，完成前不清理，成功后先提示再释放观察来源、连接和 binding；真实宿主记录提交、诊断及退出顺序。
- [ ] 对已收口或已保存部分及重复处置验证恰好一次，不重复 Round 结束、保存或提示；01 提供基础能力但不分担 P29 用例责任。
