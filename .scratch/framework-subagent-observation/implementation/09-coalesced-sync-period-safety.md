# 09: 合并同步不漏更新，并保护周期与在途累计

**What to build:** 多个消费提交提示合并为必要的只读同步；同步期间新提示仍保留后续刷新需求，最终采用文件最新记录。同周期同步保护本地未提交累计，外部更换统计周期后丢弃旧周期在途消费，不将其带入新周期。

**Delivers:** P18, P20

**Blocked by:** 08 — 子会话自行记账，Owner 按成功提示或重连同步。

**Status:** ready-for-agent

依据：[已批准 contract](../contract.md)、[spec](../spec.md)。本票拥有 P18、P20 全部 coverage 与测试，不增加周期账本、消费 schema 迁移、轮询或额外自动重试。

- [ ] 多个可合并提交提示减少实际同步次数，同时最终采用独立给定的最新记录；分别记录提示和同步次数，不只检查最终画面。
- [ ] 受控暂停一次同步，期间另一个实际进程再次提交并通知，恢复后最终新记录可见，不因清理刷新标志永久漏掉后到提示。
- [ ] 独立给定同周期本地未提交累计及外部记录，刷新只采用磁盘基线，不提交、丢弃或重复累计本地在途量。
- [ ] 独立给定旧／新周期与本地旧周期在途量，外部切周期后同步仅保留新周期允许记录，迟到提示不把旧累计带回。
- [ ] 只读同步不取得写锁、不创建临时提交、不修改消费文档；复用既有缺失／无效文档与存储基线政策，不重跑初始化。
- [ ] 按仓库测试规范执行受控并发和周期边界测试、所属存储／计费分区及受影响消费者，TypeScript 变化执行 typecheck；取得真实进程写入与 Owner 可见结果的证据。
