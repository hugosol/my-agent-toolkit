## 3. 仓库级 TS 规则以「编辑中断」形式到达，一处还与本仓库测试约定冲突（编码标准）

**[事实]** 本轮收到四条 builtin-defaults 内联提醒：`ts-no-tiny-functions`（我写的 `states()`/`sameReading()` 两个单表达式辅助函数）、`ts-set-map`（动态 string key 的 `Map`，属误报）、`ts-no-test-timers`（出现在一次**未新增 sleep** 的编辑里，`Bun.sleep` 来自既有 `until()`）、`ts-no-return-type`（`ReturnType<typeof watching>`）。

**[事实]** `docs/agents/testing.md` 明确允许「有界等待另一个进程自己的答复」，本票验收项也明确禁止用概率性等待；而 `ts-no-test-timers` 的字面语义与这两者相反，正是这种张力会诱使下一个 agent 把真实进程的顺序证据换成 fake timer，从而削弱验收强度。`ts-no-tiny-functions` 的后果是积极的（我据它把「每字段来源判定」下移到 `observeActivity/observeContext`，设计变简单），但代价是先写再拆。

建议：

- **机械项**：把 `no-tiny-functions` / `no-return-type` / `set-map` 落成仓库自己的 lint 规则（自定义 lint rule 或 pre-commit），让违规在检查阶段报错，而不是在推理中途打断；`bun run typecheck` 已有，可在其上补一个 `bun run lint`。**[事实]** `package.json` 只有 test/smoke/typecheck 脚本；**[事实]** 仓库根 `ls -a` 无 `.github/`，**[推断]** 因此这些检查可能没有 CI 兜底，建议先确认再决定加 lint 还是加 CI job 还是两者。
- **判断项**：在 `docs/agents/testing.md` 的测试分层处补一句许可——「跨真实进程的有界等待用现有 `until()` 轮询，是允许的既有时序手段；`ts-no-test-timers` 针对的是同进程内的假时间」，把冲突一次讲清。落点：`docs/agents/testing.md`（已是测试约定的唯一来源）。
