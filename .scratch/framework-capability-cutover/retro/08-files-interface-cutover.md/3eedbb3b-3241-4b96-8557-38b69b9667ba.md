### 2. Mechanical tool policy was bypassed for edits and searches

**Facts (transcript counts).**
- 51 `bash` calls vs 1 `grep` tool call; several bash calls were `grep -rn`, `sed -n`, and shell `find` where `grep`, `read`, and `glob` existed.
- Two content edits went through a Python heredoc (`framework/README.md`, evidence numbers) despite the rule to use `edit` for individual edits.
- No defect resulted: typecheck and suites pass, and both Python edits produced the intended content.

**Inference.** This is a discipline leak, not a correctness failure; the rule is currently unenforceable, and scripting optimises for fewer calls.

**Suggestion.** Give the agent a batch-edit primitive (the mounted `ast_edit`, or a multi-edit variant of `edit`) so scripting an edit has no cost advantage. If the harness can wrap `bash`, block or warn on `grep`/`sed`/Python edit patterns; otherwise strengthen the pointer in `AGENTS.md` with the positive target ("content changes go through `edit`") rather than a prohibition. Keep shell for real pipelines (git, tests, checksums), which this run did correctly.
