## 1. 把分区测试串行化做成机械约束（最高）

**事实**：11:57:07 同一轮并行发起 connect-bot 与 model-cost 两个 `bash`；model-cost 出现 3 个存储/时序失败（`no consumption document the case expects was published`），connect-bot 出现 5 个 interop 失败。随后串行重跑 model-cost 为 516/0；connect-bot 设置 `OMP_BOT_BINARY` 后为 142/0。`docs/agents/testing.md` 已明确写着 "Run expensive suites sequentially in a shared working tree"，但顶层工具策略又鼓励 "parallelize independent calls"；测试分区共享工作树、CPU 和临时目录，不属于独立调用。

**推断**：并行失败是资源竞争导致的时序失败，而非产品缺陷；串行通过支持这一判断。

**未验证**：没有做受控实验区分 CPU 争用、临时目录冲突和随机 flake，因此不能断言所有并行失败都由资源竞争引起。

**建议**：在 `scripts/` 增加一个极薄的 test-run lock 包装器（例如 `scripts/run-tests.ts`），所有 `test:*` 脚本和直接分区命令都经它获取 `.cache/worktree-test.lock`；锁被占用时打印持有者 PID/命令并快速失败。最低成本的替代是把 `docs/agents/testing.md` 的串行规则提升为顶部粗体 "never run two partitions concurrently"，并在 `AGENTS.md` 的测试指针中带上 "serial" 一词。机械锁优于文案，因为本次文案已在上下文中仍被违反。
