### 5. 提升专用工具对“带上下文搜索”的覆盖（中-低）

**事实**：148 次 bash 中约 114 条含 shell 等价命令，其中 `sed -n` 和 `grep` 各约 45 次，`head` 约 56 次。很多调用需要 `-A/-B` 上下文来读函数体；`grep` 工具没有 context-lines 参数，`read` 的范围读取可用但没有被优先选择。

**为什么重要**：工具策略明确要求优先使用专用工具；大量 bash 既耗 token，也让结果更容易被截断。Windows shell 还不支持 process substitution，`diff` 也不支持 `-I`，进一步把 agent 推向 `bun -e`/shell 组合。

**建议**：给 `grep` 工具增加 `before`/`after`/`context` 参数；对仓库源码上的 `sed -n`/`grep`/`cat` 加软警告（排除 `git log | head`、`bun ... | tail` 这类命令输出管道）；在 runbook 里补充 Windows 下比较文本的推荐方式（Bun 脚本或仓库 helper），避免依赖不可用的 `diff` 选项。

**置信度**：调用计数是事实；软警告是否噪声取决于实现，未验证。

**建议**：把规则匹配收窄到静态字符串键查找表（`Record`/对象字面量），或在规则中显式排除运行时插入/删除的 `Set`/`Map`。
