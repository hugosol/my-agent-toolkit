# Retrospective — ticket 09 (config entry and model-cost diagnostics)

## Keep (observed working)

The later fault injections (cache guard, copied delivery, diagnostic wording) each produced a concrete failure, so the tests were shown to detect the named violations rather than just pass by construction.

- **The handoff record is scoped.** The evidence file names source state, dependencies, environment, commands, counts, fault injections, the five missing-binary failures and the unverified P48 item instead of claiming full-repository green.

## Findings, highest severity first

### 1. No visible repository guardrail (High)

**Fact.** `package.json` exposes `typecheck`, `test`, and partition scripts, but the worktree root listing showed no `.github` workflow, no pre-commit hook, and no `lint` or `check` script. Every check in this ticket was run manually by the agent.

**Inference.** A future run can land a change that typechecks incompletely or skips a focused suite; nothing in the tree forces the check before handoff.

**Recommendation.** Add a minimal guardrail that runs `bun run typecheck` plus an affected-test selection (or `bun run test` if its cost is acceptable), wired into CI or a pre-commit hook. Expose it as a single `bun run check` so tickets can name one command. If CI already exists outside this worktree, make that fact discoverable from `AGENTS.md` or the testing doc.

**Unverified.** Whether this temporary worktree deliberately omits CI that exists in the host repository.

### 2. Stale navigation docs forced reconciliation (Medium-high)

**Fact.** Before this ticket, `framework/interface/README.md` said `getConfig` “remains at `framework/public` and `core/config`”, `framework/interface/session/README.md` repeated the `framework/public` path, and `framework/docs/capability-interface-architecture.md` still drew `general/index.ts` in the target layout while the approved decision requires three direct entries and no aggregate. The agent had to reconcile all three while implementing.

**Inference.** A later ticket can follow a stale statement and either keep a retired path or reintroduce an aggregate.

**Recommendation.** Keep one current-state table (capability → canonical entry → implementation → removed legacy path → batch status) and update it in the same change that moves the code. In `capability-interface-architecture.md`, separate “current state” from “target direction” explicitly, and list the affected docs in the implementation ticket rather than saying “update affected docs”.

### 3. External spec/contract paths duplicate the worktree copies (Medium)

**Fact.** The assignment supplied spec and contract under `E:\Developer\myhub\my-agent-toolkit\.scratch\...`, while the worktree also contains `.scratch/framework-capability-cutover/spec.md` and `contract.md`. The agent read the external copies.

**Inference.** The two copies can drift; a ticket can be executed against a stale requirement while the worktree holds a newer decision.

**Recommendation.** Point tickets at the worktree-local spec/contract, or state that the external path is canonical and add a hash/check that the worktree copy matches. A single source-of-truth pointer is cheaper than reconciling two documents during implementation.

**Unverified.** Whether the external and worktree copies were identical in this run; the agent did not compare them.

### 4. Missing real-host prerequisite is discovered only after running the partition (Medium)

**Fact.** `bun test tests/connect-bot` produced 137 pass / 5 fail; every failure was the same error: the actual `omp-bot.exe` is absent from `C:\Users\hugos\AppData\Local\Temp\omp-bot\backend\target\release\omp-bot.exe`. The error names the build command, but only after the full directory run.

**Inference.** Future agents will repeatedly spend time on the same 5 interop cases and may misread the red partition as a product regression.

**Recommendation.** Add a short prerequisite note to `docs/agents/testing.md` (which tests need the panel binary, the `OMP_BOT_BINARY` variable, and the non-interop subset command), or a preflight in `tests/connect-bot/support/omp-bot.ts` that reports “interop not run” as a distinct status. Do not silently skip required verification; make the missing prerequisite explicit and attributable.

### 5. The MCP-first instruction was not actionable in this run (Medium)

**Fact.** The user messages repeatedly asked the agent to consider `codebase-memory-mcp` before grep and to inspect an outline before reading source files over 100 lines. The transcript contains no MCP calls; the agent used `grep` and `read` (including large `:raw` ranges). It did use the read tool’s declaration outline for `config.ts` and `consumption-document.ts`, then raw reads for bodies.

**Inference.** The instruction may be a no-op if the worktree is not indexed, or if the agent cannot tell which MCP query answers which question.

**Recommendation.** Make the guidance conditional and concrete: “If `index_status` shows the worktree indexed, use `search_graph`/`trace_path`/`get_code_snippet` for symbols and relationships; otherwise grep/read.” Add a one-line bootstrap/check for the worktree index. If MCP is unavailable in ticket worktrees, remove the repeated instruction rather than leaving a rule that cannot be followed.

### 6. Full-partition runs lack a shared-worktree quiet-window step (Medium)

**Fact.** The agent ran `bun run test:framework`, `bun test tests/model-cost`, and `bun test tests/connect-bot` sequentially without messaging peers or claiming a quiet window. The testing doc requires coordination for expensive/full runs in a shared worktree. No interference was observed.

**Recommendation.** Add a lightweight claim step to the ticket workflow or a small wrapper that records the run window and refuses to start a full partition while another claim exists. At minimum, put “announce/claim the quiet window” next to the `test:framework` command in the testing doc.

**Unverified.** Whether peers were running suites concurrently during these runs; the transcript does not show their process state.

### 7. Long-run output was captured only on the second attempt (Low)

**Fact.** The first `bun test tests/connect-bot` was piped through `tail`, then the suite was rerun to a log to recover the failure names. The testing doc already says to save long-run output to a run-specific log; the first run did not follow it.

**Recommendation.** Provide a wrapper (`bun run test:partition tests/connect-bot`) that tees output to a timestamped log and prints the log path. That turns the documented habit into the default and avoids rerunning a suite just to recover failures.

### 8. Smaller items

- **Glossary context was only partially read.** The agent read `GLOSSARY-MAP.md` but not `framework/GLOSSARY.md` or `extensions/model-cost/GLOSSARY.md`. No harm was observed, and the test vocabulary matched existing tests. Add a ticket-level pointer to the glossary for the touched context.
- **The evidence record lacks the final commit hash.** It names the base revision and the working changes, but the durable record does not name the commit that Main received. Add a commit field to the evidence template, or write the evidence after the commit and amend it in a follow-up docs change.
- **Batch timing for an emptied old entry is ambiguous.** The spec assigns final deletion of the mixed public entry to batch 6, while ticket 09 says retire the config export and its legacy exception; the agent deleted the now-empty `framework/public.ts` in this batch. Clarify whether an entry emptied by a batch is removed immediately or held until final retirement.
