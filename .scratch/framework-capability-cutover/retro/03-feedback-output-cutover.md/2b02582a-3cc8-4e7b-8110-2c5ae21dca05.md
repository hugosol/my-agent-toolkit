## 1. [高] 把 “graph first” 变成默认入口，而不是一句 “consider”

**事实。** 子代理的 `session_init` 工具列表包含 17 个 `mcp__codebase_memory_mcp_*` 工具；TDD 轮中 `mcp__*` 调用为 0。工具计数：123 次 `bash`、53 次 `read`、8 次 `grep`；其中 `bash` 内 `grep` 60 次、`sed -n` 13 次。一次 `read` 用 `framework/docs/framework-capabilities.md:63:raw` 返回了 27,361 字符（实际是 63–362 行），而意图只是读一行。

**推断。** 预置的“调用 grep/search 前考虑 MCP”与“read 超过 100 行前先看 outline”没有改变默认行为；shell grep/read 更顺手。索引是否可用、是否新鲜，本会话没有验证。

**建议。** 在 `AGENTS.md`（或 TDD skill 的 exploration 步骤）放一个短指针，用 leading word **graph first**：

- 符号、声明、调用链 → `search_graph` / `trace_path`；
- 文件结构 → `get_file_outline`，再决定读哪一段；
- `grep` 只用于字面量、精确路径、覆盖缺口；
- `bash grep` 只用于管道命令输出，不用于仓库搜索；
- 每个 worktree 先 `index_status` 一次；未索引或过期时先 `index_repository`，否则明确退回 `grep`/`read`。

同时把 `read` 的单行 raw 写法写清楚：精确一行用 `:N-N:raw`；`:N:raw` 会从 N 读到文件尾。这个细节能直接避免本次 27k 字符的读取。

**预期。** 减少宽泛搜索和整文件读取，降低上下文负载与定位时间；graph 不可用时也有明确的 fallback，不会变成新的 no-op。

**成本/风险。** 常驻几行指针；索引过期时需要一次检查。

**未验证。** 本会话没有验证索引是否可用/新鲜，也没有验证 graph 工具能否覆盖这些文件。建议先在仓库跑一次 `index_status`，再决定该指针是否保留；如果索引不可用，应删除该指针而不是留下无效指令。

## 2. [高] 给每个 worktree 加 “preflight” 完成条件

**事实。** 第一次聚焦测试 5 个文件全部因 `Cannot find package 'yaml'` 失败；`bun run typecheck` 因 `bun: command not found: tsc` 退出 1；随后执行 `bun install --frozen-lockfile`（13 packages）才恢复。`README.md` quick start 已有 `bun install # once`，02 证据也记录了 `bun install --frozen-lockfile`。

**推断。** 新建 worktree 没有 `node_modules`；agent 先跑检查，后读 README/prior evidence。一次性的环境失败被误当成测试/类型错误，浪费了一轮诊断。

**建议。** 在 TDD skill 的 session setup 或 hyper ticket brief 里加一个 completion criterion：`node_modules` 缺失时先 `bun install --frozen-lockfile`，再跑任何检查；或加一个 `bun run preflight` / pre-test guard，缺依赖时打印明确安装命令。保持 README 的 “once” 语义，不把安装塞进每个 test 脚本。

**预期。** 首个检查就是有效的；避免把环境失败当产品失败，也避免 `bun: command not found: tsc` 这种误导性错误。

**未验证。** 该 worktree 由宿主创建，宿主是否已有 bootstrap hook 未验证；如果有，此建议可降为可选。
