# 本票 TDD 执行复盘建议

## 范围与总体判断

本复盘仅依据指定的 **ticket 05 执行 JSONL** 及其中的工具结果；没有读取父会话或其他执行会话。对其他代理的了解仅限本票收到的协调消息。本轮只做只读分析，没有修改文件或重跑验收。

本票有几项值得保留的做法：先运行既有公开 assembly 测试取得 **97 pass / 0 fail** 基线；新增拒绝恢复与处置隔离场景后再迁移实现；最终分别记录 **framework 660/0**、真实 OMP dock **20/0**、结构检查及环境限制。已有行为本来满足新增测试，因此没有必要制造产品失败。初次缺少 `yaml` 的导入错误，以及新增测试中写反初始化顺序的失败，都不应计为检出产品缺陷的 RED；最终交接也明确区分了这些情况。

主要改进空间在执行环境与协作协议，而非再增加一层“必须充分验证”的文字要求。

## 1. 高：把昂贵测试窗口改成可核验的执行租约

**事实**

- `docs/agents/testing.md` 已要求昂贵运行串行、提前协调并保存日志；规则并不缺失。
- 本票先后向 Main、03、04、integrate01、02 协调窗口。integrate01 释放时仍要求由 Main 安排后续顺序。
- 本票给 02 的消息使用了“除非你已在运行，否则我接着运行”的方式，随后启动 framework。稍后又根据 02 的初始许可启动 OMP dock。
- 中央修订顺序的消息在阻塞调用期间送达；最终报告如实保留了可能重叠的限制。两组运行均通过，但这不能证明窗口互斥。

**建议**

由宿主调度器提供**按共享机器资源互斥的测试租约**，而不是继续依赖多方口头接力。启动入口取得包含持有者、范围和租约编号的明确授权后才执行；释放只表示归还资源，由同一调度器决定下一位。普通集成运行也走同一入口，避免实现代理与集成代理分别维护队列。

运行日志自动附带租约编号、实际起止时间与源码提交，使跨工作树负载是否重叠成为可查事实。完善现有 testing 文档中的协调分支即可，不必把整套规则再次写入常驻 AGENTS。

**完成判据**：两个独立 worktree 同时申请时，只有一个昂贵运行能够启动，另一个获得明确排队结果。

**未验证**：本票记录不能确定实际重叠区间，也没有证据表明可能的重叠造成了测试错误；不建议仅为复盘重跑已通过的验收。

## 2. 高：共享文件采用单一、带版本的所有权握手

**事实**

03 与 05 围绕 `types`、`port`、`index` 的归属，以及是否保留 `extensibility/extensions` 层级，连续发生交叉确认；多条消息先后声明“FINAL”，但仍互相覆盖。最终才稳定为 03 先迁共享文件、05 再改生命周期引用。应用前置提交并恢复 stash 时，五个迁移文件发生导入冲突，之后逐一解决。

**建议**

将已有迁移基线中的共享切面整理成一个**权威交接记录**：旧路径、新路径、负责者、交付符号、前置提交，以及交接后由谁修改调用方。只需覆盖确实跨票据的文件，不另造全仓导航清单。

共享切面由一名负责人发布带版本的提案，另一方确认同一版本后生效。确认期间保留现有归属，不以最新收到的一条聊天消息即时换手。票据启动上下文直接提供相关片段，避免代理因不能读取其他票据而反复向同伴重建分配信息。

**完成判据**：仅凭一份记录即可判断任一共享文件当前由谁编辑、消费方等待哪个提交；后续变更显式替换记录版本，而不是追加另一个“最终决定”。

**推断**：这种交接可减少本次类型的协调往返与冲突处理，但不能消除语义依赖造成的必要合并工作。

## 3. 中：测试设计先确定承诺的顺序，避免把观察到的实现顺序当成契约

**事实**

新增拒绝恢复测试最初预期 `initialize → session_start`，实际为 `session_start → initialize`，产生一条失败。代理随后阅读 binding 的既有交付规则、纠正 fixture 并解释理由，最终恢复通过。这不是实现修复。

**建议**

继续使用现有 TDD 的“设计先于 RED”要求，但将本次容易遗漏的判断交给审阅者：

> 测试中的每一项先后关系，是否来自验收承诺？有明确顺序承诺时保留精确字面序列；没有时，断言必要的前后关系和消费结果。

例如，拒绝后重绑定应证明旧实例已清理、新实例以正确身份初始化并产生效果；是否还必须固定 `session_start` 与 `initialize` 的相对位置，应由已有公开契约决定，而非由失败输出决定。

这是**判断性审阅项**，适合放在现有测试审阅参考中，不适合新增语法 lint，也不需要重复写进全局 AGENTS。

**未验证**：本复盘不据此判定最终测试已经过度约束；能够确定的是，第一次预期在写测试前没有得到充分核实。也没有证据表明本票需要补做一轮人为 RED 才能接受保行为迁移。

## 4. 中：把已有类型检查接到自动入口，而不是再写一条检查规则

**事实**

Bun 行为测试已经 **99/0** 时，`bun run typecheck` 仍发现新增测试直接读取 `OwnerReference.key`、没有处理 `unresolved` 分支。修正后类型检查通过。说明行为通过不能替代类型验证，而现有检查已经能够检出这类机械问题。

`package.json` 的 `typecheck` 已组合 TypeScript 检查与 `check:authoring`，并已有测试及 integration-check 命令。只读查找未发现 `.github/workflows`、`.husky`、`.githooks`、pre-commit 或常见 CI 配置路径。

**建议**

优先把**现有** `bun run typecheck` 接入仓库实际采用的提交或 CI 入口；再按已有 testing 分层执行对应行为分区。不要为了这次错误另写类型规范、引入第二套类型检查器，或把所有真实宿主测试放到每次本地提交上。

**完成判据**：带有同类测试类型错误的提交在自动入口失败，即使 Bun 测试全部通过。

**未验证**：未检查本机安装的 Git hooks、`core.hooksPath` 或仓库外 CI，因此不能断言项目完全没有自动守门机制。若这些入口已存在，应修复其覆盖或接线，而非重复新增。

## 5. 低：在新 worktree 交付时完成一次依赖就绪交接

**事实**

首次定向测试因缺少 `yaml`，五个测试文件在导入阶段失败；随后 `bun install --frozen-lockfile` 成功，再运行才得到有效的 97/0 基线。真实 OMP 验收还需要建立指向已有 exact 18.5.0 artifact 的 worktree-local junction。

**建议**

让创建 worktree 的启动流程处理一次依赖就绪，并交付简短的环境凭据：锁文件状态、Bun 版本、可用的 exact harness 位置，以及复用还是新建。凭据失效时再重新准备，避免每个实现代理通过第一次测试失败来发现环境尚未初始化。

仅把“首次在新 worktree 运行测试”这一分支指向现有 testing/setup 参考；包名、脚本和版本继续从环境读取。保留本票已有的边界：缺少可选宿主补丁时报告缺口，复用 artifact 不等于授权修改宿主。

**完成判据**：新票据的第一次定向测试能进入行为断言，而不是依赖导入错误；环境准备失败单独报告，不混入 RED 证据。

## 6. 低：搜索工具增加明确的降级路径与当前工作树定位

**事实**

- 首次 `find` 的全部 20 个判定请求因区域限制返回 451，工具明确表示这不是“没有命中”；代理随后转用其他搜索。

**建议**

宿主按会话记忆工具的不可用状态：明确的区域拒绝后，后续同类请求直接采用已批准的替代搜索；普通超时则只标记本次结果未知。图工具默认返回当前 cwd 对应的项目与覆盖信息；若借用其他工作树的索引，明确标为导航线索，本地文件仍是编辑依据。

同样可提供已加载技能的版本凭据：本票自动加载了 TDD 正文，随后又按通用规则完整读取一次。由宿主确认相同版本已加载即可满足加载步骤，减少重复上下文，而不是要求实现代理自行猜测哪些强制步骤可以省略。

**完成判据**：不可用工具不会在同一会话中反复付出相同失败成本；索引所属工作树和技能是否已加载均有明确状态。

**未验证**：本票没有证据表明借用索引导致了错误编辑，也不能由一次超时推断 MCP 服务长期不可用。

## 优先落点

先改善**测试租约**与**共享所有权交接**：它们直接影响结果归因和协作可靠性。类型错误已有确定性检查，应优先接线；测试顺序是否构成契约则保留给审阅者判断。其余准备与工具降级由启动环境承担。以上建议不要求重跑本票验收，也不改变本票已经披露的验证范围。
