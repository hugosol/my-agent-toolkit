# Ticket 09 TDD 执行复盘建议

## 范围与结论

本复盘只依据指定 ticket 执行 session 的 JSONL、该轮工具结果及 `09-final-artifacts/`，未读取父 session 或其他 ticket 的执行历史。同伴消息仅作为本轮收到的协调信息，不据此推定对方实际工作过程。本轮未修改文件或重跑验收。

**主要改进方向：让测试作者在运行前获得准确的消费契约，并把可机械识别的错误交给自动检查。** 本轮发现的真实 OMP 缺陷没有被改写预期、跳过或伪装成通过，这一点应保留。

## 1. 高：将同步 command 中误用异步实现变成静态诊断

**事实**

- `07-cross-cancellation.log` 中，测试把异步等待和 cancellation rejection 的预期放在 directed command 上，两端均因 command 已经结束而失败。
- 随后读取公开 interface，确认 directed `run` 返回 `void`；改用 named action 后，按既有“等待完成、错误反馈一次、正常结束”契约测试。
- `10-typecheck.log` 只报告 `.at()` 与仓库 lib 不匹配。修正后 typecheck 通过；现有类型检查并未阻止此前把 async 函数赋给同步 `void` callback。
- `package.json` 已有 `typecheck` 和 `check:authoring`。后者的默认检查范围是 `extensions/**/*.ts`，不能直接假设新增的 framework 测试也受到同样检查。

**建议**

为 **directed command 的同步实现位置**增加类型感知的 Promise-return 检查，可采用定向的 `no-misused-promises` 类检查或扩展现有 authoring checker；覆盖测试中的 `defineImplementation`。允许 named action 和本来声明支持 Promise 的 lifecycle handler，避免全局禁止 async callback。

这是机械规则，应落在检查器，而不是再添加一条常驻 AGENTS 指令。

**完成判据**：本轮最初的 async directed 示例在执行行为测试前得到可定位诊断；等价的 async named action 示例通过。具体实现方式及误报范围尚未验证。

## 2. 高：把“预期来源”导航到公开契约，减少 fixture red

**事实**

本轮多次失败来自测试假设，而非被测行为：

- `03/04`：directed activation 使用了 `on`，既有词法实际是空参数与 `off`。
- `08`：named action 使用 `run`，触发与 directed implementation 形状判定的歧义。
- `09`：预期遗漏既有 action 错误反馈的 command/action 前缀。
- `26`：真实 Pi RPC 按 `key/content` 读取 widget；既有 smoke 使用的是 `widgetKey/widgetLines`。修正后 `27` 的 16 项检查通过。

所需信息都可从已有 interface、测试或 smoke 找到，因此不是外部资料缺失。

**建议**

在既有测试文档中增加一个按分支触发的短导航，而不复制协议全文：

- 写 command 用例时，指向 directed/action 的公开定义及各一个既有消费侧测试。
- 写 Pi RPC 观察时，指向现有 dock driver 和 widget/journal 的观察示例。

将反复出现的 RPC frame 解析收敛为测试支持层的具名、可类型检查的观察函数，保留“没有帧”和“明确清除”的区别；先检索并复用已有 helper，避免建立第二套解释。

TDD skill 已要求 design-before-red，不需要重复新增同义禁令。应让其所需的权威材料更容易到达。

**完成判据**：测试作者能在首次运行前定位参数词法、完成语义、反馈格式和 RPC 字段来源；预期修正有独立依据，而不是只按 received value 修改断言。

## 3. 中高：为现有检查命令提供可版本化的触发入口

**事实**

- 仓库已有有效检查：`.at()` 被 typecheck 捕获；最终 typecheck 和 authoring 检查通过。
- 本次只读检查未发现常见的版本化 CI、`.husky`、`.githooks` 或 pre-commit 配置，也没有 package 层面的 lint 命令。
- **未验证**用户级 Git hooks、外部 CI 或宿主强制检查，不能据此断言整个环境完全没有门禁。

**建议**

优先接通现有 `bun run typecheck`，而不是重复实现 `.at()` 禁用检查。采用仓库可复现的提交前检查或 CI 入口；昂贵真实 dock 保留现有安静窗口协调，不放进每次提交的自动并发运行。

新增的同步 callback 检查应接入同一入口。正式全仓出现已知失败时仍保留非零退出；范围决策与 H1 状态单独呈现，不靠 CI 排除测试来制造绿色。

**完成判据**：新工作区依照仓库配置即可触发快速检查；ES lib 不兼容和 async-directed 示例均被挡住。是否已经存在等价外部入口，应在落地前核实。

## 4. 中：派发时携带只读交接边界与真实运行窗口

**事实**

- 开始时代理根据目录信息怀疑缺少 08，先请求 source handoff；后来 `git log` 确认自身 HEAD `6de7c04` 已包含 08。
- ticket 要求核对 01 场景账本及 06/07 H1 交接，但初始任务又限制读取其他 ticket，代理只能请求同伴补充信息；Main 后续明确允许只读这些证据部分。
- 本轮曾同时收到“工作流无 active/integrating ticket”和同伴“全仓命令仍在运行”的信息。代理等到真实命令结束、窗口明确释放后才开始昂贵验收。

**建议**

由派发载荷提供一份精简 handoff：前置合入 SHA、允许只读的账本/证据位置、禁止修改的范围。代理先做本地 ancestry 核对，再在确有差异时升级。

运行窗口应由实际进程持有的 lease 表示，附 owner、开始时间和释放状态；工作流票据状态不能单独充当空闲证据。将这些动态事实放在派发数据或协调工具里，不缓存进 AGENTS。

**完成判据**：不唤醒前序执行代理也能完成覆盖审计；只有取得真实运行窗口才能启动昂贵套件。本轮未观察到最终验收重叠，建议针对的是协调可靠性和额外往返。

## 5. 中：给最终验收提供共享证据 runner 和轻量环境预检

**事实**

- 首次测试因缺少 `yaml` 在导入阶段失败；随后 `bun install --frozen-lockfile` 成功。
- 代理自行编写 Python runner，记录 argv、cwd、环境覆盖、退出码和日志，并后续补充 cwd 支持。
- 为统一真实 provider 版本，另建隔离 deployment，仅修改副本配置；503 个源/fixture 文件及记录的依赖在最终窗口内保持不变。
- 最终运行具有充分证据：全仓 `1663 pass / 1 fail`，串行 dock `130/0`，两端结构检查通过，真实 Pi smokes 与组合验收完成。

**建议**

复用仓库现有 dock 设施，提供一个共同的证据运行入口：

1. 预检锁定依赖、CLI、Node、既有 frozen harness/patch 是否可用，区分 setup failure 与 behavioral failure。
2. 记录源状态、实际加载 provider 与配置 export 的版本差异，显式支持隔离副本。
3. 完整日志落盘，交互输出只给退出码、计数、失败摘要和证据路径。

预检只报告外部 patch 缺失，不自动安装或改变宿主。原始失败日志继续保留。

**完成判据**：同类 ticket 不再重写通用 runner；长 JSON 报告无需在对话中打印大段尾部，仍可追溯完整命令和原始输出。收益尚属推断，不能将必要的真实 smoke 耗时都算作浪费。

## 6. 中低：检索工具对区域性不可用采用快速降级

**事实**

首次两个并发 `find` 分别发出 24、25 个 judge 请求，全部因 HTTP 451 地区限制失败，未产生检索结论。代理随后使用目录、grep 和图工具继续定位；也出现一次猜测 command 路径导致的 `Path not found`。

**建议**

工具层对地区/权限导致的不可恢复错误做 session 级快速降级，提供本地文本/声明检索后备路径，并明确“未执行判断不等于没有结果”。图工具同时显示索引 root 与当前 worktree 的覆盖关系；本轮使用过主仓库索引，但未观察到因此产生错误实现，风险应标为推断。

**完成判据**：同一不可用服务不再展开整批无效请求；返回的文件位置有可读的当前工作区依据。不要再靠增加常驻工具使用禁令解决工具可用性问题。

## 应保留的做法与边界

- **保留真实 red。** 部分注册拒绝后，OMP 出现 `1:cleanup` 之后仍交付 `1:start:omp-refused` 的反例。代理保留正常失败测试，并将 accepted binding 的独立检查放在最终泄漏断言之前；没有通过提前失败而漏测重新绑定。
- **保留证据分级。** 结构供给、受控行为、真实 CLI/provider 接通、远端模型和 H1 被分别陈述；本轮没有把 RPC 输出当作用户 TUI 签署。
- **保留明确的范围决策。** Main 要求不在结构重构中修复既有语义缺陷，代理据此保留全仓 exit 1，并声明 H1/P7 未完成。这不是需要“优化成全绿”的流程问题。
- 本 session 不包含独立 reviewer 的实际审查过程，因此没有证据支持新增 reviewer 专属判断规则，也不据此认定 reviewer 漏检。未做指令对照实验，亦不将某段全局指导武断归为 no-op。

以上均为环境改进候选，尚未实施或验证。建议先落实同步/异步契约检查与精确导航，再处理派发和证据工具化；避免把本轮每个失误都沉淀为新的常驻规则。
