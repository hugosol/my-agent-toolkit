## 1. 高优先级：让完成协议由宿主执行校验，而不只写在提示里

**事实：** 原执行最后一次 `yield` 的实参只有 `data`，没有显式 `key`；工具仍于 20:44:39 返回 `Result submitted.`。执行上下文中的 workpool 指令要求 `{ key, data }` 或 `{ key, error }`。

**判断：** 可确认的是提示契约与工具接受的实参存在不一致；不能据此断言交接结果丢失，记录显示提交成功。若宿主存在隐式补齐机制，原记录没有说明它。

**建议：** 由同一份宿主契约生成工具 schema 和提示中的调用形状。要求显式 `key` 的模式，应在改变任务状态前拒绝缺失、错误类型或不属于当前池的 key；仅接受当前阶段约定的成功或失败载荷。若单项模式允许省略 key，则提示与工具同时采用该规则，不让代理在两种形状间猜测。

**完成标准：** 宿主协议测试分别覆盖合法提交、缺失 key、错误 key，以及阶段切换后的旧载荷；拒绝的调用不改变完成状态。此类机械约束由工具校验，不再增加 reviewer 或 AGENTS.md 规则。
