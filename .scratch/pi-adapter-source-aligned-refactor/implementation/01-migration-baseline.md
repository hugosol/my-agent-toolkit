# 01: 固化迁移清单与重构前验证基线

**What to build:** 为两个 harness 的来源对齐重构建立可复核、可执行的迁移分配与行为基线，让后续 ticket 能证明原有消费结果被保留，而不只是目录已移动。

**Delivers:** enabling: unblocks P1–P17

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

## 契约与范围

以本 feature 的已批准 spec 和 contract 为权威，复用 S1 公开 assembly／消费 interface、S2 真实 harness、S3 接入完整性检查和 R1 结构审查。迁移清单是分析材料，不是第二份运行时能力注册表。本票不提前宣称任何 promise 完成，不实施新的公共 interface 或通用 provider 抽象。

- [ ] 从实际 assembly、调用方及实际适配的上游契约建立完整职责清单，标明 native、Pi 的 pi-subagents 来源、必要 mixture、完整协议边界、共享状态和资源所有权。
- [ ] 每个职责唯一分配给 02–07，包括原生类型、加载支持、模型目录／价格／访问事实；共享项也必须有明确 owner，不留给 08 兜底。列明布局敏感检查、生成设施、导航及受影响 extension。
- [ ] 为每个实际受影响场景记录 harness、行为入口、输入、独立预期、观察 seam、唯一测试 owner、已有覆盖与缺口。P10／P13／P14 的路径内覆盖归 02–07，真正跨路径的组合用例归 09；同一用例不得重复认领。
- [ ] 准备重构前有效的 State 样例及恢复／分支／后续写入预期，保存有效与无效用户配置样例；不得用新实现自写自读代替历史兼容证据。
- [ ] 按既有测试分层策略执行适用基线检查与真实 harness 场景，保存重构前输出和可重复操作步骤；记录源状态、依赖、harness／provider／补丁版本、命令、退出状态及已知失败。
- [ ] 明确 Pi 真实 provider 与两端真实子会话加载所需环境，区分受控替身证据和真实接通。缺失可选补丁环境作为验证缺口，不安装或修改 harness，也不阻塞其他可执行工作。
- [ ] 复核每张迁移票可独立验证且适合单个 fresh context；若证据证明必须增添前置重构或拆分 04，提出具体职责和阻塞理由并请求调整票集，不静默缩减范围或创造兼容层。
- [ ] 仅在真实实现前提存在时提出新增 blocking edge；共享文件冲突按集成 owner／执行窗口协调，不冒充逻辑依赖。

## 验证与交接

遵循仓库测试分层及共享工作树协调规则。分析与文档产物验证引用和覆盖完整性；行为基线必须实际运行并记录结果。发现既有语义缺陷单独记录并请求范围决策，不修成新预期、不记作通过。将迁移分配和场景账本写入本票执行记录，后续票引用它，不另建手工能力表。
