# 04: Pi Session 生命周期、第三方接入与跨来源组合迁移

**What to build:** Pi 主会话和实际子会话继续向 extension 交付正确的 Session、Turn、Round 与相关观察序列；pi-subagents 接入结果、身份、失败和释放语义不变，同时可以明确追踪原生事实、第三方协议及必要组合的来源。

**Delivers:** P5、P12（Pi）；P11；P10、P13、P14（Pi 生命周期／第三方接入路径）

**Test owner for:** P5、P12 的 Pi 用例；P10、P13、P14 的 Pi 生命周期／第三方接入独立用例。跨路径组合用例由 09 拥有。

**Blocked by:** 01: 固化迁移清单与重构前验证基线。

**Status:** ready-for-agent

## 边界与覆盖

以本 feature 的 spec／contract 和 01 的分配为准，经 S1／S2 验证。不承接 State 编码、命令、prompt 或 UI 内部迁移；使用其既有契约，不要求等待其迁移完成。第三方协议与跨来源 Round 组合保持完整，避免按来源目录切断同一生命周期。

- [ ] 将原生 Session ancestry 与 pi-subagents 注册、RPC、版本、启动条件和 liveness 协议分离；第三方消息按协议所有者归类，不因事件总线传输而误归 native。
- [ ] 仅将必须结合原生与第三方事实的解释放入 mixture。native 不依赖特定第三方协议；第三方可使用必要 Pi 原生契约；双方不反向依赖 mixture。
- [ ] 保持 Session／Turn／Round、后台工作读数、Parent agent、Owner 和实际会话身份的既有关系、顺序及观察范围；验证开始、结束、转移、取消和终止失败。
- [ ] 经公开 assembly 分别验证缺失、未启用、拒绝、协议失败、版本／身份／启动条件不满足的原有结果，不能变成成功、空闲或静默回退。
- [ ] 验证多 extension／binding 隔离、绑定失败后再绑定、主子会话和 Owner 场景；观察消费结果而非私有状态。
- [ ] 独立断言适用错误、取消、超时、终止及既有等待规则；不新增重试、不延长等待、不吞掉失败。
- [ ] 验证释放后本路径应停止的交付、订阅回调及外部效果不再发生，另一有效 binding 继续运行；不能只断言 cleanup 被调用。
- [ ] 真实接通 pi-subagents，记录版本、身份和启动条件，并证明实际子会话加载所要求的 child-extension 且能力可观察；可控条件覆盖拒绝路径。注册成功不是实际加载证明，替身证据与真实接通证据分开。
- [ ] 保持共享状态和资源生命周期，迁移全部受影响调用方、类型和加载支持，删除本职责旧实现／兼容转发并更新直接导航。port assembly 只组装，不承接跨来源语义解释。

## 验证与交接

使用独立事件事实、身份和顺序预期，不从实现重算结果。迭代运行受影响测试及 TypeScript 类型检查；完成时运行拥有分区、受影响消费方、适用真实 Pi dock／smoke 和终止场景。记录源状态、命令、退出状态和 provider 环境，未接通项保持未验证。保留消费可见覆盖，不为搬迁删减场景。发现既有缺陷或无法在一个 fresh context 保持完整协议时请求范围／票集决策，不静默缩减或引入通用 provider 抽象。
