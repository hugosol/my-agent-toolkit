# Retro — 票据 05「移除 Sum 列」TDD 实现轮

复盘对象：本票据本轮 TDD 实现对话（本 session），含其全部工具调用与结果。事实均标注来源命令/输出；无法确证者标为推断或未验证。

## 1. CRLF 检出使真实宿主 dock 层完全跑不起来（最高严重度）

**事实**：`bun test tests/harness-dock/detail-tree.test.ts` 在 `beforeAll` 即失败：`host-patches\omp-18.5.0-viewed-session\patch.diff touches no file`（`host-patch-artifact.ts:224` 抛错）。根因链条可确证：`patchTouchedFiles` 用 `patchText.split("\n")` 后配 `/^diff --git a\/(.+?) b\/(.+)$/`（`host-patch-artifact.ts:127-135`），而 JS 的 `.` 不匹配 `\r`；该 patch 文件在工作区为 `i/lf w/crlf`，`git config core.autocrlf=true`，且仓库**没有 `.gitattributes`**（已确认 ABSENT）。

**影响**：`package.json` 里的 `test:dock` 与整个「真实宿主证据」层在任何 Windows 检出上都是死的，且失败信息指向 patch 内容而非行尾，误导性强。本轮为绕开它付出了最高成本：改用 LF 快照（`git -c core.autocrlf=false clone` + 拷入改动 + `bun install`）才拿到 dock 证据（三个受影响文件 1/6/2 全绿，整层 77 pass/4 fail，207s）。

**建议（任一即可，推荐第一条）**：
- 让解析器容忍 CRLF：`patchText.split(/\r?\n/)` 或先 `replace(/\r/g, "")`——一行、确定性，任何检出都能跑 dock。
- 增加 `.gitattributes`（例如 `host-patches/**/*.diff text eol=lf`，或 `* text=auto eol=lf`），使构件不依赖机器 autocrlf。
- 若必须保持 LF 夹具，把 LF 快照 recipe 写进 `docs/agents/testing.md`，避免下一个 agent 重新摸索（本轮最大时间开销即在此）。

未验证：若行尾影响 `record.json` 记录的 sha256，是否需要同步刷新（本轮未比对）。

## 2. 仓库没有任何 guardrail

**事实**：无 `.github/workflows`、无 `.husky`、`.git/hooks` 只有 sample；`package.json` 无 `lint`/`check`/`format` 脚本，唯一自动检查是手工执行的 `bun run typecheck` 与 `bun test`。

**影响**：没有东西会在 agent/会话之外强制执行这些命令；本轮发现第 1 条那个「脚本存在但环境里必然失败」的问题能长期存在，正因如此。

**建议**：加一个最小 CI job（或 pre-push hook）跑 `bun install && bun run typecheck && bun test`（含各 tier 脚本）。

## 3. typecheck 抓不到未使用的局部与常量

**事实**：`tests/harness-dock/detail-tree.test.ts` 里 `const ONE_RESPONSE_SUM = 3000` 除声明外无任何引用（grep 全仓仅 1 处），而 `bun run typecheck` 全绿；`tsconfig.json` 有 `strict: true` 但无 `noUnusedLocals`/`noUnusedParameters`。

**影响**：死代码（本例恰是本票据要移除的 Sum 概念）只能靠人读发现。

**建议**：在 `tsconfig.json` 打开 `noUnusedLocals`/`noUnusedParameters` 并清理报出点。

## 4. 新 worktree 未安装依赖

**事实**：本轮首个测试命令即失败：`Cannot find package 'yaml' from framework\core\config.ts`；`bun install` 后正常。

**影响**：浪费一个循环，且容易被读成「测试坏了」。

**建议**：worktree 分派时预装依赖，或在 `AGENTS.md` 加一行导航指针（新 worktree 先 `bun install`）。未验证：其他 ticket worktree 是否同样缺失（推断为同样）。

## 5. widget 行断言的 padding 陷阱

**事实**：我新加的 `toContain("Cost: ¥0.01")` 被真实宿主输出打回——实际为 `"Cost:   ¥0.01"`（Total 的值与旁边 Round 更宽的值右对齐）。更早时，我仅凭源码推演 `alignedLines` 的宽度花掉数个回合并写了临时探针，原因是 label 自带尾空格（`"Cache: "`）使 10 字符字段看不出 padding。

**影响**：本票据明确要求「验证字段而非整行固定空格」，而测试屋风是整行逐字节断言；二者冲突会同时带来脆性期望（列宽归 06 号票据）和无谓的宽度算术。

**建议**：给 widget 套件一个字段断言小工具（如 `expectFields(line, {"Cache: ": "50%", "Cost: ": "¥0.01"})`），并在 `docs/agents/testing.md`（仓库无 `CODING_STANDARDS.md`，已确认）写明约定：布局是别的票据的 scope 时按字段断言，只有对齐本身是被测行为时才逐字节；另在 `extensions/model-cost/GLOSSARY.md` 或 README 记一句「列右对齐值、label 带尾空格」，避免手算 padding。
