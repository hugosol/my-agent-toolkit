## 7（中）字节同一性断言依赖工作区换行符，环境一变就红

**事实**：两位 peer 在本轮汇报「CRLF checkout 下 `baseline record > records the lockfiles…` 与 `controlled session > … not the default environment` 两处失败，与代码无关」，并都通过临时把 `bun.lock`、`host-patches/*/patch.diff` 归一为 LF 后得到全绿（82/0 与 84/0）；他们随后把工作区还原。我自己的两次 `test:dock` 全绿（82/0、85/0），未复现。**标记为 peer 报告、我没有独立复现**。

**推断**：断言比较的是工作区文件字节，而记录的 sha256 是提交 blob（LF）的字节，`core.autocrlf=true` 时二者不等。

**建议**：把这两处改为对**提交内容**取字节（`git show HEAD:<path>` 或 `.gitattributes` 固定这两类文件的 eol），使断言与工作区换行策略无关；否则每次环境漂移都要消耗诊断时间，并可能被误读为实现回归。
