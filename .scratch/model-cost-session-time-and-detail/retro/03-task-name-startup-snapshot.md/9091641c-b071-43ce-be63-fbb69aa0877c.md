## 1. Frozen-byte files are unprotected against line-ending conversion (fact; blocking; ~10 calls)
Every one of the 262 tracked files in this worktree was checked out CRLF (`git ls-files --eol` → `i/lf w/crlf`; `core.autocrlf=true` from the system gitconfig) while the blobs are LF. That silently broke the whole real-host partition: `patchTouchedFiles` (`tests/harness-dock/host-patch-artifact.ts:127`) splits on `"\n"` and matches `^diff --git a/… b/…$`, so a trailing CR yields `[]` and `ensureViewedSessionHarness` throws `patch.diff touches no file` before any case runs; `verifyLockfile(bun.lock)` and the patch `sha256` checks also stop matching the frozen records. Fix that costs one file: `.gitattributes` (absent today) marking byte-addressed artifacts, e.g. `host-patches/**/patch.diff -text` and `bun.lock -text` (or `* text=auto eol=lf`). One line turns a ticket-blocking discovery into a non-event for every worktree.

Repair recipe worth naming in `docs/agents/testing.md`, since the obvious git plumbing silently no-ops (`git checkout-index -a -f` with `-c core.autocrlf=false` / `core.eol=lf` rewrote nothing): `git cat-file blob HEAD:$f > $f` per tracked file with a CR, then `git add -A` (content unchanged, status clean, no EOL churn in the commit).
