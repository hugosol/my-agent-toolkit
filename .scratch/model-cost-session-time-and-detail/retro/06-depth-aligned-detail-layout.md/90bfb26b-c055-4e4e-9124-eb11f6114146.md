## 1. dock（真实宿主）分区入口被行尾差异整体挡死（机械问题 → 确定性检查）【严重度最高】

**事实**
- `bun test tests/harness-dock/detail-tree.test.ts` 立即失败：`error: ...\host-patches\omp-18.5.0-viewed-session\patch.diff touches no file`（栈：`tests/harness-dock/host-patch-artifact.ts:224` → `viewed-session-harness.ts:82`）。
- `cat -A` 显示该 patch 在工作树里每行以 `^M$` 结尾；`git config core.autocrlf` = `true`；`git show HEAD:...patch.diff | cat -A` 显示 blob 本身是 LF。
- `patchTouchedFiles` 用 `^diff --git a/(.+?) b/(.+)$` 对 `patchText.split("\n")` 逐行匹配；行尾多出的 `\r` 使匹配恒失败，于是报“touches no file”（误导：patch 其实完整）。
- 把两个 `patch.diff` 临时 `tr -d '\r'` 后，同一命令 **3 pass / 0 fail（27.7s）**，随后 `git checkout` 恢复，工作树干净。

**建议**（任一即为一次性小改动）
- 首选确定性检查：让 `patchTouchedFiles` 容忍行尾（`split(/\r?\n/)`，或读取后 `replace(/\r\n/g,"\n")`）；顺手让错误信息变成“patch 为空/格式不符”。
- 或在仓库加 `.gitattributes`：`host-patches/**/patch.diff -text`（或 `*.diff text eol=lf`），使 checkout 不改写这些字节。
- 或在 `viewed-session-harness` 前置断言，把“本 checkout 行尾为 CRLF”作为明确前提报出。

**未验证**：仓库 CI 是否在 Linux 上跑 dock（我未查看 workflow 配置）；若在 Linux 跑，此条只影响 Windows 本地 checkout，但“解析依赖 checkout 行尾”仍是隐患。

## 4. 「子代理行不含 ratio 列」是跨文件隐含依赖，且无处写明

**事实**：我按 `fieldsColumns(row.fields)` 推断子代理行含 `¥Cache/In/Out：…`，据此手算 22 列槽位与期望值；实际输出只有 `Cache:` + `Cost:`。原因是树构建时子代理行调用 `fieldsOf(view.own(childId) ?? {})`（不带 price），而 model 行调用 `pairFieldsOf(...)`（带价格）；两路径差异只存在于代码，注释与 glossary 均未说明。

**建议**：在 `display.ts` 的 `agentTreeOf`（或 `ConsumptionFields.referenceRatio` 定义处）加一句“descendant 行不带 price，故没有 ratio 列；ratio 只出现在 model 行与 Total/Round”，或写入 model-cost glossary 的 Agent tree/Depth alignment group 条目——一行成本，唯一真相地点。

**推断**：任何给 detail 树写断言的票据都会踩同一坑（我为此浪费一轮 fixture 调整）。

## 5. 链式列的手算字面量：策略建议（可省数次调试往返）

**事实**：字段起始列是链式推导（下一字段 = 上一字段 + 该列宽 + 间隔）。我为整组字段手算字面量，先后错三次：把 `Cache: ` 当 9 列（实为 7 标签 + 3 值 = 10）、把 `Ctx: ` 当 6 列（实为 5）、按错误列序算出 `Run=111`（实为 88）。失败输出（`Expected: 111 / Received: 88`、`Expected length: 1 / Received length: 0`、`Expected: <= 60 / Received: 63`）都来自此类偏差；另有一次误用字符下标截取“列区间”（`slice(列号)`）得到 `"        Run: "`。

**建议**：在 `docs/agents/testing.md`（或 tdd 技能的测试设计段）加一条经验规则——**链式布局只对“规则承载”的那一列写手算字面量（如组内名称列宽 → 第一个字段起始列），其后各列断言等值关系**（同组内多行同列、跨组不同列）。字面量仍源自独立规则，但不必手算五次加法。附则：列/像素断言不要用字符下标截字符串，改用整行正则 + 期望空白数，或先测量再比较。
