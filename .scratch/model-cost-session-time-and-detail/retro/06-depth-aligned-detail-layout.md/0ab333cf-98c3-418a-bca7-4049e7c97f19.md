### 2.［高］dock 分区在本 checkout 静默不可运行，而它是本票要求的真实宿主证据

**事实**：`file host-patches/*/patch.diff` 显示两个 patch 都是 CRLF；本地 `git config core.autocrlf=true` 且无 `.gitattributes`。本轮 `bun test tests/harness-dock/detail-tree.test.ts` 得到 `0 pass / 1 fail`，失败发生在启动阶段 `patchTouchedFiles` 报 `patch.diff touches no file`（上一轮的记录里同一现象出现过）。上一轮为了拿到 dock 证据，曾把两个 patch 临时转成 LF 再恢复。

- 或让 `patchTouchedFiles`（`tests/harness-dock/host-patch-artifact.ts` 一带）按 `/\r?\n/` 切行，对 CRLF 容忍。
- 若两者都做，优先 `.gitattributes`：它同时消掉"同一文件在不同 checkout 行为不同"的隐患。

### 3.［高］无头环境里"拿到真实终端设备"的配方没有被记录

**事实（本轮踩过的坑，均可在对话里复现）**：
- `winpty`（Git 版）在 stdin 非 tty 时直接拒绝：`stdin is not a tty`。
- `conhost.exe --headless --width … <cmd>` 不产生子进程输出／文件，按该调用形式拿不到结果。
- `wt.exe -w new nt … <exe> <args>` 中，**命令后带 `-`／`--` 开头的参数会被 wt 自己吃掉**：`--size 120,40`、`--report <path>` 都会让命令静默不执行（输出→文件是唯一可靠回执）。
- 手写 ConPTY（`CreatePseudoConsole` + `CreateProcessW` + `PROC_THREAD_ATTRIBUTE_PSEUDOCONSOLE`）时：1) `UpdateProcThreadAttribute` 的 lpValue 要传 **HPCON 句柄本身**，传句柄的地址会让子进程落到一个**新建的默认 120x30 控制台**（`isTTY` 为真但流是空的）；2) 子进程若继承宿主管道的 std handle，就不是控制台，必须清空本进程 std handle 并 `bInheritHandles=FALSE`；3) `ClosePseudoConsole` 在本机**阻塞**，读完流后直接让驱动进程退出即可。
- bun 的 `process.stdout.columns` 在设备改宽后**不刷新**（两轮都停在 120），也不发 `resize` 事件；宽度事实只能从 `GetConsoleScreenBufferInfo` 取。
- 预期会挂住的探测要用 shell 的 `timeout` 包住，否则工具的 60s 规则会把它扔进后台，白等一轮。
**推断**：任何"终端展示类"ticket（本票 P32/P33、H1 行、P67 的窗口视觉）都要重走这条链，成本约十余次探测调用（估计）。
**建议**：新增 `docs/agents/terminal-evidence.md`（并在 `docs/agents/testing.md` 里加一行指针），内容就是上面五条**可用配方＋坑**：wt 的无参数调用形式与"输出写文件"模式、ConPTY 的三条要点、bun 宽度字段不可信、探测要用 `timeout` 包裹。这属于"环境查不到、只有踩过才知道"的缓存，正是文档该存的东西。
