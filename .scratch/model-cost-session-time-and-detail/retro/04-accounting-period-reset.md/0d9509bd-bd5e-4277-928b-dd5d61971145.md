## 1.（高）真实宿主 dock 的可运行前置条件没有成文路径

- **类别**：Navigation + Tool economy
- **事实**：工作树没有 `node_modules`、也没有 `.cache/omp-baseline`。第一次 `bun test tests/harness-dock/period-switch.test.ts` 以 `(fail) (unnamed) [5000.71ms] a beforeEach/afterEach hook timed out` 结束，并打印 `killed 1 dangling process`——`ensureIsolatedHarness()` 正在联网安装宿主包，被 bun 的 5 秒 hook 上限掐断，留下 `.cache/omp-baseline/18.5.0.staging-<pid>-<ts>`。随后 `rm -rf` 因该残留目录被占用失败（os error 145）。最终靠逆向 `tests/harness-dock/baseline.ts` 才写出可用的一行命令：`bun -e 'import { ensureIsolatedHarness } from "./tests/harness-dock/baseline.ts"; await ensureIsolatedHarness()'`（16.26s 完成），之后 dock 立即 2.02s 通过。
- **建议**：在 `docs/agents/testing.md`（或在 `package.json` 加一个脚本，如 `setup:harness`）写明两步准备：`bun install --frozen-lockfile`；用 `ensureIsolatedHarness()` 预置隔离宿主（首次需联网、耗时数十秒），并注明"必须先预置，因为 dock 的 hook 预算只有 5s"。工具经济上的收益是直接的：本次为这条信息花了 3 次失败调用 + 2 次诊断调用。
- **成本**：极低（一段文档/一个脚本），影响所有需要真实宿主证据的票据。

## 2.（高）`*.diff` 的 CRLF 检出会让 dock 的 patch 装配静默失效，且没有守护检查

- **类别**：Automated checks
- **事实**：`bun test tests/harness-dock/detail-tree.test.ts` 在 `beforeAll` 抛 `host-patches/omp-18.5.0-viewed-session/patch.diff touches no file`。直接探针确认：该文件 `has CRLF: true`，599 个 `\n` 全是 `\r\n`；`patchTouchedFiles()`（`tests/harness-dock/host-patch-artifact.ts:127`，只 `split("\n")` + `/^diff --git a\/(.+?) b\/(.+)$/`）对两个已跟踪的 `patch.diff` 都返回 0 个文件；把分行改成 `/\r?\n/` 后同一文件立刻解析出 8 个文件。另外 `host-patches/omp-18.5.0-viewed-session-codex-response/` 目录里没有被 git 跟踪的 `patch.diff`（`git ls-files` 只有 README.md 与 record.json）。
- **建议**（机械性缺陷，优先给检查而不是规则）：① `.gitattributes` 固定 `*.diff text eol=lf`（[推断] 本地 CRLF 来自检出配置）；② `patchTouchedFiles` 容忍 CRLF（`split(/\r?\n/)` 或 `line.trimEnd()`）；③ 加一个廉价的守护用例：对 `host-patches/**/record.json` 里每个 `patchFiles[].file` 断言"文件存在且 `patchTouchedFiles()` 非空"，让这类失败在单测里以明确信息出现，而不是滑到某个 dock 的 `beforeAll` 深处。
- **成本**：低；今天是"少一个 dock 文件可跑"，明天可能是"某张票据以为自己在验证真实宿主，其实 patch 从未生效"。
