## 1（高）dock 验收证据被行尾静默破坏：记录哈希是 LF，检出是 CRLF，而仓库没有 `.gitattributes`

**事实**
- `git config core.autocrlf` = `true`（本 worktree）。
- `host-patches/omp-18.5.0-viewed-session/record.json` 记录 `patch.diff` 的 `sha256 = 66195465…`；工作区文件 `sha256sum` = `057e01f6…`；`tr -d '\r'` 后 = `66195465…`，与记录一致。`bun.lock` 同理（LF 归一化后等于记录值 `9e9f4833…`）。
- 该 record 自己的 materialise 说明写的是 `git -c core.autocrlf=false apply …`，即设计上假定 LF 工作区。
- 上一轮报告把 `baseline record > records the lockfiles…` 与 `controlled session > … not the default environment` 两条 dock 失败记为“环境性”，未定位；本轮最初复现同样两条，把上述文件归一化为 LF 后 `bun test tests/harness-dock` 由 79/2 变 81/0（计入本轮新用例后 82/0）。

**影响**：真实宿主验收（P10/P19/P35 所依赖的 dock 证据）会因 workstation 的行尾设置无解释地失败，并被误判为“环境噪音”而放过；证据强弱取决于谁在哪台机器上跑。

**建议**（机械类，优先做检查而非写规则）：加 `.gitattributes` 固定被哈希工件的字节，例如 `bun.lock -text`、`host-patches/**/patch.diff -text`；可叠加让 dock 侧 `sha256File` 按 LF 归一化字节比较，使证据不再依赖检出方式；在 `docs/agents/testing.md` 的 dock 一节写明该前提与临时绕行命令，直到前者落地。

**未验证**：`.gitattributes` 对既有 Windows 检出与其他机器的影响需要一次全仓 `git status`/`git add` 校验。仓库根 `ls`（本会话输出，含 dotfile）与 `ls -a | grep -i gitattributes` 均未见 `.gitattributes`。

## 3（中）真实宿主原生 payload 形状只能靠临时插桩获得，probe 结论没有被固化成工件

**事实**：为给 P10“原生耗时来源”取证，我在 `framework/adapters/omp.ts` 临时插桩（把 payload keys 与 entry 的 `durationMs` 追加到 `.cache/verify-02/probe.jsonl`），跑一次 dock 委派用例后才得到：两种帧的 `details` 都含 `projectAgentsDir / results / totalDurationMs / progress`；running 帧 entry 的 `durationMs` 为 42→770、31→444，ended 帧在 `results[]` 里给出终值 780、444；entry 的 `id` 是任务名（`persistenceChildOne`）。探针随后删除，结论只留在 `harness-support.md` 的散文里。

**影响**：(a) 这类“宿主来源”承诺会在每个 ticket 上重复出现，每次重新插桩都是重复成本与污染风险；(b) 探针顺带证明了“执行结束的终值真的会到”（合同要求取得原生最终耗时），而既有测试并未断言这一点，说明该事实此前没有工件承载。

**建议**：让 dock 的 session 驱动把扩展侧观察到的 delivery（或其原始 payload 摘要）落成运行目录内的 JSONL，用例可直接断言原始形状；或在 `docs/research/` 存一份真实 `task` payload 样本。宿主事实应以工件存在，而不是每次现场探针。

## 6（低-中）把某一次运行的真实毫秒数写进 ticket/commit，会被后来者当成可复现期望

**事实**：上一轮的提交说明与 ticket 写了“children's records carried 756 ms / 284 ms”（来自一次探针运行）；本轮同形状运行得到 754 ms，探针运行里还有 780 ms 的终值——数值随机器负载变化。

**影响**：具体毫秒数不可复现，却被写成跨运行证据；真正可复现的断言是形状（`> 0`、`drawn === document` 的值）。

**建议**：ticket/commit 只保留可复现断言与“哪次运行、什么形状”，具体毫秒数留在运行工件（探针日志、dock capture）并注明其为一次性观测。

## 7（低）harness 缺陷：`edit` 调用到达时丢了 `path`

**事实**：两次 `edit` 响应为 `path must be a string (was missing)`，而调用参数里给了 `path`（两次都发生在 `new_string`/`old_string` 较长时）；第三次相同调用成功。

**影响**：每次约损失一个往返。

**建议**：报给 harness 维护者；修复前，长串编辑拆小或换用更短的 patch。

## 8（低，推断）dock 依赖 `.cache/omp-baseline` 的既有安装，冷启动需要网络

**推断**：`ensurePatchArtifact` 在 prefix 缺失时执行 `bun install`（本会话只读该函数与 record 的 materialise 说明；本 worktree 中 `.cache/omp-baseline/*` 已存在，未实际触发安装）。
