## 1. 仓库无 `.gitattributes`：CRLF 检出直接打掉真实宿主套件（高）

**事实**：本 worktree 的受跟踪文件以 CRLF 检出（`core.autocrlf=true`）。`bun test tests/harness-dock` 中 `tests/harness-dock/baseline.test.ts` 失败：记录的 `bun.lock` sha256 `9e9f4833…` ≠ 实读 `7f5c82e6…`；集成分支 worktree 的同一文件是 LF，与记录一致。04 票也记录过同一根因令 LF-only patch 解析失败、`detail-tree.test.ts` 无法运行。修复动作：`git ls-files -z | xargs -0 rm -f` + `git -c core.autocrlf=false checkout -- .`，276 个受跟踪文件（含先被单独归一的 `bun.lock`）恢复为 LF，`git status` 仍干净、dock 全绿。

**建议**：仓库根加 `.gitattributes` 钉死记录字节，例如 `* -text`，或 `* text=auto eol=lf` 搭配 `*.diff -text`、`*.json -text`。这样任何 worktree、任何 `core.autocrlf` 都不会改变 checkout 字节，`bun.lock` 的 baseline hash 与 patch 解析都稳定。

**标注**：无 `.gitattributes`（事实：根目录列举 + glob 命中为空）；`.gitattributes` 可消除此问题为标准 git 机制，本轮未实测（推断）。

## 2. 没有 guardrail：`typecheck` 只在 agent 想起来时才跑（高）

**事实**：`package.json` 只有 `test`/`typecheck`/smoke 脚本，**无 lint 脚本**；根目录无 `.github/`、`.husky/`、`.githooks/`、`.pre-commit-config.yaml`、`lint-staged*`、`lefthook*`，`core.hooksPath` 未设置（glob 与 `git config` 结果）。本轮新增测试文件后首次 `bun run typecheck` 报 `TS2769`（`name: string | undefined` 不能赋给 `SessionRecord.name`）——只有 agent 主动运行才拦下。宿主的两条写作期规则提醒（`ts-no-tiny-functions`、`ts-set-map`）也确实触发了一次返工（一个单表达式 helper 需内联）。

**建议**：把仓库已有的命令接成确定性门禁——`pre-commit` 钩子（或 CI job）跑 `bun run typecheck && bun test tests/model-cost`（快速分区）。接线成本极低，且把宿主/仓库的机械规则从"写完再被提醒"提前到"提交前必绿"。

**标注**：事实。
