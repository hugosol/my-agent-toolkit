# 04: 消费周期重置与旧执行隔离

**What to build:** 用户执行允许的 clear 或首次 holiday 重置后，活动消费文档中的主／子时间随原有消费周期一并清除；同一新周期只从下一条新输入和新的子代理执行累计。重启、旧历史或迟到旧执行均不能将已清除的时间带回。

**Delivers:** P20, P21

**Blocked by:** 01 — 主会话 Session span 的采集、保存与展示；02 — 子代理原生运行耗时的累计与落盘。

**Status:** ready-for-agent

Source: [approved contract](../contract.md) · [spec](../spec.md)

## Acceptance criteria

- [ ] P20：分别运行 clear 与首次 holiday，在既有整份归档／新周期提交中一并清除活动时间；读取实际新文档及重新加载结果，均不带旧主时间或子累计。
- [ ] P20：已处于 holiday 时不再次重置，不新增时间写入；保留原先先归档后提交、失败终止及消费重置结果，不从归档回读恢复时间。
- [ ] P21：旧输入 10:00，重置后尚无新输入时主时间不可用；11:00 新输入、11:03 round_end 后得到 180,000 ms，不扫描历史重建起点。
- [ ] P21：重置前旧原生执行的迟到进度／结束不得带回已清除耗时；重置后新执行 120,000 ms 则新累计为 120,000 ms，随既有提交保存、重新加载后仍一致。
- [ ] 使用实际 Session 与消费周期边界验证隔离，不用改名或创建新的展示行掩盖旧执行污染。
- [ ] 保留现有动作准入：自身 DeepSeek 入口、可靠 idle 且无自身待完成保存才允许；不排队、不延迟到未来 round_end 执行，不改 clear／holiday 原有消费语义。
- [ ] 完成主／子时间的重置、提交和恢复自动化检查、所属分区与受影响消费者、TypeScript typecheck；实际通过 /budget 操作及文件／widget 观察证明两个重置路径，不只调用内部 helper。

## Boundaries

复用 S1/S2/S3 和 Accounting reset 的既有整文档协调操作。不建立跨周期时间保留区、时间文件、补存或逐执行账本；不修改 omp 或新增补丁。归档只保留既有提交事实，不为重置额外采集旧时间，不撤销原本已发生的消费。内部周期／执行标记形状保持实现自由，以旧值不能污染新周期的结果验收。
