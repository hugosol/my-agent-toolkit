# 什么证据才算完整迁移，如何安全验收并切换？：Lighthouse

> Question and discussion: [什么证据才算完整迁移，如何安全验收并切换？](../decision/11-acceptance-cutover.md)
>
> 用户在 Q14「确认」授权整票发布；[确认来源与证据限度](../assets/acceptance-confirmation-2026-10-13.md)、[发布前票据历史](../assets/acceptance-before-publication-2026-10-13.md)可恢复。本文是验收与切换规划，不是测试通过、宿主补丁完成、支持版本升级或正式切换的证明。

## Question

确定本次完整迁移的验收依据、自动测试／真实 OMP 脚本／真实接口冒烟／人工验收的分工，约束运行环境与凭证隔离，并明确版本冻结、完成记录、正式切换和回退。具体业务行为消费地图中的既有权威，不重新设计计价、存储或展示。

## Discussion

### 验收依据与旧实现的角色

Q4 采用、Q14 整票确认：本次 Wayfinder 的 Lighthouse 及其明确修订的项目文档是需求与政策权威，实施／验收文档据此整理。优先验收本次文档，不要求全量新旧实现对照表；大部分需求已经在 Wayfinder 中迁移到本仓库文档。实施生成的文档不能因代码实际如此而覆盖已确认需求。

文档未覆盖的部分才参考冻结的旧实现；发现影响交付范围的遗漏或冲突时明确提出，不静默删功能、不自动把旧行为全部恢复。沿用[装配权威](10-assembly-layout.md)冻结的 source oracle，不实时跨仓库 import，不随 HEAD 移动。原票历史中的全量 source oracle 对照、旧账号隔离／双执行者拒绝等要求不再是现行恢复点；以行为、归属、数据、存储、观察和装配当前原主题为准。

### 自动测试与真实 OMP 脚本

Q2／Q5 的分工在 Q8、Q12 中明确：可控行为通过 test cases 验证，test case 覆盖由既有工作流程保证，本决策不另立特定覆盖规范。永久测试中的网络一律使用 mock，不发真实请求；真实服务调用不得混入反复运行的 test cases。

真实 OMP 接线可由自动脚本启动隔离的实际宿主并驱动 RPC、读取 Session JSONL、捕获请求与 stderr。复用已有 tests/harness-dock/ 与 scripts/verify-omp-candidate.ts，不建立平行验证体系；实施时接入冻结的 patched artifact 并补齐本次契约场景。现有入口的存在不等于本次迁移已通过验证。框架候选回归报警与扩展业务验收分开，不以局部框架套件代替完整消费者行为验证；消费者接线／旧测试取舍沿[装配原主题](10-assembly-layout.md#consumer-migration-and-behavior-tests)。

只有脚本驱动验证允许成本取舍：多次尝试失败，或发现实现成本过高，就可转人类验证，简要记录场景、原因、人工方法与预期结果，不死磕自动化、不为证明建立复杂机制。不能将此例外扩展为省略文档要求的 test cases；人工也无法证明或需要改变已定功能时，明确留下未决项，不宣称通过。

真实服务最终效果与视觉 TUI 不纳入自动化验收范围，交由人类验收；RPC／mock 不能证明真实服务可用或视觉正确。

### 正式运行环境隔离

Q7／Q11／Q14 确认：真实 OMP 正在负责调度 subagent 实现代码，实现与验证不得触碰它的运行环境。不改正式配置、扩展加载、会话、凭证存储或统计目录，不重启、不发送验证命令，不把验证接入正在工作的实例。

自动测试与脚本使用独立安装／进程、隔离配置、临时工作目录、会话与数据目录。只读利用已有凭证供独立探针或隔离进程鉴权是局部例外，不授予正式环境写权限；不能执行登录、刷新写回或自动修改正式凭证存储。正式切换只在人类验收后由用户手动执行。

### 少量真实接口冒烟与秘密边界

Q9 经用户明确调整，不要求逐次人工介入：代理可自主进行少量必要的真实请求，用于贯通冒烟或获取接口返回格式，不应重复多次执行、不循环探测、不自动反复重试，不进入 test cases。

脚本只在本地执行进程读取用户提供的凭证文件并用于鉴权。秘密不得打印、进入模型请求上下文、对话或验收日志，不持久化到证据资产；返回数据作为分析／mock 素材时脱敏。已有凭证位置仅作[执行输入记录](../assets/acceptance-confirmation-2026-10-13.md#执行输入)，不是加载凭证的文档链接。缺文件、失效或必须改正式凭证存储才能继续时跳过，并留记录供人类参考，不要求当场补齐。

独立真实冒烟提供辅助证据，不替代人类的真实服务最终验收。凭证路径获准不证明文件可读、鉴权有效或接口调用成功；本轮没有读取秘密或发出调用。

### 支持基线与冻结规则

Q1 同意：优先从现有 OMP 18.5.0（@9348320）支持基线补齐已确认的公开 Viewed session 出口，不顺带升级其他宿主能力。若实施调查证明必须换基础版本，显式提出变更，不默认本机安装版本或 latest。

宿主补丁完成后冻结精确 revision 与实际可运行 artifact，对该组合进行独立验证。最终记录宿主版本／revision、framework／extension 源码 revision、依赖版本／lockfile 与环境；当前 Windows x64／Bun 1.4.2 支持记录不因本文自动改变。完整验证和人工验收后才显式更新支持声明，不提前编造不存在的补丁 revision，不要求同时维护旧新两条生产支持路径。

独立验证与支持声明机制消费[原 support 权威](../../../framework/docs/harness-support.md#independent-compatibility-verification)，不恢复启动版本／shape 检查、自动准入或报告门禁。公开出口先宿主再 adapter／公共 Interface／消费者，沿[装配前置](10-assembly-layout.md#public-viewed-session-prerequisite)。尚未实现的补丁是实施工作，不是未回答的规划问题。

### 完成记录、人工切换与回退

Q6／Q10／Q13 确认：自动化验收通过与完整迁移验收完成分开。脚本已转人工的项目记录为待人工，不算已通过，也不因转换本身视作 test case 失败；完整验收须收口全部必需人工项。源码检查、零 usage fixture、局部计算／Promise 探针或绿色局部套件不能冒充生产链路证明。

一份轻量验收记录足够：精确版本／revision／环境与依赖、test cases 运行结果、OMP 脚本和独立真实冒烟的通过／失败／跳过结果、待人工场景及简要步骤、人工验收及正式切换确认。不建额外证据平台、不要求每项通过场景的完整日志；失败或关键贯通保留够用且脱敏的信息。

人类先在隔离环境完成验收，再选择合适时机停止正式 OMP，手动备份旧配置与旧统计，准备从空开始的新统计、新旧扩展加载互斥并重启。复用旧目录前手动备份清空，目录／固定文件／路径语义消费[存储原权威](06-local-storage.md)，程序不自动迁移或清空旧数据。正式确认失败时停止新实例、保留新数据供排查，恢复旧配置与旧备份后重启，不合并新旧统计。实施者提供清单，不在代码实现期间执行这些动作。

## Decision

本次文档优先，永久测试 mock 网络、真实 OMP 脚本尽力自动化、少量真实冒烟自主且隔离、真实服务与视觉最终由人类验收。冻结可运行宿主补丁组合后明确支持范围，轻量记录完成状态，正式切换与回退由用户手动完成；本票不执行迁移或认证。

## User stories

1. As a 实施者, I want 以本次权威文档验收并只在缺口参考旧源码, so that 不重复恢复旧需求或用当前代码覆盖批准政策。
2. As a 开发者, I want 可重复且不含真实网络的 test cases, so that 高质量产出与快速迭代不依赖服务或付费调用。
3. As a 实施者, I want 脚本驱动隔离的真实 OMP 并允许高成本场景转人工, so that 接线有真实证据而不陷入过度自动化。
4. As a 用户, I want 正在调度 subagent 的环境保持不动, so that 实现和验证不会打断正在运行的工作。
5. As a 实施者, I want 只读凭证支持少量自主冒烟且缺凭证可跳过, so that 获取真实接口信息无需逐次人工介入也不泄露秘密。
6. As a 用户, I want 人工确认真实服务与视觉效果并手动切换, so that 自动化通过不会被误作完整验收或部署授权。
7. As a 维护者, I want 精确冻结版本和轻量验收记录, so that 支持声明可追溯且待人工项不会被标成通过。

## Preconditions

- [完整组织与装配](10-assembly-layout.md)提供消费者切换、公共生命周期／范围／展示 Seam、冻结 oracle 和公开 Viewed session 宿主前置；生产代码与补丁仍需图外实施。
- [行为](01-behavior-contract.md)、[归属](02-accounting-ownership.md)、[观察](03-observation-contract.md)、[数据](12-state-data-contract.md)、[存储](06-local-storage.md)、[认证](04-provider-access.md)、[HTTP](05-http-capability.md)、[命令](07-command-state.md)、[展示](08-presentation.md)、[刷新](09-refresh-lifecycle.md)、[模型](13-model-catalog-policy.md)提供待验收业务契约；不恢复被修订的旧要求。
- 已有 dock／候选脚本可作为实施基础，但最终 patched artifact、扩展场景、结果报告尚未产生；设计前置不要求先交付生产。
- 真实请求需要只读可用凭证，否则记录跳过；正式切换需要用户完成人工验收、备份和停机。

## Postconditions

- 后续实施整理验收清单时消费本次权威与上述验证分工，不另建全量旧实现对照或额外测试覆盖政策。
- 脚本降级人工不取消验收要求，不扩张为 test cases 的成本豁免；付费冒烟与永久 mock 测试分离。
- 完整迁移、支持声明和正式切换不由本票 resolved 或局部测试通过推导；全部实施与执行结果在图外工作流记录。

## Invariants

- 延续装配的公共 Interface、原 native import seam、Owner／逐 Session 对称与消费者行为，不为验收保留旧生产路径。
- 复用 tests/harness-dock/、scripts/verify-omp-candidate.ts 和独立 support 机制，不把报告或兼容检查插入正常启动。
- 正式 OMP 配置／运行时／数据不被开发与验证写入；唯一凭证例外是执行进程只读鉴权，不泄露、不写回。
- 网络 mock test cases、独立少量真实冒烟、人类真实服务／视觉验收三者不混淆。
- 统计 schema、路径、归档、损失边界与计价政策仍只由原主题定义；新旧统计不自动合并，正式切换由人类执行。
