# 08: 工具续跑与轻量 Round 累计

**What to build:** 工具与正常续跑组成同一连续活动 Round，消费只来自真实模型请求，用户能观察最近一轮（进行中或刚结束）自身累计。

**Delivers:** P3, P14, P15

**Blocked by:** 07: 请求锚价与可靠 usage 记账

**Status:** in-progress

## Acceptance criteria

- [ ] 工具返回和 round_end 不增加消费，工具后的真实新请求增加一次；工具续跑总值使用独立字面预期。
- [ ] framework 统一拥有 Round 开闭/结束候选复查，adapter 映射可靠信号；工具、已知自动续跑、排队输入及驱动继续的子等待保持同轮，子结束不能关闭父轮。
- [ ] 非续跑结束先提交候选并返回，下一任务轻量复查同实际 Session 静止且无已知续跑才结束，不轮询、不用超时猜结束。
- [ ] 截断/恢复/重载不伪造正常完成证据；正常结束、取消和终止失败尽量共用结束位置，不混淆活动 idle 与保存完成。
- [ ] 最近一 Round（进行中或刚结束）从同 Session 同周期可靠运行期快照和已算金额差分取得；只有本 Session 自身消费，父子活动和迟到子消费不回填父 Round。
- [ ] round_end 捕获稳定自身聚合及关系，异步提交并在 handler 返回前承接真实结果；不把一般保存变为后续事件屏障。
- [ ] 受控公共事实 tests 与隔离真实工具续跑观察消费、候选复查及连续两轮展示，预期独立；无历史 Round 持久账本。
- [ ] 通过批准的生产公共 seam 观察行为，预期来自合同/规格、独立字面值或手算，不以被测实现重算；永久网络 tests 使用 mock。
- [ ] 使用隔离安装/配置/工作/Session/数据根，不操作正式 OMP；承接异步失败并保留够用脱敏证据，完成本票自动检查及材料准备，不因计划人工验收暂停可执行工作。

## Verification responsibility

本票负责所列 Delivers 的自动 coverage 与适用宿主贯通/证据准备；P58/P52 按本票具名责任执行。合同采用 Rapid iteration：H1/H2 及允许的条件性 H3 按原 Coverage 交用户确认，未确认不记通过；不改变承诺或免除实现/永久 tests。
