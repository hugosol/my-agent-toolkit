# 04: 安全文件更新与锁恢复

**What to build:** 公共调用方在同机本地文件竞争下安全读改发布，等待失败不迟到写入，失效锁有可靠恢复路径。

**Delivers:** P48, P49, P50

**Blocked by:** None (can start immediately)

**Status:** closed

## Acceptance criteria

- [x] 单一异步入口接绝对目标和更新函数；以现有父目录 realpath 加文件名协调别名，同键进程内 FIFO、不同文件独立，空闲键释放，失败不毒化后续队列。
- [x] 跨进程锁原子排他，权限内重读/解析最新文档再调用业务更新函数，同目录临时文档原子替换；读者只见完整旧/新文档，损坏时不调用更新且不覆盖。
- [x] 进程内排队与跨进程取锁默认合计 15 秒，可覆盖；等待超时/取消保证不迟到写，更新开始后等待真实结果，不假报取消或承诺整次硬时限。
- [x] 返回可判别等待超时/取消、IO、损坏与业务拒绝；不理解消费 schema，不增同步第二入口、后台重试、持久队列或 native file-lock 依赖。
- [x] 只有可靠确认持有进程退出才能回收锁；不能凭年龄抢活锁，未知活性有限失败；失效锁恢复后可提交，失败释放自身资源且不长期堵塞后续。
- [x] 用真实临时本地目录和独立进程验证存活/退出、别名竞争、FIFO、不同文件进展、完整读回、失败后继续以及受控占锁/排队取消；内存锁模拟不能替代安全证明。
- [x] 通过批准的生产公共 seam 观察行为，预期来自合同/规格、独立字面值或手算，不以被测实现重算；永久网络 tests 使用 mock。
- [x] 使用隔离安装/配置/工作/Session/数据根，不操作正式 OMP；承接异步失败并保留够用脱敏证据，完成本票自动检查及材料准备，不因计划人工验收暂停可执行工作。
