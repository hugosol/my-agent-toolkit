- **推断**：`docs/agents/issue-tracker.md`／`triage-labels.md` 已提供槽位（`in-progress`／`closed`、实现票的 `## Comments`），但票据对象本身看不出「有未决项」，因此缺口不会自己路由——一次 retry（一个完整实现轮＋协调者重述）正是这样产生的。
- **建议**：实现轮的第一步/最后一步显式命名状态动作（开工置 `in-progress`；收口在票据 `## Comments` 以固定形状记「缺口 → owning 承诺 → 需要的证据 → 被什么挡住」，并决定 `closed` 或回退状态）。或加一条最小检查：证据里出现「未决／待裁决」而票据 Status 仍为 `ready-for-agent` 时报出来。

## 2（高）没有 guardrail，且显示类断言是「负向子串」，跨模式泄漏行天生看不见

- **事实**：仓库没有 `.github/`、没有 `.husky`／`.githooks`、没有 eslint/biome/oxlint 配置，也没有 `CODING_STANDARDS.md`／`CLAUDE.md`；`package.json` 里 `test`／`test:dock`／`test:framework`／`typecheck` 都在，但没有任何东西自动运行它们。该缺陷在本轮之前 survive 了记录中的 255 例 `tests/model-cost` 与 ticket 25 的 862 例全仓。既有断言形状是负向子串：dock 的 token-only 用例断言 `not.toContain("¥")`／`not.toContain("Cache/In/Out")`，`detail-tree` 用 `line => !line.startsWith("Balance:")` 过滤比较帧，S2 套件没有「持有读数 × 非 monetary 目标」这一组合。

- **建议**：(a) 补最小 guardrail：CI job（或 pre-commit）跑 `bun run typecheck` ＋ `bun test`（全仓 292s，最该被自动化）；(b) 给显示类 seam 一条审查规则：断言「该模式画出的整组行标签」，而不是在整段文本上做子串否定；并在真实宿侧补一个单次运行内覆盖 monetary／token-only／allowance／hidden 的模式矩阵用例。

## 3（中高）dock 测试支撑里的两个具体陷阱

- **事实**：`savedSession(file, predicate)` 返回**首个**匹配记录，我用 `own[GO_PROVIDER] !== undefined` 时拿到第 2 阶段那次保存（deepseek `1000/1000`），而断言是终局 `2000/2000` → 一次真实宿运行失败；把 predicate 改成同时要求终局状态才稳定。`widgetFrames`／`widgetTextWhere`／`shownLinesWhere` 三个等待 helper 在 `model-cost-balance.test.ts` 与 `model-cost-modes.test.ts` 之间各存一份（本轮又拷了一份）。「一次运行同时配好 DeepSeek＋Go 并脚本化余额应答」需要我现场扩 `Provision` 联合，并把 `startRun` 的位置参数 `withModelCost` 换成 `RunOptions` 对象（动了别的票也在用的文件）。
- **推断**：等待 helper 的契约（「等到文档出现该用例期待的记录」）被「首个匹配」满足，于是期待终局的用例会静默读到旧 save；多 provider＋脚本余额的 provision 每次靠改 `startRun` 形状。
- **建议**：`savedSession` 改为返回**最后一个**匹配，或把该陷阱写进注释；把 widget 轮询 helper 提升到 `tests/harness-dock/index.ts`（该文件自称是 dock 消费者的唯一入口）；给 dock 一个可组合的 provision（N 个 provider ＋ 脚本余额），而不是每票改签名。**未验证**：其他 dock harness（如 combined-host）是否已有等价 helper。
