## 2. `mock.module` 在该 runner 里是进程级，可静默破坏或挂起其他 suite（严重度：高）

**事实**（本票真实踩坑，两个版本都试过）
- v1 固定名：`tests/model-cost/consumption-archive.test.ts` 用 `mock.module("node:crypto", …)` 强制归档名冲突 → `tests/model-cost` 里**另一个文件** `period-switch.test.ts` 的「an earlier archive is never replaced by a later switch」失败 2 例（266 pass / 2 fail）。
- v2「队列 + 回退真随机」想让泄漏无害 → 整个 `tests/model-cost` 分区 600s 超时（`bun test tests/model-cost` 原本 3.1s）。
- 删除该文件 → 3.1s / 266 pass 恢复。

**建议**
- 加确定性检查：一条 lint/rule 禁止 `tests/**` 出现 `mock.module(`（本仓库已有 `ts-*` 自定义规则，代价低）；需要替换时必须走**注入 seam**。
- 若确需模块级替换，写进 reviewer 的 `CODING_STANDARDS.md`：替换物必须是真实模块的**超集**，且不得改变其他调用者的语义；并在用例里注明「该 mock 的泄漏面」。

**预期**：杜绝「加一行测试替身、别的分区挂 10 分钟」这类跨文件破坏；也把「为测试发明 seam」与「模块级替换」的取舍摆到明面。
