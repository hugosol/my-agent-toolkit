## 候选改进（按严重度）

### 1. 仓库没有 guardrail（**事实**：无 CI、无 lint、无 hooks、无 CODING_STANDARDS.md）

- **事实**：`.github/` 不存在；无 `biome.json`/eslint 配置；`.git/hooks` 只有 samples；`package.json` 只有 `test`/`test:*`/`typecheck`/smoke 脚本。
- **事实**：宿主 `builtin-defaults` 的三条 TS 规则（ts-no-tiny-functions、ts-set-map、ts-no-any）本次各触发一次提醒，且都发生在工具调用**之后**（"configured not to interrupt"）——我依赖自己读到提醒再把 `Set` 改成 `Record`、把一行函数内联。这些规则只活在宿主，不在仓库，换任何 agent/环境都不复现。
- **建议**（机械类 → 走确定性检查，而不是写规则）：加一个 `lint` 脚本（biome 即可，含 `noExplicitAny` + 自定义「静态成员表用 `Record` 而非 `Set`」「单表达式包装函数内联」），并在 CI 里跑 `bun test` + `bun run typecheck` + lint。仓库现在已经把 `typecheck`/`test` 写进 `package.json`，缺的只是「有人每次都跑」这层。
- **前置**：CI 要能绿，必须先让已知红可见（见 2）。

### 2. 已知失败没有单一事实源（**事实**：全仓 5 红，三张票各写一份）

- **事实**：本次实测全仓 `bun test` = 888 tests / 883 pass / 5 fail：2 条 `tests/harness-dock/baseline.test.ts`（兄弟 checkout `../oh-my-pi` 停在 579da1d6 而非 v18.5.0 9348320）+ 3 条 `tests/connect-bot`（2 条 30s 面板窗口实测、1 条 `native-session-boundary.test.ts` 的扫描命中 `extensions/model-cost/harnesses/omp/widget.ts`）。
- **事实**：17/19/20 票的 `assets/*-evidence-*.md` 各自记录了自己版本的「环境性失败」，20 票还专门提示我 `baseline.test.ts` 是唯一慢/已知红文件；没有任何一处是权威清单。
- **建议**：一份 `docs/agents/known-failures.md` 作单一事实源（用例、原因、是否环境性、复跑方式、何时移除），`AGENTS.md` 只留一行指针。直接收益：后续 agent 不必像本次那样额外跑 99s 的消费方套件才敢写下「与本票无关」。
- **顺带**：这份清单是 CI 转绿的前提（修掉或显式 `skipIf`）。

### 3. 宿主契约的可读来源缺一行导航指针（**事实**：18 行日志落在 minified 打包上）

- **事实**：为回答「RPC 模式下 hasUI 是否 false、怎么进入 headless」，我先对 `dist/cli.js` 做了多次 `grep -o`/窗口读取，多次返回 3–4KB 的单行输出；真正一步到位的答案是可读的 `dist/types/modes/rpc/rpc-mode.d.ts`（`--no-ui`: extensions run with `hasUI=false` and no UI frames）与 `dist/types/extensibility/extensions/types.d.ts`（`hasUI: boolean`「false in print/RPC mode」）。
- **建议**：在 `framework/docs/harness-support.md`（dock 的既有文档落点）加一行：宿主的扩展/RPC 契约读冻结安装里可读的 `dist/types/**/*.d.ts`；`dist/cli.js` 是 minified 打包，别在它里面读语义。同一行可带上一句本次确认的用法：headless 运行 = dock 的 `extraArgs: ["--no-ui"]`。
- **推断**：这条最省时间——本次约 1/5 的探索成本花在它上面。

### 4. dock 的两条时序/单位约定只藏在测试注释里（**事实**：各让我多花一轮）

- **事实 (a)**：一个 Round 的结束由宿主「下一个 task」确认，因此**单次 prompt 后立刻读 `consumption.json` 会等不到**（我第一次用 15s 轮询超时才意识到）；正确说法写在 `round-facts.test.ts` 头部（"a second prompt afterwards opens a second Round"）。
- **事实 (b)**：`startCaptureServer` 的 `usage.input` 是**总 prompt tokens（含 cached）**，扩展存的是 `input − cacheRead`（我第一版断言写成 10，由失败输出纠正为 7）。
- **事实 (c)**：framework 的 actions 拒绝未知参数时**不回显参数**，只打印 help（我猜它回显，一次断言失败）。
- **建议**：把 (a)(b) 收进 dock 的参考落点（`tests/harness-dock/README.md` 或 `session.ts`/`capture-server.ts` 顶部「约定」小节）：一条讲「读保存文档前要有第二次活动」，一条讲「wire 数字 → 记账桶的换算」。 (c) 属行为细节，补一句在 `framework/docs/framework-capabilities.md` 的 actions 段即可。

### 5. 全仓测试很贵，缺一条「迭代期跑什么」的默认（**事实**：~8 分钟）

- **事实**：`bun test tests/harness-dock` 123s、`bun test` 264s、`bun test tests/connect-bot tests/codebase-tools` 99s；而本票只改了 model-cost 的 shared logic，消费方套件不可能受影响。20 票同伴随消息给的经验值（「单文件 ~2.7s vs 整目录 ~105s」）也确实只存在于它的会话里。
- **建议**：`AGENTS.md`/`docs/agents/` 一行「迭代期：`bun test tests/model-cost`（~3s）+ 改动对应的单个 dock 文件（~15s）；全仓 `bun test` ~4.5min 且含已知红」。这是典型环境缓存：能挡住每次 agent 的全仓冲动。

### 6. model-cost 扩展当前不在 git 追踪内（**事实**：`git diff` 空输出）

- **事实**：`git ls-files extensions/model-cost` 只回 `GLOSSARY.md`；`shared-logic/`、`harnesses/`、`definition.ts`、`config.yaml` 全是 untracked，`git diff <runtime.ts>` 因而无输出，我随后花了数次调用排查「改动是否丢失」。
- **建议**：迁移期在 `AGENTS.md` 加一行「model-cost 扩展树尚未提交：它对 `git diff` 无输出，核对改动请用 read/edit，别用 git diff 判断」；`git status --short | head` 的最初 60 行也因这个原因具误导性。迁移结束后删掉即可（临时导航指针）。

### 7. 子代理任务提示可以形状化（**推断**）

- **观察（事实）**：我收到的任务提示把跨票状态与运行经验压成一段中文长句（"20retry完widgetvisual20cases/255model/385framework+61dock2baselinefails…"），我额外花精力才拆出「哪些失败是既存的」。
- **建议（推断，属宿主/orchestration 层）**：改成固定小标题（已知红 / 可复用经验 / 本票边界 / 禁止项），比长句便宜且不易漏。这与本仓 `AGENTS.md` 的极简风格一致——把内容放对位置，而不是放长。

## 有效做法（保留，不要动）

- **事实**：`.scratch/<feature>/assets/*-evidence-*.md` 是最有用的导航面。`grep -rn "无 UI" lighthouse assets` 一次就给出批准规则（08 展示表、09 刷新段）与既有 S5 模式，比通读 43KB contract + 49KB spec 便宜得多。建议在实现票模板/`AGENTS.md` 里明确「设计 S5 用例前先查 assets 的既有 evidence」。

## 与本票行为有关的判断点（需人工/上游复核，不属环境改进）

- **事实**：无 UI 时我只报「请求确实发出且失败」（`unreachable`／`unreadable`）；`no-access`（本机无该 provider 凭据）与 `misconfigured`（命名代理未配置）没有请求结果可报，只留在只读结果。替代方案是连这两类也报，代价是无 Codex 凭据的 headless 用户每次启动看到一行错误、且仓库自带配置下 codex 启动查询恒为 `misconfigured`。已记入证据文档 §1/§7 供验收复核。
- **事实（未验证项）**：真实 30s 成功 TTL 边界未在真实进程里等待；用可控时钟（S2）覆盖时间规则、真实无 UI 运行覆盖「刷新查询确实发出」。已在证据文档 §7 显式标注。
- **未验证**：`--no-ui` == 「hasUI=false 且无 UI 帧」只在冻结的 18.5.0 上验证（其 `.d.ts` 与实跑一致），未跨版本核对。
