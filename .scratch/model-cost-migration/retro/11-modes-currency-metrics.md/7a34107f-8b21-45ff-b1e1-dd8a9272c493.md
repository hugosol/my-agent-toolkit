# Retro — ticket 11 (消费模式、双币种与只读指标), TDD run `7a34107f-8b21-45ff-b1e1-dd8a9272c493`

Scope: this execution only (`11-modes-currency-metricsmd-2`, the retry that had to wire the approved production Codex price fact). Findings are ordered by severity; each notes facts, inferences and what stayed unverified.

## 1. High — a typechecking guardrail is scripted but not wired

Facts. `package.json` exposes `test` (`bun test`) and `typecheck` (`tsc --noEmit`), and `bun test` does not typecheck (it strips types). I removed the capture server's `protocol` option; `tests/codebase-tools/outbound-role.test.ts` kept passing it — `bun test` for that suite would still have been green (the server ignores the unknown key), while `tsc` failed with `error TS2353: ... 'protocol' does not exist in type 'CaptureServerOptions'`. The same class of leftover (an unused `CaptureProtocol` import) only surfaced when I finally ran `bun run typecheck` after all edits. There is no lint script and no aggregate check script in `package.json` (fact, read at the start of the run).

Suggestion. Add one aggregate command (`"check": "bun run typecheck && bun test"`) and run it from a pre-commit hook or the repo's CI job, so a rename/removal that only breaks types cannot land. Unverified: whether a CI workflow or git hook already exists — I never inspected `.github/` or `.git/hooks`; if one exists, the finding is that it does not run `typecheck`, not that a new one is needed.

## 2. High — the ticket's own evidence asset is not a named deliverable step

Facts. `.scratch/model-cost-migration/assets/11-modes-currency-metrics-evidence-2026-10-13.md` was the single highest-value read of this run: its "未验证项" section stated the exact gap the retry asked me to close (production Codex Ref and its ratio unreachable, visible only with an injected catalog). It is now stale — it still says the production price source is unreachable and that the allowance dock case asserts no `Ref:`, while that case now asserts `Ref: $0.0050` and a saved `referenceCostUsd`. The run ended (budget order) before I updated it. The ticket's acceptance list does name "材料准备", but nothing in the role text turns that into a step with a path.

Suggestion. Make "update `.scratch/<feature>/assets/<ticket>-...-evidence-*.md`" an explicit completion item in the ticket template and in the TDD ticket role text, the same way the ticket names its own test files. The asset is the first thing the next agent reads; nothing else in the environment keeps it honest.

## 3. Medium — the process-wide configuration cache is an undocumented trap for suites that build the runtime from the factory context

Facts. `getConfig(definition)` (`framework/core/config.ts`) answers from `validatedConfigs`, recorded once per definition id for the whole process. When I rewrote `tests/model-cost/display.test.ts`'s `bindDisplay` to build the runtime from the factory's `context.config` — the production shape — every case after the first silently loaded the first case's storage root: 12 failures that all looked like "the baseline was not loaded" (all-zero tokens) rather than a config problem. The suite's existing comment ("this reader answers the declaration so the binding validates without touching the repository's own file") does not warn against using `context.config` for the runtime; the neighbouring suites all pass their own root explicitly, which is the workaround, not the rule.

Suggestion. State the rule once, where the double lives (`tests/framework/support/harness-port-double.ts` header or its `bind` docs): the validated configuration is recorded once per extension per process, so a suite whose cases each own a root must pass that root to the runtime itself. One sentence in a file that both framework and extension suites already read.

## 4. Medium — host-side price facts had to be re-derived from the isolated 18.5.0 install

Facts. Answering "what does the host state a model costs" required reading the installed package: `@oh-my-pi/pi-catalog/src/models.json` (per-provider `cost {input,output,cacheRead,cacheWrite}`), `extensibility/extensions/model-api.ts` (`ctx.models.list()` is `modelRegistry.getAvailable()`), `providers/openai-shared.ts#calculateOpenAIUsageAccounting` (`input = prompt − cached − cache_write`), and the Codex Responses usage details. `framework/docs/harness-support.md` is the repo's own register of harness differences and contained none of this; `lighthouse/13-model-catalog-policy.md` said only that the adapter maps the native fact.

Suggestion. Add three pointer lines to `framework/docs/harness-support.md`: where a model's price is readable (`ctx.models`), its unit (USD per million tokens — the same unit the host's own usage readout prints), and the Responses wire→bucket mapping. That is the material any future harness-difference test needs, and it is exactly what this run had to reconstruct from a dependency.

## 5. Medium — `models.yml` has two writers in the dock, and the shared seam resisted extension

Facts. `tests/harness-dock/agent-config.ts` owns "write `models.yml`", yet `model-cost-modes.test.ts` hand-wrote its own for the Go provider. The run needed one file with two providers and one provider with explicit model definitions and prices; the shared writer could not express either. Extending it in place meant either a one-line plural wrapper (flagged by this repo's `ts-no-tiny-functions` rule) or a local third writer — which is what I ended with, in the same suite that already had one.

Suggestion. Consolidate on one writer taking several providers and optional model definitions (id, api, reasoning, input, cost, contextWindow, maxTokens). If you want it enforced rather than remembered, it is a mechanical rule a reviewer can apply: a dock suite does not write harness config files itself.

## 6. Low — rule reminders that match an edit's surroundings rather than its change

Facts. The `ts-set-map` reminder fired on an edit that only added two `if` statements beside pre-existing `new Map()` usages; the `ts-no-tiny-functions` reminder fired on an edit that retained a pre-existing exported helper with seven call sites (a case its own "allowed" list covers). Both nudged restructuring of code the edit did not touch, and both cost a detour from the actual change.

Suggestion. Match reminders against added lines only, so an edit is judged by what it introduced rather than by the context it landed in.

## 7. Low — verification ordering across files shared with other suites

Facts. I ran `bun test tests/framework` (39s) early, then changed `tests/harness-dock/capture-server.ts`, which `tests/codebase-tools/outbound-role.test.ts` also uses; that earlier run's result was partly superseded, and the whole-repo `bun test` never ran this round. Per-slice runs were needed (red → green on each new case), so the waste is the suite-level run whose files changed afterwards, not the slice runs themselves.

Suggestion. Keep per-slice runs scoped to the file under test, and make the end-of-run verification the aggregate `check` from item 1; that also removes the temptation to run a whole suite "just in case" mid-flight.
