## 1【高】dock 的"宿主硬事实"没有落点，四项事实各花掉多轮试错

- 类别：信息获取 / 导航。
- 事实（本会话逐条踩过，均有失败运行或源码读取为证）：
  1. 自造 provider 必须同时写 `baseUrl`＋`apiKey`＋`api`＋`models`；只写 `auth: "none"` 或省略 key，宿主在发问前以 `No API key found for opencode-go.` 拒绝，捕获端点收到 **0** 个请求。首两次探测失败，第三次加回 `apiKey` 才通。
  2. `contextWindow: 64_000`（YAML 下划线字面量）与内联 `cost: {…}` 会让配置文件整体失效（模型仍能解析，但 key 未安装），表现仍是第 1 条的报错。
  3. RPC 模式下 `ctx.hasUI === true`（只有 `--no-ui` 为 false），因此 `setWidget` 帧在普通 RPC 运行里真实出现；"hidden 不创建 widget"必须断言**没有携带 lines 的帧**，而不是"没有帧"。该事实来自 `rpc-mode.ts` 源码注释，花了专门一轮才确认。

  5. allowance 运行需要 `protocol: "openai-codex-responses"` 的捕获端点＋`providers.openaiWebsockets: off`，否则请求不进观测面。
- 事实：`tests/harness-dock/` 下**没有任何 markdown 文档**；`agent-config.ts` 只记录了"覆盖内置 provider"这一种用法，`capture-server.ts` 的 usage 注释只说"reported buckets"，RPC 的 `hasUI` 与"自定义 provider 需 apiKey"两条完全无落点。
