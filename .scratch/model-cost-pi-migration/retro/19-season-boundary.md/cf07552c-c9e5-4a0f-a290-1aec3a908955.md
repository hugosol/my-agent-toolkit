## 1.【高】真实宿主 dock 分档在任何新 worktree 上直接不可运行（patch 工件被 CRLF 改写）

**事实**（本轮实测）：本 worktree 跑 `bun test ./tests/harness-dock/model-cost-modes.test.ts` 在**装载阶段**就抛 `host-patches/omp-18.5.0-viewed-session/patch.diff touches no file`（`tests/harness-dock/host-patch-artifact.ts:224`）。根因已定位到可复现的三条事实：

- `patchTouchedFiles` 按 `"\n"` 切分后匹配 `/^diff --git a\/(.+?) b\/(.+)$/`（`host-patch-artifact.ts:127-135`）；JS 里 `.` 与 `$` 都不跨 `\r`，所以带 `\r` 的行 0 命中——实测 `patchTouchedFiles(text)` 返回 `0`，同一文本去掉 `\r` 后 8 行全命中。
- 该文件在工作区是 CRLF（27184 字节，599 个 `\r\n`），在 git 索引里是 LF（26585 字节，`git show HEAD:...| file -` 显示无 CRLF）。
- 仓库**没有 `.gitattributes`**，而本机 `core.autocrlf=true`，于是检出即改写这些工件的字节。

**代价**：迁移验收里最贵、也最需要真机证据的那一档（OMP 真实宿主：widget/`setWidget` 帧、Viewed/Codex 补丁链）在**任何新 Windows worktree 上静默不可用**；全仓 `bun run test` 在 fresh worktree 上会在 dock 装载期失败而非按用例失败；本票的 OMP 侧因此只有 hermetic 分区的证据（证据文件已如实标注，未把 dock 通过算作已得）。

**建议**：

1. 加 `.gitattributes`，对工件按“作者字节”处理：`*.diff -text`（或 `*.diff text eol=lf`）。这是单行、repo 级、可一次修掉三个 `host-patches/*` 的根因（`omp-18.5.0-viewed-session-codex-response/` 下未找到 `patch.diff`，需确认其工件形态）。
2. 让解析器对 CRLF 免疫（按 `/\r?\n/` 切分或 regex 用 `\r?$`），作为防御层；`ensurePatchArtifact` 现有的 `throw` 就是可用的检查点，只差把它稳定接上。
3. 若工件还要做 hash/冻结断言，**注意同一根因的第二个面**：`ensurePatchArtifact` 会 `sha256File(entry.patchFile)`，而工作区字节已被检出改写——这一条本轮**未验证**（[推断] 风险，未比对记录值），修 (1) 时应顺手核一次。

## 2.【高】fresh worktree 缺少依赖引导步骤，`bun run typecheck` 一上手就不可用

**事实**：本 worktree 没有 `node_modules`。第一次跑 `bun run typecheck` 的输出是 `bun: command not found: tsc`，脚本以 1 退出；`bun install --frozen-lockfile` 后（13 packages，1.75s）才可用。`docs/agents/testing.md` 只写“Run `bun run typecheck` for TypeScript changes”，没有任何 bootstrap 步骤；本轮的任务说明也只说“不要擅自正式安装/切换用户数据”，未提到“先装依赖”。

**代价**：每个 ticket 子代理在 fresh worktree 上的第一次门禁调用都会白跑一次；若集成者在 fresh 检出上跑 `bun run test`，会在任何用例之前就失败（同 (1) 的效果叠加）。

**建议**：在 `docs/agents/testing.md` 开头（或 ticket 模板的“环境”段）写明 fresh worktree 的第一个动作：`bun install --frozen-lockfile`（并说明它只写 gitignored 的 `node_modules/`，不触碰用户数据）。若 worktree 由宿主创建，更省的做法是宿主在 provision 时就把依赖装好。
