## 2.（高）缺少 `.gitattributes`：三个文件的 EOL 随检出而变，既触发 §1 又破坏 dock 测试

### 事实

- 本仓库 `core.autocrlf=true`（`file:D:/Program Files/Git/etc/gitconfig` 与 `E:/Developer/myhub/my-agent-toolkit/.git/config`），`bun.lock` 与 `host-patches/**/patch.diff` 都没有属性（`git ls-files --eol` 的 attr 列为空），因此它们的行尾由「谁最后写它」决定：本 worktree 是 `i/lf w/lf`（工具以 LF 重写），别的工作树是 `i/lf w/crlf`（git 检出成 CRLF）。
- 同一 run 的其他票据报告（第一手，未被我复验）把 CRLF 检出列为分区失败根因并给出修法：`patchTouchedFiles` 用 `split('\n')` 解析，CRLF 下 `patch.diff` 解析出 0 文件（10–11 例 `patch.diff touches no file`），`baseline.test.ts` 记录 LF blob 哈希与 CRLF 工作副本不符（`implement-08b4b58d…:69`、`implement-4103ce8a…:86`、`implement-3ea03086…:52`、`implement-299bb2b0…:15`），并建议 `.gitattributes`（如 `*.diff -text`、`bun.lock text eol=lf`）。

### 影响

同一个「环境事实」同时制造两类失败：LF 版工作副本 → §1 的 stat-dirty 假阳性；CRLF 版工作副本 → dock 分区约 12 例环境失败。两者都反复出现在报告与「未验证项」里，消耗实现/验收 agent 的注意力。

### 建议

在仓库根 `.gitattributes` 固定这三个路径的 EOL（`bun.lock text eol=lf`、`host-patches/**/*.diff -text`，或等价写法），使检出结果与 blob 字节一致。这同时消灭 §1 的复现前提和 ~12 例 dock 环境失败，并让「提交后工作树是否干净」变成稳定判据。
