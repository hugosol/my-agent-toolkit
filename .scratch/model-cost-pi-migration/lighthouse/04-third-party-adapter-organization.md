# 第三方能力适配的集中组织与公共语义复用：Lighthouse（部分发布）

> Question and discussion: [第三方能力适配的集中组织与公共语义复用](../decision/04-third-party-adapter-organization.md)

## Question

确定第三方能力的集中组织与公共语义复用。本次已确认内置观察、宿主隔离与两端自行计时累计的原则，不确定具体目录、接口、接线、清理或依赖失败行为；源票仍未完成且未认领。

## Discussion

### 跨票确认来源与旧到新修订

初始结果来自 2026-10-16 的 [选择 pi 子代理扩展及缺口处理路线](../decision/03-subagent-provider-choice.md) 会话：用户提出“把观察逻辑作为model-cost的内置能力即可，因为这项能力依赖于model-cost的json持久化实现”，不需通用化。代理以目标文件名明确确认后，用户回答“Q1 同意，非常准确”。

本轮同日恢复选型时，用户提出“omp也需重新设计这个能力，因为现在的计时功能也不稳定”，要求“subagent结束时显示总耗时，后续续跑累加耗时，用json持久化记录”，不再由 OMP adapter 或 nicobailon 提供计算好的 duration。对具体边界 Q8 与以 `04-third-party-adapter-organization.md` 为目标的旧到新修订 Q9，用户回答“Q8 是 Q9 是”。这授权本次部分发布，不认领或修改源票正文、状态、Assignee 或其他未答范围。

明确被取代的旧约束是“OMP 所有观察均保持现有路径”在子代理耗时这一项上的含义；修订理由为用户报告现有计时不稳定，要求两端统一自身测量。其他 OMP 观察及计费路径不因此改动。此前选型讨论中的有条件放弃耗时不是当前采用路线，不能据此省略本次已确认需求。

### 内置能力及宿主差异

子会话观察随 model-cost 交付，复用其 JSON 持久化登记与汇集，不建立单独安装的观察扩展产品。OMP 非耗时观察保持原路径，pi 使用专属观察实现；子代理耗时按下一主题在两端重新设计。

本轮不抽取或打包通用子代理观察能力；未来可能复用不构成本轮要求。共享业务登记与统计可放 model-cost shared-logic，其确切边界仍待设计；pi 原生钩子、事实读取及第三方机制隔离，OMP 不被迫依赖 pi。JSON 不创造身份、直接父链或生命周期事实。

具体目录、小接口、装配、发现、跨进程通信、订阅清理、实例/Owner 寿命及缺失/不兼容依赖的可见行为仍是本票未答范围。保持第三方适配集中在一个文件或目录的约束。

### OMP 与 pi 的子代理耗时方案

两端都由 model-cost 自行计时、累计和 JSON 持久化，不再消费 OMP adapter 或 nicobailon 算好的 execution duration。不要求运行中持续更新读数；每次实际执行结束时结算并显示该子会话的累计总耗时，同一实际会话续跑再次计时、结束后累加，不覆盖此前累计。

每次实际执行开始计时，结束结算；包含这次执行内模型请求、工具执行与等待委派结果的时间，排除结束到下一次续跑之间的空闲。取消或终态失败也结算本次已发生的时间。崩溃或缺少可靠结束事实时，不把下次恢复前的离线时间补算，也不声称完整测量成功；具体不完整读数的表示仍待设计，不自动等于零。

自行计时仍需要可靠的开始/结束事实，由各宿主适配提供；不再消费 duration 不等于移除生命周期事实适配，也不能把进程启动、第一条请求或保存时刻冒充实际执行边界。公共 Round 与 execution 不预设一一对应，边界接线须结合 [独立 Round 决策](../decision/08-pi-round-boundaries.md) 而不重定义公共语义。

同一消费统计周期内的累计、续跑与 JSON 恢复需在设计和验收中落实；既有统计周期重置语义不因本次确认自动修改。本地图包含这项跨宿主重设计的规划，不包含生产修改交付。

## Decision

确认 model-cost 内置、复用 JSON、隔离宿主机制的组织原则，并在 OMP/pi 两端采用自行计时、结束结算及续跑累计的耗时方案；其他 OMP 路径不因此改动。具体接口、边界接线与寿命设计未决定，本票保持未完成。

## User stories

1. 作为 model-cost 维护者，我需要内置观察与登记，以便避免独立安装和通用化负担。
2. 作为跨宿主使用者，我需要共享业务与隔离的宿主机制，以便复用同一份逻辑且不让 OMP 依赖 pi。
3. 作为子代理使用者，我需要结束时显示累计耗时、续跑后累加并保存，以便不依赖提供方不稳定的计时，也不把执行间空闲算入工作时间。

## Preconditions

- model-cost 现有持久化可复用，但不证明生产跨进程汇集和新计时方案已经实现。
- 选型权威与 [nicobailon 验证](07-nicobailon-runtime-validation.md) 提供固定版本输入；具体可靠执行边界尚待设计，不把探针的活跃区间当成完整 execution。
- 公共 Round 时序由独立边界票提供；本票接口设计不能把自身耗时需求直接当作 Round 定义。

## Postconditions

- 不新增独立观察扩展产品或通用抽取工作。
- 后续设计必须覆盖两端自行计时、结束结算、续跑/恢复累计、取消/失败及缺失边界；具体实现尚未完成。
- 原有“OMP 保持原路径”不再阻止这项耗时重设计，但不授权重写其他 OMP 观察/计费。

## Invariants

- 对齐 [Extension 开发地图](../../../framework/docs/extension-development-map.md)：同一份 extension definition/shared-logic，原生机制隔离，装配薄。
- Framework 保持公共身份、Turn、Round、State 与生命周期语义权威；model-cost 不复制第二套公共语义。
- 耗时不是会话跨度、仅最后一次 duration 或请求延迟；事实缺失不等于确认零。
- 本发布不改变源票正文、状态、Assignee 和其他未决上下文；源票启动时消费本权威。
