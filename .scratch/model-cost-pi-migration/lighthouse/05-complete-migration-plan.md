# model-cost 完整迁移的职责落点与验收路线：Lighthouse

> Question and discussion: [model-cost 完整迁移的职责落点与验收路线](../decision/05-complete-migration-plan.md)

## Question

在已选提供方、集中适配组织与 Round 映射下，确定完整功能的职责落点、兼容性、必要修改范围及可观察验收，使实现无需再作关键设计取舍。本票交付规划，不交付生产实现或安装切换。

## Discussion

### 确认来源与前置权威

来源为 2026-10-16 用户“请开始ticket05”后的连续访谈：

- Q1 用户指出罕见性，但明确“不过确实需要统一语义”；随后澄清范围为取消或终态失败已最终结算而后台事实仍挡住关轮，采用必要调整，不引入复杂状态机。
- Q2：“同意，只需对齐展示内容，具体的格式，间距等由人类再验收”。
- Q3：“直接补齐到pi adapter即可”。
- Q4：“同意……需要各harness独立实现……pi应当参考omp的实现方式，按照自己特性来达到同样的目的”；宿主读取、定时器接线及清理独立实现，可复用的业务计算不下移。
- Q5 用户要求共同格式与 shared-logic；Q7 对最小兼容方案答“同意”，其中包含不改路径规则、保留 runtimeMs、可选缺口信息、新版读旧记录及两端共同更新。
- Q8：“同意，身份来源必须隔离……总的用量统计可以跨harness展示，目前先按这个原则实施”。这确认规划原则，不将地图改为生产执行。
- Q9：“采用”；Q10：“同意”，分别确认分层验收与代表性效率对照。

复用而不重述政策：[完整基线](01-capability-baseline.md)、[提供方与自身计费路线](03-subagent-provider-choice.md)、[集中组织、通信、State、存储协调和耗时规则](04-third-party-adapter-organization.md)、[Round 映射与终止原则](08-pi-round-boundaries.md)。其中 pi 查看适用范围、workflow/调度加分项边界、公开事实优先级、重评条件均不改变。

### 一、完整功能的职责落点

下表是迁移交接索引；已批准的机制细节仍以对应前置权威为准。

| 功能/缺口 | 复用与必要实现 | 验收关注 |
| --- | --- | --- |
| 声明、配置、命令 | 复用同一 definition、配置校验及 shared-logic 的 `/budget detail`、`holiday`、`clear`；pi 薄装配与发现入口负责接入 | 命令效果及拒绝路径、正常会话切换；无子代理模式 detail 的既定提前返回 |
| 实际身份、父链、Owner、观察与 State | framework core/behaviors 复用公共语义；OMP 原生机制与 pi/nicobailon 私有接入按组织权威接线 | 主/子、嵌套、并发、续跑、follow、默认值与恢复；身份不按名称或进程猜测 |
| 输入、Turn、原始 usage | framework pi adapter 补公共映射，复用公共合成、scope 分发；不在 model-cost 自建原生请求监听 | 请求起点、结束、缺失 usage、去重及实际 session 归属 |
| Round 与活动 | pi adapter 按 Round 权威实现；framework 与 OMP adapter 纳入必要终止语义对齐 | 正常继续不切轮；取消/终态失败结算后结束；晚到追加与真正执行区别 |
| 改名与启动快照 | pi adapter 映射 session_info_changed、可靠启动模型及有效 thinking level | 改名及时交付；未知不借当前值；恢复、续跑不覆写原启动快照 |
| 请求价格与计费 | pi adapter 补已有 modelPrices 出口；复用维护价格、request-price、request-accounting 与现有渠道规则 | 请求锚价、统计周期、未知/零、参考费用及自身/含后代不混同；不用第三方最终 cost |
| provider 余额、额度及比例估计 | pi adapter 补已有 providerAccess；业务 endpoint、认证使用、查询、缓存/刷新及估计文档由 shared-logic 继续拥有 | DeepSeek 余额、Codex 窗口与比例估计、失败保留规则；adapter 不实现业务协议 |
| 消费保存、归档与重置 | shared-logic 拥有 schema、周期、业务合并、提交资格及只读同步；framework modules 提供既定协调/原子发布 | 并发、在途增量、冲突、旧周期、损坏文件、独立归档事务；刷新不强制提交 |
| 子代理耗时与 Session span | shared-logic 复用/调整累计与恢复；活动事实来自公共路径；span 保持原业务含义 | 粗估与完整性区分，缺失不补零，续跑累加、不补离线；耗时持久化不能被仅费用增长条件漏掉 |
| 会话上下文读数 | model-cost 各 harness 读取并归一公开 getContextUsage，交给既有 session-context/展示计算 | tokens 为 null 时未知；归属实际会话；不从账目推导，不以 context window 替代显示预算 |
| 峰谷边界等待 | 复用既有价格时段/重绘目的；OMP 接宿主管理 timer，pi 自持并按寿命清理 | 一个 UI 实例一个等待，子会话不另建；无 UI 不持有；绘制不发请求/写盘 |
| brief/detail、代理树及统计展示 | shared-logic 提供相同业务内容；各 harness 独立原生绘制、主题及专属接线 | 内容等价；未知/不完整、预算条、Accrued 与费用结构不丢失；格式由人类验收 |
| 查看目标与切换 | OMP 原 Viewed 路径保留；pi 沿用选型权威的主会话展示范围，不跟 inspector 切换 | 不能以来源会话、Owner 或展示名冒充查看事实；真正实际会话切换按既定生命周期处理 |
| 入口、加载及释放 | 新 pi discoverable 入口仅导出薄装配；子入口经 framework 集中加载，同/独立进程复用业务；根专用效果隔离 | 入口确实被发现，子观察生效、无重复根预取/UI、退出/重载释放完整 |

上下文原生读取、定时器载体及绘制机制不因此提升为 framework 公共能力；各 harness 参考 OMP 的目的而非复制 OMP 原生假设。计费、记录、时段含义与展示数据继续留在 shared-logic。

### 二、两端终止语义的必要修改范围

将兑现 [Round 终止原则](08-pi-round-boundaries.md) 所需的 framework 公共合成及 OMP adapter 调整纳入后续实现范围，并回归受影响消费者。不是只在 pi 或 model-cost 里特判。

该范围限于本地活动最终结算后的取消/终态失败处理；正常工具、重试、排队及自动继续不提前结束。保留简化事件主干，不为罕见情况增加通用状态机，不修改宿主原生执行器，也不扩大为 OMP 生命周期重做。这是实现规划，不是本会话生产修改授权。

### 三、统一格式、兼容与跨 harness 汇总

- 统一 schema、读取、合并、保存由 shared-logic 拥有，不建立 pi/OMP 两套格式。相同 storageDir 共享文档，不同目录只是不同数据集。
- 本次不改变现有路径规则，包括 `~/` 在该字段中指向用户目录下 `.omp`；不按 harness 改解释、不自动迁移/复制数据或创建隐式存储根。人类明确配置目录；两端共享时可使用清晰绝对路径。
- 保留 harness 分区作为记录身份命名空间；完整身份包含 harness，父链与保存版本在对应作用域中判断。文件互斥不等于身份不会冲突。
- 读取整个文档；统计周期总用量、适用费用与 Accrued 可以跨 harness 汇总，不受当前 harness 过滤。读取和遍历细节封装在 shared-logic。
- 当前会话 Round、Session 和代理树只包含其真实归属和后代，不把另一端无关会话挂入；写入只更新有权保存的自身记录。
- 保留旧 runtimeMs，新活动继续累加；不重算历史、不清账、不重置周期。缺失仍未知，合法零仍为零。不因来自旧实现就一律标记不完整：估算精度改变不等于实际观测缺口。
- 为实际观测到的缺口增加可选持久化信息，沿用同一文档格式演进；旧记录缺少该信息时不推断曾发生缺口，也不凭缺少标记证明其历史观测完整。已知缺口的保留、恢复和周期规则仍以组织权威为准。
- 新版读取旧记录；OMP/pi 共享文档时共同更新 shared-logic。不要求未更新旧版与新版混跑。现有严格字段校验意味着旧读取器不自动兼容新增字段，不能宣称双向兼容。

这取代本票访谈中未获批准的“旧耗时一律按不完整历史小计处理”提案；并非修订前置权威。未授权清空数据或批量迁移用户存储。

### 四、验收门槛与证据等级

| 层 | 必须证明 |
| --- | --- |
| 公共事实与生命周期 | 实际身份、父链、Owner、State、输入、Turn、Round、改名、启动快照；正常继续、取消、终态失败及恢复符合既定权威 |
| 记账与共享存储 | 自身锚价/金额、一次请求只记一次、并发无丢账、跨 harness 汇总且身份隔离、旧记录兼容、重置归档、坏文件及耗时缺口 |
| provider 与展示数据 | 目录价/认证接线、DeepSeek 余额、Codex 额度及比例估计、上下文、峰谷重绘；缺失/失败不伪造零或成功 |
| 实际装配与功能 | pi 发现、子观察加载、主/子入口寿命、有/无子代理模式、全部 budget 动作、brief/detail/树；关闭重载无残留效果 |
| 人类界面 | 展示内容正确完整；格式、间距、窄宽度及观感由人类验收；RPC/无 UI 单独核对，不代替终端 |

- 可控计算、并发及异常边界使用确定性测试；原生事件、第三方接入和真实装配必须运行相应宿主路径，不能只用 mock。
- 两端共同路径变化包含 OMP 回归及受影响消费者，不以 pi 通过代替。主/子、前/后台、嵌套/并发、续跑、取消/失败、恢复、同/独立进程按适用路径组合覆盖，避免只验孤立原生事件。
- 固定 pi 1.2.0 / pi-subagents 0.78.0；OMP 按既有支持工件及补丁条件记录，不能用不同检出行号或版本替代认证。workflow/调度维持加分项范围，不扩大硬要求。
- 按仓库 testing.md 选择迭代、票完成及最终集成层级；测试补充实际 smoke/宿主观察，不代替它们。
- 未执行的真实 provider、终端或人工验收明确列未验收，不写通过；付费调用执行前另行授权，不复用研究旧限额。真实凭据与可用环境是执行前提，不由 mock 代替。

### 五、效率与复杂度对照

使用代表性事件序列进行实现前后对照，不预设任意百分比，也不建立庞大基准系统：

- OMP 同进程不新增 IPC 或逐事件读盘；记录读取、锁及发布次数。
- 多进程观察按文档合并提交、争锁以及重复根查询/重复计费，确认没有不必要重复工作。
- 正常空闲不新增固定轮询；故障重连仅在组织权威批准范围内。
- 保存对照证据，出现明显额外开销或复杂度上升由人类判断是否满足组织决定；绿色测试或架构图不能证明效率达标。

### 证据与实现限制

[完整基线](01-capability-baseline.md) 提供 F/O/N/M/P/G 行标识；[Round 事实核查](../research/08-round-boundary-facts.md) 提供现有终止差异；本票直接核对 consumption-document.ts 的 runtimeMs、身份、父链、saveVersion 和严格字段校验，以及 storage-root.ts 的路径规则。均为源码/文档事实，不是新方案运行通过。

本会话未更改生产代码、未启动宿主/模型/provider、未运行生产迁移或安装切换。文档和跟踪状态检查只证明规划资产可恢复。基础 IPC 探针及先前候选验证继续受各自权威的证据限制约束。

## Decision

按既有集中组织和 Round 决定补齐公共 pi adapter、保留宿主专属实现与共享业务，纳入必要两端终止对齐；统一数据格式、兼容旧耗时并跨 harness 汇总而隔离身份。采用分层真实验收、人类界面验收及代表性效率对照，完整迁移规划可交接实现，但不宣称迁移已完成。

## User stories

1. 作为迁移实现者，我需要每项功能的职责落点及必要修改范围，以便复用公共语义和业务而不是只完成子代理统计。
2. 作为两端共同使用者，我需要同一格式及跨 harness 总统计、隔离的会话身份，以便共享消费数据而不串账或失去历史。
3. 作为使用者，我需要相同展示内容和正确的未知/失败处理，以便切到 pi 后保持完整功能，外观则由人类确认。
4. 作为维护者，我需要真实宿主证据和效率对照，以便不把接口、mock 或测试通过冒充完整兼容与迁移成功。

## Preconditions

- 完整基线、选型、组织和 Round 权威继续成立；其实现仍需交付，已决定不代表已经可用。
- 共享文件的两端使用更新后的统一 shared-logic、解析到同一显式目录；没有未经批准的旧新版本混用承诺。
- 真实宿主、provider 凭据、人工验收及付费调用许可在相应执行时可用；缺失则对应项保持未验收。

## Postconditions

- 完整功能落点、数据兼容、两端必要修改及验收路线已决定，可以拆分 implementation tickets。
- 静态证据、测试、真实运行及人类验收分开记录；未验收项不能算完成。
- 本地图仍只规划，不授权生产修改、正式切换、清账、长期 fork、额外付费或未批准宿主补丁。

## Invariants

- 遵循 Extension 开发地图：公共语义在 framework，宿主事实在 adapter，model-cost 业务在 shared-logic，专属读取/绘制在 harness，装配和发现薄。
- 费用来自既有自身锚价与计费；未知、零、不适用、已知小计及完整性不互相替代。
- 身份、父链、Owner、查看目标与进程不同；跨 harness 总统计不合并身份或写权限。
- files 模块的协调/原子发布与业务合并规则分开；不以并发安全证明身份安全，不以粗估精度放宽 Round 计费边界。
