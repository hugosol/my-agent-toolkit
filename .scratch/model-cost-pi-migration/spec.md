# model-cost 在 pi 上的完整功能迁移

## Problem Statement

使用者目前可以在 OMP 中使用 model-cost 的请求计费、Round 与 Session 累计、子代理树、provider 余额与额度、消费归档及展示，但无法在 pi 中获得同等完整的功能。仓库已经具有一套宿主无关的扩展定义与 shared-logic，以及服务 codebase-tools 的局部 pi adapter；这不等于 model-cost 已可在 pi 运行。当前 pi adapter 仍拒绝 user-input、Turn、Round 与子代理耗时观察，model-cost 也尚无 pi 专属装配和发现入口。

仅安装第三方子代理扩展或展示其汇总 cost 无法解决迁移：实际会话身份、直接父链、Owner、State、请求归属、后台继续、保存边界和跨进程生命周期必须可靠衔接。否则使用者可能遭遇漏账、重复计费、提前关轮、跨会话串账、历史耗时丢失，或把未知用量和缺失余额误认为零。

维护者还需要同时保留 OMP 的既有功能，避免为 pi 复制计费业务或另建公共语义。共享消费文件时，两个 harness 应能共同累计而不混淆身份、写权限和当前会话的展示范围。

## Solution

在固定版本的 pi 与 nicobailon 子代理扩展上接入 model-cost，复用同一扩展定义、公共语义和 shared-logic，补齐公共 pi 事实映射、集中子代理接入、扩展专属绘制、薄装配及发现入口。用户在 pi 上获得现有完整功能；未启用子代理提供方时，主会话功能仍正常可用，真实接入失败则明确诊断。

所有费用继续由 model-cost 自身按请求锚价计算，按实际会话累计并沿直接父 Session 链汇总；Round 边界遵循原生活动、最终结算及已选提供方公开保活标准。OMP 与 pi 共同采用简化的子代理累计活动耗时估算，保留历史记录及真实观测缺口。两端使用同一消费文档格式，在显式选定同一存储根时汇总统计周期总量，同时隔离会话身份。

交付必须区分确定性测试、真实宿主运行、真实 provider 观察及人类终端验收，并提供代表性效率对照。本 spec 是已批准规划的实现需求汇编，不是迁移已实现、已认证或正式切换的声明。

## User Stories

1. 作为 pi 使用者，我希望直接加载 model-cost 的发现入口，以便无需复制 OMP 业务或手工拼装内部 adapter 就能使用统计功能。
2. 作为两个 harness 的使用者，我希望相同功能使用同一扩展定义与配置校验，以便宿主差异不会造成不同的业务规则。
3. 作为 pi 使用者，我希望未启用子代理提供方时仍能使用主会话计费、余额与额度功能，以便子代理不是基础功能的安装前提。
4. 作为 pi 使用者，我希望接入失败与正常无子代理模式明确区分，以便配置或协议错误不会被隐藏为功能正常。
5. 作为无子代理模式使用者，我希望调用 `/budget detail` 时收到提示并立即返回，以便不会改变展示偏好或执行后续 detail 操作。
6. 作为子代理模式使用者，我希望即使还没有创建子代理也能切换 detail，以便不必先产生子代理记录才能查看主会话详情。
7. 作为操作者，我希望 `/budget` 的帮助、参数拒绝和动作语义保持一致，以便已有操作习惯在 pi 中仍然适用。
8. 作为使用者，我希望每个真实模型请求恰好记账一次，以便根侧观察、子进程记账及文件同步不会重复收费。
9. 作为使用者，我希望费用固定使用请求真正开始时的模型、时段和价格，以便响应结束前的切模型、价格更新或跨峰谷不会重估该请求。
10. 作为使用者，我希望所有费用仍由 model-cost 自身计算，以便不会因第三方累计 cost 的范围或算法差异改变结果。
11. 作为使用者，我希望缺少 usage 或单价时保留未知与已知小计的区别，以便缺失事实不会被解释为免费请求。
12. 作为使用者，我希望计费渠道、额度渠道、参考费用与无统计口径保持区别，以便 Codex 的美元估计不会被加进实际消费金额。
13. 作为使用者，我希望 Turn、Round 和 Session 的统计范围清晰分开，以便一次工具返回不会被当成额外模型请求。
14. 作为主会话使用者，我希望子代理消费只沿直接父 Session 链汇总到 Session，而不分配给父 Round，以便子代理续跑和迟到结果不会改写父轮归属。
15. 作为子代理使用者，我希望自主委派、嵌套、并发、续跑和取消都保留可靠身份，以便不同任务及其消费不会串在一起。
16. 作为维护者，我希望身份、直接父、Owner、查看目标与 execution 不互相替代，以便名称相同、进程重用或继承历史不会伪造关系。
17. 作为使用者，我希望会话改名及时出现在统计中，以便代理树继续表达实际工作内容。
18. 作为使用者，我希望子会话启动模型和有效 thinking level 仅从可靠启动事实获得，以便后续模型变化不会覆盖启动快照。
19. 作为扩展使用者，我希望 `follow` 在实际使用时读取 Owner 当前 State，以便独立子进程不会一直使用启动时的旧值。
20. 作为扩展使用者，我希望暂时读取不到 Owner State 时使用声明默认值并自动恢复读取，以便短暂断连不迫使整个扩展停用或重启。
21. 作为扩展使用者，我希望 State 恢复后不重放已执行操作，以便一次请求或动作不会因为恢复通信再执行一次。
22. 作为维护者，我希望观察子会话不授予 Owner State 写权或主会话效果权限，以便扩大观察范围不会扩大权限。
23. 作为使用者，我希望工具、自动重试、压缩和已排队输入继续时保持同一 Round，以便低层运行结束不会提前切断统计和保存。
24. 作为后台委派使用者，我希望等待结果及结果唤醒接续原 Round，以便父会话不会在自动继续前过早结算。
25. 作为调度能力使用者，我希望未来独立任务的登记不占住当前 Round，以便当前活动可以正常结束。
26. 作为使用者，我希望取消和终态失败在本地原生活动最终结算后结束 Round，以便后台保活不会让已终止活动永久挂轮。
27. 作为使用者，我希望晚到结果只追加时不开新轮、真正开始执行时才开新轮，以便已结束轮不会被重新打开或重复记账。
28. 作为恢复会话的使用者，我希望缺失边界保持截断或未知，以便重载不会伪造历史正常结束或把离线时间算成持续活动。
29. 作为子代理使用者，我希望获得累计活动时长的大体估算，以便比较子代理投入，而不要求执行器级精确时间。
30. 作为子代理使用者，我希望多次活动与续跑的已知耗时在同一消费统计周期内累加并恢复，以便不会只看到最后一次运行。
31. 作为子代理使用者，我希望崩溃或缺失结束保留已知耗时小计及不完整状态，以便未知离线时间不会被补算或伪装为零。
32. 作为拥有旧数据的使用者，我希望旧 `runtimeMs` 保留并继续累计，以便新估算口径不会导致清账、历史重算或一律降级为不完整。
33. 作为主会话使用者，我希望 Session span 继续表达本周期首次输入至最近 Turn 结束的墙钟跨度，以便不会被子代理活动时长替代。
34. 作为 DeepSeek 使用者，我希望现有余额查询、缓存、认证更新及失败保留规则在 pi 中继续生效，以便迁移后仍能判断账户余额。
35. 作为 Codex 使用者，我希望两个额度窗口按报告长度识别并独立更新，以便后端字段位置变化或单窗口响应不会清空另一窗口。
36. 作为 Codex 使用者，我希望比例测量使用同一报告的配对读数并继续独立保存，以便旧新窗口读数不会被误配为比例样本。
37. 作为多 CLI 使用者，我希望同一文档的并发保存既不覆盖他人也不丢掉在途新增量，以便独立进程可以共同累计。
38. 作为使用者，我希望读取刷新不会强制提交尚未到保存边界的消费，以便查看 detail 不会改变记账时机。
39. 作为使用者，我希望坏文件或无效存储基线明确暂停消费记账及保存而不覆盖文件，以便原有数据不会被当作空账重建。
40. 作为使用者，我希望 `clear` 和首次 `holiday` 继续执行有条件的整文档归档与周期重置，以便两端共享统计不会出现半归档或跨周期串入。
41. 作为使用者，我希望忙碌、活动未知或自身保存未收口时直接拒绝重置，以便动作不会排队后在意外时刻清账。
42. 作为两个 harness 的使用者，我希望同一存储根下的统计周期总量、适用费用与 Accrued 跨 harness 汇总，以便看到整体消费。
43. 作为两个 harness 的使用者，我希望相同 session id 在不同 harness 中仍是不同身份，以便总量汇总不会导致父链、版本或写权限冲突。
44. 作为使用者，我希望当前会话及其代理树只显示真实后代，以便另一 harness 的无关会话不会被挂入当前树。
45. 作为配置维护者，我希望存储根继续使用现有显式配置和路径解释，以便切换 harness 不会偷偷改变数据位置或复制数据。
46. 作为配置维护者，我希望 framework 的运行目录显式配置且与业务存储分开，以便缺配置时不会写入隐藏的回退目录。
47. 作为使用者，我希望 brief/detail、预算条、费用结构及代理树在 pi 中保留相同业务内容，以便迁移不损失现有统计信息。
48. 作为使用者，我希望每个会话的 context 来自其公开实时读数，未知仍为未知，以便不会将累计 token 或 context window 冒充当前占用与显示预算。
49. 作为使用者，我希望峰谷边界自动重绘而不发请求或写文件，以便价格时段展示更新不会影响消费。
50. 作为操作者，我希望 pi 保持主会话展示、不随第三方 inspector 选择切换，同时 OMP 保留原查看路径，以便各 harness 使用自己的可靠展示事实。
51. 作为使用者，我希望入口重启恢复 brief、普通会话或模型变化保留入口偏好，以便展示设置不会被错误地持久化或继承到子入口。
52. 作为维护者，我希望同进程共享业务实例、独立子进程不重复根 UI 或余额预取，以便统一路径不会增加不必要效果和开销。
53. 作为维护者，我希望退出、重载及处置完整释放订阅、登记、通信与等待，以便失效接入不会继续观察或复活旧效果。
54. 作为维护者，我希望原生事件、第三方加载与完整装配有真实宿主证据，以便不会把 mock 或文档存在当作迁移通过。
55. 作为维护者，我希望共享路径变化包含 OMP 及受影响扩展回归，以便 pi 功能完成不会破坏已有消费者。
56. 作为维护者，我希望通过代表性事件序列比较锁、发布、请求及事件成本，以便确认统一实现没有明显效率退化或显著复杂度增加。
57. 作为人类验收者，我希望单独验收真实终端的内容、格式、窄宽度与观感，以便 RPC 输出正确不会替代可读性判断。
58. 作为后续升级维护者，我希望记录固定版本、工件、补丁条件和未验收项，以便仅针对变化的事实重新核验，而不误认为所有版本和平台均已支持。

## Implementation Decisions

以下均为现有 ADR、已批准 Lighthouse 与既有业务约定的汇编，不新增设计批准。涉及接缝的内容只记录已经确认的职责与内部注入方式；尚未决定的接口签名、接缝清单及契约覆盖留给 `/to-contract`。

### 1. 固定开发基点与事实来源

- 固定 pi 1.2.0 与 nicobailon `pi-subagents` 0.78.0。依照完整 OMP 子代理基线逐项核对，不能用 model-cost 当前消费子集缩减公共语义要求；批准的宿主适用范围与耗时替代口径除外。
- 保留自主委派、嵌套、并发、续跑及取消。workflow、定时调度是重要加分项，不升级为新增产品硬要求；适用路径仍需核对生命周期。
- 事实优先级为 pi 原生公开事实、第三方公开事实、复用或补充自身业务实现，最后才评估第三方修改。自身计算不能创造缺失身份、请求、父链或生命周期事实。
- 不自动批准私有 API、宿主补丁、第三方修改或长期 fork。完整 usage 不可靠、不能防止漏账/重复、公开机制不能兑现边界或必须依赖未批准机制时，带证据返回既有选型重评流程，不静默降级。

### 2. 已确认的职责归属

- 复用同一 extension definition 与 shared-logic。Framework core/behaviors 拥有身份、父链、Owner、State、观察分发及生命周期；各 adapter 负责原生事实映射。
- nicobailon 的识别、加载、登记、订阅、事实转换与释放集中在 framework 的 pi adapter 私有实现。Extension 不导入第三方私有接入，不另行识别安装状态或建立第二条观察派发路径。
- Framework modules 提供无宿主及业务语义的文件协调和本机通信；framework 不依赖 model-cost，也不把其 JSON 作为身份或 State 权威。
- model-cost shared-logic 继续拥有计费、消费记录、耗时估算、业务合并/保存及展示计算；各 harness 独立实现原生绘制、context 读取、峰谷等待载体及专属接线。装配和发现入口保持薄。
- 公共路径切换须迁移受影响消费者并移除被替代的生产路径，不保留两套宿主业务算法、兼容别名或旧接线 shim。

### 3. 子扩展接入与稳定模式

- 使用第三方公开的 `registerRequiredChildExtensions` 加载本扩展的子观察入口，由 framework adapter 集中接线；不自动向子会话加载所有主会话扩展。
- 装配对外提供只读的子代理模式/无子代理模式结果与明确失败诊断，隐藏第三方安装细节及初始化中间态。
- 未启用提供方属于正常无子代理模式，实际接入失败不是。模式在初始化完成时确定，不按已有子代理数量判断，不自动发现、安装、启用或热切换提供方。
- pi 无子代理模式下 `/budget detail` 提示后直接返回，不切偏好、不执行后续 detail；子代理模式即使没有记录也沿用成功动作。其他 budget 动作及 OMP 原路径不新增此分支。

### 4. 实际会话、观察与寿命

- 实际 Session、直接父、Owner、Viewed session、进程与 execution 保持区别，不按名称、深度、PID 或继承 transcript 猜身份。公共观察保留足够的来源与身份用于准入和去重，观察不授予额外写权或外部效果权限。
- 同进程直接调用并共享业务实例；独立进程使用相同业务实现，处理各自承接的实际会话。自身记账、根观察和已保存记录不作为三份消费累计。
- 配置、有效消费基线及计费输入就绪后再处理相关记账；并发准备共享一次结果。根侧余额/额度预取和 UI 与共同记账准备分离，子进程不冒充 Owner 启动根专用效果。
- Idle 或一次活动结束不销毁实际 session、历史与累计。事件订阅、第三方登记和通信句柄跟随所属接入的退出/重载/处置释放，不因子活动结束销毁共享根实例。不新增资源池、租约或引用计数系统。
- 保持既有实现工厂无副作用、Owner 初始化及首次请求等待、正常会话转移和至多一次 cleanup 等生命周期语义。重载/清理应按所验证路径记录，不因此宣称任意热重载兼容。

### 5. State 的权威读取与恢复

- 既有 StateStore 继续拥有权威值、写权与寿命。`follow` 在语义使用点取得 Owner 当前值，同一次处理共用快照；同进程直读，独立进程的通信与有限等待由 framework 集中承担。
- 暂时无法获取时使用字段声明默认值，不使整个 extension 不可用，不反写 Owner，不宣称读取成功，不使用持久化旧值或未经确认的缓存恢复 `memory` State。
- `inheritance: none` 正常使用默认值；权威值 false 是有效读数，不是失败。
- 同目标并发获取合并，失败有间隔、退避有上限，当前进程自动恢复，健康时不持续轮询；恢复不重放兜底后已经执行的操作。
- 身份不匹配、Owner 可靠结束等明确失效不靠重连绕过，断连本身不证明 Owner 结束；接入处置后停止恢复且不复活旧句柄。

### 6. 本机通信与运行目录

- 跨进程运行中观察使用单向事件推送，State 使用按需请求/应答，二者复用 framework 管理的本机接入；不是任意 RPC，不传模型文本，不开放远端 State 写入。
- 使用 Windows 命名管道或 POSIX 本地 socket 类本机流；extension 不自行维护服务器或协议，不使用消费文件、请求应答文件队列或目录扫描传运行中消息。
- 接入定位信息与消息、State、业务数据分开，包含必要 Owner、端点和本次接入校验；核对目标与寿命，不能仅凭 PID、旧地址或关闭连接判断身份/生死。凭据不进入模型或日志。
- Framework 运行目录由共享配置显式提供，可使用已批准名称 `runtimeDir`。相对值基于配置文件位置解析；参与同一接入的进程须解析一致。缺失、空或非法时明确报错，不能使用代码默认临时目录或 cwd 回退。
- 运行目录与 model-cost 存储根分开。Windows 管道名不构成第二个磁盘目录；文件型定位信息及 POSIX socket 受显式目录约束。配置变化在正常新进程生效，不热迁移，也不改变既有 HTTP 默认预算等无关配置。

### 7. 输入、请求、计费与快照

- pi adapter 补齐公共输入、Turn 起止与原始 usage、改名、可靠启动模型及有效 thinking level，以及已有模型目录价格、provider access 出口；model-cost 不自建原生请求监听。
- 请求开始时固定 provider、精确模型、开始时刻、消费统计周期、holiday 及适用价格/币种/单位，响应边界执行现有自身计费、去重和累计，不采用 adapter 或第三方最终 cost。
- 保持计费渠道、额度渠道、参考费用、无统计口径、未知、确认零及已知小计的区别。缺 usage/价格沿用提示并跳过相应指标的现有业务取舍，不扩展缺失计数账本或离线补算系统。
- 请求去重标记按实际 session 与 Turn 保持在观察实例内存直到销毁，不在 Round 结束清空、不落盘。父 Session 含后代合计是聚合视图，不是额外消费；子消费不归入父 Round。
- 启动快照只写可靠的新会话启动事实，未知不借当前值，恢复、fork 继承历史及续跑不伪造新启动；后续切模型或改 thinking level 不覆盖原快照，沿用既有消费提交保存。

### 8. Round 原生主干与已批准内部注入

- 按每个实际 session 独立映射。pi `agent_start` 提供活动开始事实，`agent_settled` 提供结束候选；轮内再次开始是继续，不把每个低层 `agent_end` 当关轮。
- Framework 在候选后的下一 task 重读：pi idle、无排队消息、提供方无后台活动/待发唤醒，满足才正常结束。工具、自动重试、压缩、排队输入和已知后台继续不提前切轮。
- 沿用 nicobailon 版本化公开保活协议，不复制结果队列、逐通知阶段或通用待续义务状态机。未来 schedules、终态历史和 wait subscription 本身不保持当前轮活动。
- 接受提供方既有唤醒超时标准，包括其 10 秒期限行为；这是后台事实的正常变化，不是新增本地超时关轮机制，仍需结束候选和本地静止检查。
- 公开保活查询的未注册、身份不匹配、失败或不可得不等于 false。无子代理模式只按本入口接入范围的 pi 原生事实判断，不宣称宿主全局无子代理。
- 已批准的内部接缝事实：pi adapter 薄装配向 Round 原生映射注入小型会话后台活动查询；第三方协议转换留在 adapter 私有接入。Round 映射不直接依赖第三方载荷，framework behaviors 仍拥有公共合成和分发。具体命名及后续契约设计不在本 spec 决定。

### 9. 取消、终态失败及两端必要对齐

- 显式取消与终态失败在本次本地活动原生最终结算后结束 Round，不等待后台保活清空，也不在按停止键时提前结束。仍会重试的错误不是终态，结算前候选结局也不能单独触发结束。
- 旧结局不得误用于后来的新活动；已结束轮不重开。晚到结果只追加不开轮，实际触发执行才开新轮。
- Adapter 不额外停止子代理、清队列或主动唤醒；交由宿主/提供方。第三方 UI 取消暂停唤醒的保证有 `hasUI` 条件，不泛化为所有 RPC/headless 路径。
- 恢复/重载及缺失边界遵循截断/未知原则，不补造旧轮正常结束或离线连续活动。
- 将兑现上述终止原则所必需的 framework 公共合成与 OMP adapter 调整纳入实现及回归，不能只在 pi 或 model-cost 特判。范围限已最终结算的取消/终态失败，不重做 OMP 执行器，不另建复杂通用状态机。

### 10. 子代理耗时与 Session span

- OMP/pi 统一自行累计粗粒度活动耗时，优先使用既有 Working/Round 活动事实；不单独新增 execution 起止轴，不使用第三方或 OMP 已算好的最终 duration，不为精确时间要求修改第三方。
- 包括模型、工具和活动中的委派结果等待，排除真实 Idle 与不同活动间空闲；不承诺精确覆盖排队、创建会话和扩展加载。不放宽 Round 计费边界。
- 活动结束结算，不要求持续刷新运行中读数；续跑累加，同消费统计周期持久化恢复。仅耗时增长也必须能保存，不能被仅费用增长条件漏掉。
- 已观察的取消/失败活动保留已知估算；缺失结束不补离线时段。可靠小计及本周期观测不完整状态保留，后续成功不抹掉旧缺口，周期重置开始新累计。没有已知测量为未知，可靠零仍为零。
- 耗时业务封装累计、去重、周期、恢复与完整性，不新增统管余额、额度、耗时与消费基线的通用 LastGoodValue 框架。
- 主会话 Session span 仍是本周期首次用户输入至最近观察 Turn 结束的墙钟跨度，包含空闲间隔但不累计子代理耗时；fork 与周期重置遵循既有新输入边界。

### 11. 内存、只读同步与合并提交

- 先更新内存和只读展示，业务提交事件使相应变更获准提交，再按文档协调发布。读取刷新和写提交是不同操作，仍由实际会话的正确 `round_end` 兑现消费提交。
- 同进程合并同文件已获准提交的变更，不顺带保存其他 session 未到边界的数据；锁内读取磁盘现值并由业务合并，复用 framework 既有互斥与原子发布，不整份覆盖内存快照、不另造锁。
- 在途确认仅清除实际提交部分，期间新变化继续保留。周期一致且文档可用时，各记录分别返回有效/拒绝结果，有效项可共同发布；文档或发布失败不能声称任何项已落盘。不自动重试拒绝项。
- 业务继续拥有 schema、周期、版本、合并、归档和保存失败语义。消费文档与 Codex 估计文档不强制相同提交时机或失败策略。
- 只读同步与保存后文档采纳共用对齐规则：同周期保护本地未提交累计，周期变化按既有重置处理，确实变化才通知展示。不把具有初始化含义的 load 当日常刷新。
- 读取外部已提交数据由已有合适事件触发，无事件可暂显上次结果，不增加固定轮询；绘制不读文件。第三方完成/进程通知只是刷新提示，不证明消费已经提交。
- 运行中基线不可读、损坏或不合 schema 时报告并暂停本实例消费记账/保存，不当空文档、不覆盖、不反复修复；最后可靠展示须标明暂停，独立 provider 功能继续。下次正常初始化再建立基线，不套用 State 自动恢复规则。

### 12. 周期重置与归档

- `clear` 与首次 `holiday` 保留 DeepSeek 当前入口限制：可靠 idle 且自身没有待完成保存才能执行；活动未知、忙碌或保存未收口直接拒绝，不排队、不延期到 round_end。
- 重置归档磁盘已保存的完整活动文档，涵盖全部 harness/provider/session，先归档后发布新周期，失败终止；不强制提交其他在途数据，旧周期未保存数据不能带入新周期。
- 普通 clear 开启 holiday=false 的新周期，首次 holiday 直接开启 holiday=true 的新周期；已 holiday 幂等提示，不再重置。有效零数据也适用。
- 边界余额使用本次独立读取，同一结果用于旧周期结束与新周期开端；失败不补缓存或零。不清 Codex 独立估计、不修改旧归档，不从归档读回记账。

### 13. 共同格式、兼容及身份隔离

- 两端使用同一 schema、读取、合并和保存业务；同 storageDir 是同数据集，不同目录是不同数据集。保存 Session 自身聚合和直接父关系，不新增 Round/Turn 明细账、最近轮持久化快照或历史轮查询。
- harness 分区是身份命名空间，完整身份包含 harness，父链与保存版本在相应范围判断。跨 harness 汇总统计周期总用量、适用费用和 Accrued；当前 Round、Session 与代理树只包含真实归属及后代，写入只更新有权保存的自身记录。
- 保留历史 `runtimeMs` 并继续累加，不清账、不重算、不重置周期；估算精度变化不代表历史存在观测缺口，不能将旧值一律标为不完整。
- 为真实已知缺口增加可选持久化信息。旧记录缺少标记时既不推断曾有缺口，也不凭其缺失证明历史完整；新字段不得使旧记录变坏文件。
- 新版读旧记录；共享文档的 OMP/pi 共同更新 shared-logic，不承诺未更新旧读取器可读新增字段，不支持旧新版混跑作为本次兼容条件。此为本次迁移的已批准特定兼容范围，不套用历史通用双向兼容承诺。
- 不改变 storageDir 路径解释，尤其该字段 `~/` 仍指用户目录下的 `.omp`；相对路径规则保持现状。目录显式配置，不自动迁移、复制、合并或创建隐式存储根。

### 14. provider 业务与接入

- pi adapter 提供当前 provider、本次可用认证及已解析 base URL，隐藏宿主凭据存储与 OAuth 更新。每次操作读取并固定当次资料，不持久化秘密或账号统计身份。
- DeepSeek endpoint、余额协议、Codex 窗口解析、比例估计、查询时机、缓存/刷新及失败保留全部留在 shared-logic，复用已有 provider-refresh 等真正共通策略。
- 保留 provider 单账号范围，不建立账号列表、选择/轮换、凭据指纹分区或自动换账号重置。真正换账号时由用户自行选择新数据范围。
- 保留余额初始化及成功 TTL 规则、按对应 provider 已结算请求触发的刷新、失败保留和更新认证；不新增固定轮询。Codex 窗口按长度识别、独立保留读数，比例只用单报告配对数据，估计文档保持独立，不随消费重置清空。

### 15. 展示、上下文与峰谷等待

- brief/detail、代理树、未知/不完整提示、显示预算、费用结构、余额/额度及 Accrued 使用相同只读业务内容；绘制主题、布局和宽度由各 harness 独立实现，不要求像素一致。
- 代理树为静态自身累计列表，沿直接父链缩进、各深度独立对齐；会话最新名优先，随后沿用既有 task 名、已保存名、agent 类别与 id 回退。启动快照不借当前值，树中不新增父 Round 子消费或缓存份额。
- context 由对应 harness 读取各实际会话公开 `getContextUsage()` 并归一，tokens 为 null 表示未知；不落消费文件、不从累计推导。比较既有固定显示预算，不将宿主 context window 作为预算，也不改变请求/压缩限制。
- 入口展示偏好仅进程内存，普通会话/模型/查看变化保留，重启或重载恢复 brief，不作为 State、不持久化或传给子入口；子会话自身显示保留固定 brief 的既有规则。
- OMP 保留可靠 Viewed 路径；pi 不复制 OMP hub，不随 inspector 改显示目标，保留主会话下子统计与树。若出现真正实际会话切换且复用显示区域，按既定生命周期处理并针对新事实评估，不能用 Owner、来源或名称冒充查看目标。
- 一个 UI 实例只持有一个峰谷边界单次等待，子会话不另建、无 UI 不持有，释放 UI 时取消；OMP 使用宿主管理 timer，pi 自持并清理。定价、时段与重绘含义复用业务，每次触发后从实际时钟重算，不重放错过的边界。绘制及边界重绘不请求网络、不写盘、不变记账。
- component/lines 只决定绘制形态，使用相同业务结果；headless/RPC 不代替真实终端验收。

## Testing Decisions

这里记录既有测试先例、已批准验证层级与执行限制；不选择新接缝、不建立承诺编号或承诺到测试的覆盖矩阵。这些由 `/to-contract` 决定。

### 既有先例与复用约束

- [仓库测试约定](../../docs/agents/testing.md)规定迭代用受影响文件，票完成用所属分区及共享契约消费者，最终集成运行 `bun run typecheck` 与 `bun run test`；TypeScript 改动需 typecheck。共享工作树的昂贵及真实宿主运行顺序执行，运行期间保持源码与 fixture 不变，日志可归属到具体版本与环境。
- [model-cost 测试分区](../../tests/model-cost/)已有请求锚价/计费、Round 统计、存储周期、子代理耗时、余额、额度、上下文和展示测试；[framework 测试分区](../../tests/framework/)已有身份/观察范围、Owner/State、生命周期、Round 与文件协调先例。优先复用消费者可见行为，不将被替代的旧原生 duration 或内部布局断言重新钉死。
- [独立进程存储先例](../../tests/model-cost/storage-processes.test.ts)运行真实子进程、隔离配置与目录，验证共同文件和拒绝写入；多进程协调不能只用内存锁 stand-in 证明。
- [真实宿主 dock](../../tests/harness-dock/)已有隔离精确安装、显式扩展集、RPC、捕获请求、会话 JSONL、stderr 与存储读回。现有 OMP accounting、Round、恢复、子代理树、余额与额度路径是适用先例，不宣称这些设施已经支持 pi 或证明 nicobailon 集成成功。
- 现有模型数据与 HTTP smoke、布局/终端 smoke 可以作为相应既有计算或绘制的验证工具；执行何者及增补何种契约覆盖由后续阶段按实际变更决定，不机械重跑无关套件。

### 已批准的验证范围

1. **公共事实与生命周期**：实际身份、直接父链、Owner、State、输入、Turn、Round、改名、启动快照、正常继续、取消/终态失败及恢复。尤其核对原生事实经过 framework 后的 model-cost 归属和提交触发，不能只打印原生事件。
2. **记账与共享存储**：自身请求锚价、usage/金额去重、同/跨进程并发、在途提交保护、逐记录冲突、只读刷新、跨 harness 汇总与身份隔离、旧记录继续累计、真实耗时缺口、整文档归档/重置及坏文件暂停。
3. **provider 与展示数据**：模型目录价与认证接线、DeepSeek 余额、Codex 双窗口及比例、context 与峰谷重绘；缺失、失败、未知、零及无统计口径不可互换。
4. **真实装配与寿命**：pi 入口实际被发现，必需子扩展实际加载，根/子准备及效果不重复，两种接入模式、全部 budget 动作、关闭/重载/释放无残留。需要验证的组合包括主/子、前/后台、嵌套/并发、续跑、取消/失败、恢复及同/独立进程，按适用路径覆盖，不将加分项扩为新硬要求。
5. **Round 常见路径**：普通请求仅一次开闭；工具/重试/压缩/排队继续同轮；后台结果通知与唤醒不提前结算；未来任务登记不挂轮；取消/终态失败最终结算后结束；晚到仅追加不开轮、真实执行开新轮；协议不可用不冒充无后台活动；恢复不伪造完整历史。
6. **两端回归**：公共子代理/State/终止语义改变包括 OMP 与受影响消费者，不能用 pi 通过替代 OMP 回归。OMP 记录既有冻结工件及 Viewed/Codex response 补丁条件，不能混用未经认证的版本或引用行号。
7. **人类界面**：真实终端验收展示内容、格式、间距、宽度降级及观感；RPC/无 UI 单独核对，不替代 TUI。精确外观由人类实际验收，本 spec 不新增像素要求。
8. **效率与复杂度**：用代表性事件序列做实现前后对照，记录读取、锁、发布、请求/事件成本、重复根查询和计费去重。OMP 同进程不新增 IPC 或逐事件读盘，独立进程避免无效重复效果，健康空闲不新增固定轮询。不预设百分比、不新建庞大基准系统；明显额外开销或显著复杂度增加由人类判断。

确定性计算、并发及错误边界可用可控数据；原生事件、第三方接入和真实装配必须实际运行对应宿主，不能全由 mock 替代。记录固定源、依赖、环境、命令、结果与未覆盖项；既有候选实测和 Windows 基础 IPC 探针不能充当本实现端到端证据，也不能推断 POSIX 或跨用户权限已经验证。

真实 provider 凭据、人工终端和可用宿主是执行前提；付费调用须另行授权，不继承研究旧限额。未执行或环境不可得的验收明确保持未验收，不能写通过；完成测试不等于独立兼容性认证。正常启动不新增版本清单、能力形状或验证报告门控。

## Out of Scope

- 本次 spec 发布不执行生产代码修改、宿主正式安装、全局配置修改、迁移切换、清账或用户数据批量迁移。Spec 描述后续实现目标，不扩大地图会话的执行授权。
- 新的子代理提供方选型、任意提供方注册系统、自动安装/发现/热切换、长期 fork、未经批准的宿主或第三方补丁。
- 精确执行器端到端计时、专用 execution 时间轴、持续运行时计时刷新、统一 LastGoodValue 框架、通用后台待续状态机、自定义静默窗口或超时关轮。
- pi inspector 查看联动或复制 OMP hub；无可靠事实时猜父链、Owner、Viewed session、usage、价格或空闲。
- workflow/定时调度的新产品硬要求、任意外部后台来源的通用兼容，以及由本轮研究自动推定的未来版本/平台支持。
- Round/Turn 明细账、历史轮查询、持久化最近 Round、父 Round 子消费分摊、离线补账、历史费用或耗时重算。
- 多账号选择/轮换/统计分区、凭据持久化、自动识别换账号和自动重置消费。
- OMP/pi 原生会话文件互通或会话历史迁移；共享消费文档不代表两端可以恢复彼此原生会话。
- 旧版读取器与新增字段的双向兼容、未更新旧版与新版共享文件混跑承诺、旧生产路径兼容 shim。
- 为统一而复制 shared-logic、重建公共语义、重做 OMP 执行器或修改无关 HTTP 默认值及配置规则。
