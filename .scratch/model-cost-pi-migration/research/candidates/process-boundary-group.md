## 1. `@zhushanwen/pi-subagent-workflow` — npm-only, no public repo

- **Execution model: child-pi-process, two hops.**
  - Hop 1 (host pi → engine CLI): `@zhushanwen/subagent-core` `EngineClient` spawns the engine CLI entry —
    `this.child = spawn(launch.command, launch.args, { cwd, env, ...platformOpts, stdio: ["pipe","pipe","pipe"] })`
    **[P]** `subagent-core@1.5.1 dist/chunk-4RPMGJDN.js:1443` (source `src/execution/engine/client/engine-client.ts`,
    chunk marker at `:1261`); command resolved by `resolveEngineNodeLaunch` (`subagent-engine-sdk@0.10.1 dist/node-executor.d.ts:53`,
    docs `:39-52`) from the discovered engine bin (`subagent-core dist/index.js:565-599` `enginePkgName`/`expectedVendoredBinPath`/`locateVendoredEnginePkg`).
    stdout is the engine protocol stream (`onStdoutData`, `chunk-4RPMGJDN.js:1461`). The workflow package itself
    has **no** `child_process` import in `src/` (grep clean) — hop 1 lives in core/SDK.
  - Hop 2 (engine CLI → real pi): `spawnEngineChild` (`subagent-engine-sdk dist/chunk-HSNDUHFH.js:14-28`, source `src/spawn.ts`),
    args built by `buildPiSubagentSpawnArgs` **[P]** `pi-subagent-cli@0.7.2 dist/chunk-K3KTNCBH.js:30-31`
    → `["--mode","rpc","--session-dir",<dir>]` + optional `--session <file>` + `--model <provider>/<id>[:<thinking>]`,
    then `--tools`, `--append-system-prompt`, plus `--no-extensions` and per-extension `--extension` (`:419-432`);
    verified `pi` invocation selection at `:265-283`; run call site `PiEngine.run` `:1758-1767`.
- **What comes back / how the parent learns session id, model, usage, duration, status.**
  - Session id **and** session file: engine issues pi's own RPC `get_state` and reads the reply —
    `sendGetStateCommand` `:203-207`, `extractGetStateFields` (`sessionFile`, `sessionId`) `:538-548`,
    `performGetStateHandshake` `:549-575`; fallback session-file derivation `deriveSessionFilePath`/`findSessionFileByHeaderId` `:726-738`.
  - Terminal outcome: `AgentOutcome` carries `content, usage{input,output,cacheRead,cacheWrite,cost,contextTokens,turns}, durationMs, error, sessionId, sessionFile, worktreePath, toolCalls, engineId, exitCode`
    (`subagent-engine-sdk dist/contract-types-jSa1g28F.d.ts:336-355`; usage type `:307-315`).
  - Live control: `set_model` hot-switch with `get_state` readback and structured error typing (`chunk-K3KTNCBH.js:1788-1800`); per-turn usage deltas live in the journal reducer (`contract-types…d.ts:43-52`, `journal-replay.d.ts:34-45`); history read is journal replay, `PiEngine.read` `:1773-1777`.
- **Public surface.** Model tools (7) and commands (3): `subagent_start`, `subagent_manage`, `subagent_message`, `subagents`, `workflow_run`, `workflow_control` + workflow-script tool; commands `subagents`, `workflows`, `subagent-model`; messageRenderer `subagent-bg-notify` (all listed in `src/index.ts:5-7`, registrations `src/interface/tool/subagent-tool.ts:187,229,251`, `src/interface/tool/tool-subagents.ts:262`, `src/interface/tool/tool-workflow.ts:244,307`, `src/interface/command/{commands,subagents,subagent-model}.ts:87,209,247`).
  Its own package barrel exposes **only the factory** (`index.ts` = `export { default } from "./src/index.ts";`) → no
  consumable API from the extension package. The consumable protocols sit in sibling public packages:
  `@zhushanwen/subagent-core`, `@zhushanwen/subagent-engine-sdk` (engine port + protocol types), `@zhushanwen/extension-protocol` (`SUBAGENT_BG_NOTIFY_CUSTOM_TYPE`, `src/index.ts:45`). Config file: `subagents/config.json` (`pi.startupConfig` in the published manifest).
- **Coverage.** S-IDENT **covered** (sessionId+sessionFile via `get_state`; identity = engine taskId/recordId, name); S-STARTUP **covered** (provider/model/thinking in argv before spawn, `chunk-K3KTNCBH.js:31-39`; resume distinguishable via `--session <file>`, `chunk-K3KTNCBH.js:1550`); S-OWNER **adaptable** (workflow-window → engine port resolution `subagent-core dist/index.js:723-728`; run keyed by recordId [INFERENCE: no exported owner field]); S-SCOPE **adaptable** (engine registry is per-host process; no cross-process observer API in the extension); S-LIFECYCLE **covered** (run statuses + journal/lifecycle predicates `subagent-core dist/chunk-4RPMGJDN.js:1226`); R-ROUND **covered** (per-turn `usageDelta` in journal turns); T-TURN **adaptable** (usage + model + cost per turn; **no** http status, **no** responseId, **no** catalog price → needs-upstream-interface for those three); R-RUNTIME **covered** (`durationMs` in `AgentOutcome`, live status via engine events); IN-INPUT **covered** (`subagent_message` tool + `set_model`); V-VIEWED **covered** (`subagents` tool/command, journal replay `read()`, resume via `--session`).
- **Evidence limits.** No git revision exists → all citations are to published npm artifacts (extension 9.5.1 and its pinned deps). dist chunk filenames/hashes are per-publish, not per-commit. Nothing was executed.

## 2. `@bacnh85/pi-subagent` (bacnh85/pi-extensions) — in-process SDK sessions

- **Execution model: in-process.** `createAgentSession({ cwd, model, thinkingLevel, resourceLoader, tools, sessionManager: SessionManager.inMemory(childCwd), settingsManager, … })` **[H]** `pi-subagent/extensions/runner.ts:256-261`;
  subscribe `session.subscribe(...)` `:273`; prompt `await Promise.race([session.prompt(task), eventDone])` `:304`; teardown `session.dispose()` `:338`.
  No child `pi`; the only `child_process` use is git worktree housekeeping (`runner.ts:357-365`).
- **What comes back.** `SubAgentResult` `runner.ts:116-136`: `agent, task, exitCode, messages[], stderr, usage, model, stopReason, errorMessage, patch, mergeStatus, mergeError, status, durationMs`;
  `UsageStats {input,output,cacheRead,cacheWrite,cost,contextTokens,turns}` `:44-52`; model composed as `provider/model` from the child message `:285`; live progress snapshots `{label, at, elapsedMs, inactivityDeadline, hardDeadline, result}` `:107-114`.
- **Session facts.** In-memory manager → **no session file**; the SDK object *does* expose the id (`AgentSession.sessionId` → `SessionManager.getSessionId()`, pi `src/core/agent-session.ts:1657-1659`; `inMemory` = `persist:false`, `sessionDir ""`, pi `src/core/session-manager.ts:1804-1806`, recommended for hosts that avoid session files `docs/sdk.md:42-47`) but **the extension never reads it** (grep `sessionId` in `pi-subagent/extensions/` → only `ctx.sessionManager.getEntries()` for auto-review, `auto-review.ts:242`). A consumer therefore gets no child session id, no sub-session marker, no owner field, and nothing on disk to read. Thread inspection is in-process only (`thread-viewer.ts:165-169`).
- **Public surface.** Tools `subagent` (`index.ts:663-664`) and `herdr` (`:1974-1975`); commands `subagent` (`:404`) and `agent` (`:2173`); **cross-extension EventBus channel** `pi-subagent:run` (`service.ts:16`) consumed at `index.ts:309`, with typed request/response `SubagentRunRequest`/`SubagentRunResponse` including a `respond` callback and `onProgress` (`service.ts:18-40`). No npm `main`/`exports` → no importable module API.
- **Coverage.** S-IDENT **unsupported** (no session id/sub-session/agentId beyond the role name); S-STARTUP **adaptable** (`model`/`thinkingLevel` are construction inputs, never surfaced as a start record); S-OWNER **unsupported**; S-SCOPE **adaptable** (in-process event only, no observer); S-LIFECYCLE **adaptable** (terminal classification + exitCode; start/end not published to consumers); R-ROUND **unsupported** (no round identity; only a `turns` counter); T-TURN **adaptable** (per-assistant-message usage + model; no http status/responseId/catalog price); R-RUNTIME **adaptable** (`durationMs` `runner.ts:134-135`; live `elapsedMs`); IN-INPUT **unsupported** (only `session.abort()` `:301`; no steering); V-VIEWED **adaptable** (in-memory transcript + ThreadViewer; lost at exit, no resume across restarts).
- **Risks.** In-process sharing of the host's auth/model runtime via casts `(modelRegistry as any).runtime/.authStorage` (`service.ts:68-69`, `runner.ts:261`) → SDK-version coupling; a child extension can crash the host; no audit trail.

## Gaps that would need new/upstream pi interfaces (for the baseline dimensions)

1. **Child session identity for eliminated sessions.** Both `--no-session` users (ptc foreground, d3ara1n, HenryQW ephemeral) have no session id at all, and ptc states that a session-file path chosen by the child is unlearnable (`dispatch.ts:2030`; ADR-0022:151). pi already offers `--session-id` (`cli.md:92`) so this is *adaptable*, not blocked — but there is no public API for a parent to learn a child's auto-chosen id/file from a one-shot run except parsing the first JSON header record (`json.md:27-33`) or `get_state` (`rpc-commands.md:155-177`), neither of which these candidates do.
2. **Per-turn `httpStatus` / `responseId` and catalog price.** No candidate carries these; pi's JSON/RPC event tables document `usage` (incl. `cost`) but not an HTTP status or a response id (`json.md:60-75`) → **needs-upstream-interface** for T-TURN to reach parity with the OMP baseline.
3. **Round-level (R-ROUND) identity.** pi's events give `turn_start`/`turn_end` (`json.md:44-49`) plus `agent_start`/`agent_end`/`agent_settled`, but none of the five emits a distinct round record with identity+open/close to consumers; zhushanwen's journal `turns[]` is the closest (`contract-types…d.ts:43-52`).
4. **Cross-process observation scope (S-SCOPE) and lifecycle reasons (S-LIFECYCLE) for a session the consumer did not start.** Every candidate's registry/history is per host process and per owning session (ptc ADR-0023; d3ara1n history by parent id, `history.ts:46`); a framework needing "observe ALL sessions" would need a pi-side session registry interface, not a candidate workaround.
5. **Sandbox-free trust displacement.** *Not a baseline dimension* but relevant to migration cost: all five execute model-influenced code with the user's identity; ptc documents this explicitly (ADR-0007) and gates `tools.bash` behind opt-in.
