# 02: 双声明静态集成检查

**What to build:** 维护者通过现有静态集成检查命令，能分别分析同业务目录下两个独立角色声明，准确定位能力不足，同时继续检查原有单声明。通过 S3 交付。

**Delivers:** P4

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

依据：[获批契约](../contract.md)及其继承的 spec。仅交付 toolkit，不修改后端、不新增自主重试或第二套状态机。

## Acceptance criteria

- [ ] 独立合法双声明样例通过实际命令检查，不合并 ID、不跳过第二声明。
- [ ] 分别构造只有一个角色缺少所需能力的样例，错误归属正确，不沿用另一个角色的分析结果。
- [ ] 原单声明的合法与缺失能力样例保持正确诊断及可辨识退出结果。
- [ ] 通过真实命令而非仅私有分析 helper 验证；记录命令、诊断和退出状态，覆盖所属测试分区并在 TypeScript 改动后运行 typecheck。
- [ ] 更新受影响的命令使用说明；明确静态结果不等于运行兼容认证。

本票可使用独立声明样例，不等待角色实现。12 负责最终真实角色声明的集成命令检查。
