# 11: 长期部署与故障处置说明

**What to build:** 维护者不依赖临时 spec 或讨论材料，也能按长期说明安装两个角色、配置预算、理解协议并处理常见故障。Agent 按说明实际配置和演练，而不是仅写文档。通过 S1 与获批文档审查交付。

**Delivers:** P29（技术部分）

**Test owner for:** P29 的技术 coverage；H1 汇总归 12。

**Blocked by:** 08：不确定动作与错误结果保真；09：首次启用指引与输入职责

**Status:** ready-for-agent

依据：[获批契约](../contract.md)及其继承的 spec。仅交付 toolkit，不修改后端、不新增自主重试或第二套状态机。

## Acceptance criteria

- [ ] 长期说明覆盖安装与独立自动装配、稳定配置、实际协议与角色责任、普通／collect 预算、错误和取消语义；公共能力变更同步其权威说明。
- [ ] 明确 sessionId 不是秘密认证凭据、同机信任边界，以及真实与受控验证的范围和环境限制，不夸大安全或宿主支持结论。
- [ ] 审查完整性与链接，临时 spec／讨论记录不是部署、协议理解或维护的必要依赖；不建立第二套冲突协议真相。
- [ ] Agent 在隔离环境按说明实际配置，并演练 recover 与 retry 区别、人工真实交接、报告保存但通知失败；记录步骤、结果和适用环境。
- [ ] 对演练暴露的问题修正文档或实现并复验；纯文档执行链接／示例检查，行为修改执行所属分区和相应 smoke，TypeScript 改动运行 typecheck。
- [ ] 准备供 12 汇总的长期说明与演练证据；不把文档修正、技术核对或复验交给用户。
