# 07: 真实等待取消与终止原因

**What to build:** 实际 omp 的工具中断或 Session 结束能取消在途 collect，释放真实连接和后端等待；管理者能区分正常到期、主动取消、客户端超时与传输／解析失败。通过 S1、S2 交付。

**Delivers:** P19、P21

**Blocked by:** 01：公共 HTTP 全请求取消与兼容；06：collect 长等待与报告待办

**Status:** ready-for-agent

依据：[获批契约](../contract.md)及其继承的 spec。仅交付 toolkit，不修改后端、不新增自主重试或第二套状态机。

## Acceptance criteria

- [ ] 将工具取消与对应 Session 生命周期接入公共 HTTP 取消，覆盖真实 omp 工具中断与 Session 结束两条路径，均包含响应头已到但正文未完成的场景。
- [ ] 观察实际连接结束和后端等待释放，后续报告仍可由新 collect 收取；本地提前返回或受控 HTTP 断线不能单独充当真实宿主证据。
- [ ] 独立控制正常后端到期、调用方取消、客户端预算耗尽、传输失败及 JSON 解析失败，终止原因可辨识。
- [ ] HTTP 200 响应头后断流、非法 JSON、不完整正文不得变为成功快照或正常 timeout。
- [ ] 终止竞争时如实呈现实际采用原因，不新增全局优先级或伪造快照；取消技术实现与验证均由 Agent 完成，不留给 H1。
- [ ] 保留真实环境、命令、连接／等待观察证据；执行所属分区、对应真实宿主 dock 及 TypeScript typecheck，更新取消与限制说明。

本票独占 P19、P21 完整测试。01 拥有公共传输各阶段资源清理与消费者兼容；08 拥有错误／取消后的有界请求次数与后续显式调用检查；10 拥有两个 Session 之间的并发取消隔离检查。
