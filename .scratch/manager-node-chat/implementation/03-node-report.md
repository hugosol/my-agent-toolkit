# 03: 节点自动报告与结果区分

**What to build:** 实际 omp 自动加载 node-chat，节点执行者只填写正文即可向后端提交报告，看到保存、辅助通知与诊断各自的真实结果；报告成功不意味着交接完成。通过 S1 交付。

**Delivers:** P15、P16

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

依据：[获批契约](../contract.md)及其继承的 spec。仅交付 toolkit，不修改后端、不新增自主重试或第二套状态机。

## Acceptance criteria

- [ ] 交付真实可加载的独立 node-chat 自动入口、声明和 report 工具，通过公共 Session 取得原生 sessionId 并实际请求后端，不依赖 connect-bot。
- [ ] 模型参数只有 body；报告标识、时间、来源、接收者和执行关联由后端产生并保留，不添加模型身份字段、地址业务校验或无依据的空字符串拒绝。
- [ ] 以独立正文样例验证真实提交；分别构造保存失败、保存成功但通知失败、诊断失败，准确呈现各项结果。
- [ ] 不把已保存报告描述成未提交，不因通知／诊断失败自动重报，不把报告成功描述成 node 已完成。
- [ ] 按既有机制建立实际需要的公共配置与请求处理，显式稳定定位配置；身份和资源按 Session 持有，common 不依赖角色，不复制私有客户端或后端状态机。
- [ ] 通过实际工具与必要真实后端对接验证，受控响应只证明确定性错误分支；运行所属分区、对应 real-host dock 及 TypeScript typecheck，补充节点使用说明。

## Coverage ownership

本票拥有 P15、P16 全部测试。它贡献 P1、P2、P3、P5、P6、P7、P8 所需节点实现；这些跨角色承诺的完整检查由 10 独占，不把基础机制推迟到验收票实现。公共 HTTP 取消由 01 扩展；本票不提前声称 P19–P25 已完成。
