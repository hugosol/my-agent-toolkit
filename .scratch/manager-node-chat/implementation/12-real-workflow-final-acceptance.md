## Acceptance criteria

- [ ] 在隔离的真实 omp、herdr-bot 及必要 Herdr、角色 Task、zone 与模型环境中验证，不操作用户现有对话或产物；记录版本、环境和必要配置，不以替身冒充真实执行。
- [ ] 事先约定 A、B 的独立产物与 C 的使用要求；实际观察 C 使用两份材料、管理者显式交接满足依赖并推进至 finish，至少一个前置节点报告后仍继续收尾。
- [ ] 保存工具结果、身份关联、产物使用证据和全部人工干预，不重新承接后端全部内部验收。
- [ ] 汇总各票证据，检查 29 条 promises 所有指定 coverage 均有负责人和结果；预期来自独立字面样例、人工推导小图或后端契约，不由被测实现重算。
- [ ] 执行实际双角色声明的静态集成命令、仓库统一最终测试入口及 typecheck，按真实宿主要求补充 smoke；记录命令、退出状态、源码／环境状态和失败。遵循共享工作树安静窗口与顺序协调，不以裸全量测试绕过调度。
- [ ] 完成所有实现、指定自动检查与证据准备后，再提交唯一 H1：用户综合评价实际指引、真实推进与故障处理、长期说明是否清楚可用。
- [ ] H1 反馈涉及的技术修正、文档修正及复验仍由 Agent 执行；用户不承担取消技术验证、公共兼容、静态检查或证据收集。
- [ ] 分别报告技术工作／自动检查完成与 H1 确认状态；H1 未确认不得声称全部验收通过。真实环境缺失如实标记执行阻塞并继续其他可执行工作，不以替身或空证据关闭。
