# 08: 不确定动作与错误结果保真

**What to build:** 已接受动作发生断线或错误时，调用者仍能区分不确定结果、已提交状态及外部效果；扩展不声称回滚、不自主重做，存活 Session 后续显式请求仍可使用。通过 S1、必要 S2 观察交付。

**Delivers:** P22、P23、P24

**Blocked by:** 05：批量派发与故障恢复；07：真实等待取消与终止原因

**Status:** ready-for-agent

依据：[获批契约](../contract.md)及其继承的 spec。仅交付 toolkit，不修改后端、不新增自主重试或第二套状态机。

## Acceptance criteria

- [ ] 分别在后端接受状态动作、派发、报告后断开调用方；取消反馈不声称未生效或已回滚，显式查询仍能观察已存在的后端事实。
- [ ] 非成功 HTTP 的结构化正文以及 HTTP 200 的 historyError、stateCommitted、逐项失败和外部效果对调用者可见，不压缩成状态码错误或笼统成功。
- [ ] 使用独立受控错误样例和真实后端对接结果；保留状态已提交但历史失败、部分派发效果及报告已保存但辅助失败的实际含义。
- [ ] 对网络失败、取消、正文错误、报告辅助失败记录有界请求次数，证明没有客户端自主重试、重报或伪造运行状态；明确观察窗口。
- [ ] 故障后仍存活 Session 的显式新调用正常可用，不复用已取消的生命周期状态；不把显式用户调用算成自动重试。
- [ ] 通过真实角色工具验证，运行所属分区、受影响消费者、对应 dock 和 TypeScript typecheck，更新错误与不确定副作用处置说明。

本票独占 P22、P23、P24 测试。03／05 的保存分项与目标分项测试分别证明业务结果结构，本票证明通用错误呈现与断线后的事实，不重复维护同一用例。
