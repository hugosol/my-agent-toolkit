## 范围与结论

本复盘仅依据指定 ticket 执行会话的 JSONL 历史及其中的工具结果，不包含父 session、其他票据或后续集成结果。本轮未修改文件、执行建议或重跑验收。

本票有有效的行为性 red → green：真实 OMP 请求中的 manager 指引缺少 `reconcile_dispatch`，测试在该断言失败；补全指引后通过。首次 `node_modules/yaml` 缺失则是环境失败，不能算行为性 red。执行者最终正确区分了两者。

历史记录的最终验收为 **16 pass、0 fail、320 次断言**，覆盖所属分区及对应 dock；`typecheck` 和 authoring 检查通过，提交为 `8444bfd`。这些是原执行结果，不是本轮复验。

以下建议按风险与收益排序；未发现可据此认定的阻断级产品缺陷。

## 1. 中高优先级：让真实宿主测试的静默窗口成为可确认的运行条件

**事实**：执行者向 Main 发出“请确认共享机器 dock quiet window”的协调消息，随后启动了多次真实宿主测试。本票可见历史未出现窗口获批或占用释放的回复。仓库 `docs/agents/testing.md` 已要求此类运行事先协调。

**风险推断**：通知已送达不等于已获得运行窗口。独立 worktree 能隔离源码，却不能隔离共享机器资源。自然语言协调缺少明确完成条件，容易让不同执行者对“现在能否运行”作出不同解释。

**建议**：由调度宿主提供机器级 dock 运行许可，包含持有者、适用范围和释放状态；测试启动入口在获得许可后再运行。优先把资源协调做成可观察的机制，而非继续增加“注意并发”的文字。若暂时保留消息协调，明确完成条件为收到确认，而不是消息发送成功。

**建议验收**：两个执行者同时申请时，只有一个能够进入受约束的运行区间；退出或异常结束后许可可释放。

**未验证**：本次是否确有并发测试、是否发生资源争用。测试通过不能反推没有争用，本复盘也不将其报告为已发生事故。

## 2. 中优先级：在 worktree 交付前完成依赖准备，保护 red 的含义

**事实**：首次运行新增 Prompt 测试时，复制 `node_modules/yaml` 失败，报 `ENOENT`。随后执行 `bun install --frozen-lockfile`，才进入真实 OMP 请求并得到缺失 `reconcile_dispatch` 的行为性失败。

**建议**：把锁定依赖安装与成功状态纳入 worktree 的准备流程。交付给 TDD 执行者时，提供简短的准备结果；失败时明确标为环境未就绪。无需在全局指令里再重复一套安装步骤。

**建议验收**：新建 worktree 的首个目标测试能够到达行为断言；准备失败、测试装配失败和产品行为失败在输出中可区分。

**应保留的做法**：本次没有把 `ENOENT` 充作 red，也没有为原本正确的 node 指引人为制造失败。这一判断应保留。

## 3. 中优先级：为 Prompt 测试提供文本块导航，并默认保留失败现场

**事实**：P27 最初把完整 provider 消息与后端提交正文作相等比较，得到“预期一条、实际零条”。随后保存并读取原始请求，发现 OMP 在同一用户消息中另加了原生 `system-reminder` 文本块。最终改为核对后端正文仍是一个逐字不变的文本块，并验证角色指引来自另一条消息，没有放宽正文完整性要求。

首次失败时未启用证据目录，为取得原始请求，又运行了一次相同失败场景。

**建议**：

- 在现有 dock 测试说明中增加一个分支明确的导航指针：涉及 Prompt、启动输入或消息边界时，先查看实际 provider 文本块与持久化贡献的读取示例。
- 为同类测试提供统一的原始消息／文本块读取方式，保留角色、消息和文本块边界；不要把宿主包装与业务正文先压平成一个字符串。
- 在失败路径自动保留最小现场，并输出路径；成功运行的完整归档仍可按需开启。

这属于测试环境和证据访问改进，不需要改变生产 Prompt，也不应通过忽略任意前后缀让断言通过。

**建议验收**：宿主新增独立提醒块不会被误判为业务正文变化；业务正文被改写或重复时仍失败；第一次失败即可查看对应请求，无需为取证再运行一次。

## 4. 中优先级：为确定不可用的语义搜索设置会话级降级路径

**事实**：本票两次 `find` 分别发起了 26 和 23 个 judge 请求，均因相同的区域限制返回 HTTP 451。工具已明确提示这不是“未找到”，执行者随后使用 literal 搜索继续推进。

**建议**：在工具路由层把这类确定性的提供方不可用状态记为会话级健康状态。后续语义搜索直接走已有可用替代路径，或简洁返回当前不可用原因；保留显式恢复入口。不要让每次新查询重新批量触发同一不可用提供方。

**建议验收**：首次确认不可用后，后续查询不再生成整批同类失败请求；降级结果继续区分“工具不可用”和“搜索无匹配”。

**边界**：本次成功使用 grep 恢复探索，未因此阻塞交付。改善点是重复无效调用，而非搜索结果正确性。

## 5. 中低优先级：由评审检查 Prompt 测试的语义与措辞耦合

**事实**：指引测试观察的是实际注入内容，而非源码常量，这是正确的 seam。后续也将宽泛关键词断言加强为具体职责断言。但若干正则同时固定了中文措辞和句内排列，例如要求 `recover`、参数名及“保留原执行和 Chat”按特定顺序出现在同一段中。

**风险推断**：含义不变的指引整理可能引发测试失败，进而使维护者保留偶然措辞。另一方面，脚本化 provider 的动作是预先指定的，演练成功本身不能证明模型因阅读指引而选择了正确动作。

**建议**：在现有评审流程中检查两件事：

1. 协议名称、字段、身份等需要精确的内容维持字面断言；自然语言说明的断言对应独立的职责与限制，而不无意锁定排版或表达顺序。
2. 每项证据标明证明范围：注入事实、工具行为、Agent 编排演练、真实模型决策及 H1 判断分别陈述。

这是需要判断的评审事项，不宜用新的语法禁令替代，也不建议另建模型评测平台来扩大本票范围。

**建议验收**：评审能指出每条自然语言断言要捕获的具体错误，并辨认同义改写造成的误报；受控演练结果不会被提升为真实模型使用质量结论。

**应保留的做法**：本次演练文件、README 和交付报告已明确标注受控 provider／Herdr、测试产物来源及 H1 未通过，不应把这一已做对的边界描述成漏验。

## 已有效的检查与不建议增加的规则

- 原会话读取的 `package.json` 已提供 `typecheck`，并串联 `check:authoring`。测试虽在 Bun 中通过，TypeScript 仍及时检出了三处 `readonly CapturedRequest[]` 的 `.at()` 不兼容，执行者随后修正并复验。**复用现有检查即可，不需要再写一条“禁止使用 `.at()`”的代理指令。**
- 根 `AGENTS.md` 主要是短导航指针，没有本次证据支持将其继续扩写成测试操作手册。
- 本轮未核验 CI 或 Git hooks 的实际接线，不能断言仓库没有自动守卫，也不据此建议再建一套重复检查。
- 最终证据写入独立目录并明确验证范围，值得保留；可改进的是失败现场从第一次运行起就可取得。

## 建议落点

优先改调度宿主与测试环境：**运行许可、依赖就绪、失败现场保留、不可用搜索降级**。仅在现有 dock 文档增加必要的分支导航；将 Prompt 语义与证据强度的判断留给评审。避免把这些改进全部转写为全局 `AGENTS.md` 中的长期负担。
