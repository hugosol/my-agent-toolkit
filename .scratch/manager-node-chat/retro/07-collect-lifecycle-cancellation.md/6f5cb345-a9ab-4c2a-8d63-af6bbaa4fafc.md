# Ticket 07 TDD 执行复盘建议

## 范围与结论

本复盘仅依据指定 ticket 执行日志 `07-collect-lifecycle-cancellationmd-b739e0db-3e1.jsonl`，截至提交 `96c8dc9` 和实现轮交付；未读取父 session 或其他执行日志。另只读查看了本仓库检查命令、测试指引及常见检查入口。本轮没有修改文件，也没有重跑验收。

**实际结果：**实现轮记录了 workflow-chat 分区 11 pass、相关真实宿主 dock 15 pass、framework 分区 725 pass，以及最终 typecheck 成功。真实宿主触发、双向 FIN、取消后报告收取均有输出。以下建议关注证据强度和执行环境，不把测试局限等同于已发现产品缺陷。

## 1. 高：将“存活变异”落实为对应承诺的证据边界

**事实：**执行轮先仅移除 `lifetime.signal`，保留工具 signal；真实 shutdown 用例仍通过。随后同时移除两个取消来源，abort 用例才在约 30031ms 后失败于 `<5000ms` 断言。恢复后最终 dock 全绿。票据记录诚实保留了这一区别，但最终交付摘要仅强调了后一个失败变异。

**推断：**目前的真实宿主用例能够发现“两条取消来源都未接通”，却没有单独证明 Session 生命周期来源不可被遗漏，因为 shutdown 同时可能触发工具取消。更大的变异失败，不能替代较小变异所暴露的覆盖缺口。这不证明当前连线错误。

**建议：**在 TDD 的现有“green 后检查敏感度”分支增加明确完成界限：**变异对应哪项承诺，就对该项记录 killed、survived 或不可隔离；存活变异不能由更大变异的失败替代。**优先在已批准的真实宿主 seam 寻找可以区分两个来源的情境；若宿主始终共同触发，则将连线审查证据与运行证据分开交付，而不是声称单一运行用例隔离了两个来源。此规则应归入按需加载的 TDD 参考，不增加全局 AGENTS 负担。

**验收建议：**读者能逐项判断“实际断线已证明”“具体取消来源经审查确认”“尚未独立隔离”三者，且不要求为已经满足的行为人为制造 red。

## 2. 高：让终止竞争测试区分“竞争发生”与“完成后再触发”

**事实：**`http-collect-termination.test.ts` 的 `deadline-then-abort` 在 `await pending` 返回后才调用 `caller.abort(reason)`；它证明了返回结果不会被后续操作改写，但没有让取消与期限同时作用于在途请求。`failure-then-abort` 同步调用断线与 abort，允许两种类别，本次输出采用的是 cancelled。

**推断：**“竞争覆盖”的名称和总结比部分情境实际证明的范围更宽。仅允许两个结果、校验错误对象身份，还不足以单独表明测试对“错误覆盖已采用原因”的变异敏感。

**建议：**由测试审查阶段逐项核对**触发—采用—返回**三个边界：已完成后再取消的用例按该行为命名；真正竞争的用例让两个触发都发生在请求完成前，并对预先指定的错误归因变异检查敏感度。若公共 seam 无法独立观察“采用”，明确这一限制，避免用固定 sleep 或全局优先级填补。保留当前“不预设取消总是优先”的正确约束。

**验收建议：**每个竞争用例说明它能排除的一个具体错误；测试名称与证据范围一致。该项属于语义判断，应交给测试 reviewer，而不是新增机械 lint 规则。

## 3. 中：把异步观察屏障前置，并让失败在观察预算内结束

**事实：**首次六文件 dock 已通过后，执行者才补上响应头写入回调门控，新增 `headers-forwarded` 观察，再次运行六文件 dock，约耗时 37 秒。另一次取消变异虽然要求五秒内释放，却先等待连接结束，直到约三十秒才执行时间断言。

**推断：**最初的设计说明没有把“后端产生响应头”“代理已转发响应头”“连接结束”拆成明确屏障；完成界限不够局部，导致较晚强化测试和重复昂贵验收。时间断言也没有形成紧凑的失败反馈。

**建议：**在真实宿主 dock 的现有测试参考中，把屏障检查收进设计步骤：每个“已经发生”的前置条件先指明由哪个事件确认，再触发下一动作。区分写入回调证明的转发完成与宿主应用层解析完成。为连接结束观察配置可清理的五秒等待界限，失败时输出已发生事件并释放资源，而不是等完整三十秒预算。

**验收建议：**缺少取消连线时，用例在观察预算附近失败；响应头门控在首次昂贵验收前已经建立。无需新增一套测试框架。
