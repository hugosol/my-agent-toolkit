## 1. 高：把“行为 red”设为可检查的实现前置门槛

### 事实

- 首次测试在 `JSON.parse(result.stdout)` 处报 `Unexpected EOF`，尚未观察到目标行为。
- 安装依赖后，18:48:15 的测试只显示“期望退出 0，实际退出 1”。执行者给断言补充报告信息后，没有先运行并检查诊断，而是开始修改生产分析逻辑。
- 18:49:39 的完整报告显示，两个 fixture 的 authored declaration 都缺少必需的 `create` 函数，诊断为 `demand/authoring/static-structure`。
- 18:49:47 才给 fixture 补上 `create`；此时双声明实现已经改动，随后测试通过。

**结论：**首个“双声明合法通过”场景的红灯混入了 fixture 错误。日志没有展示“合法 fixture 在原实现上因双声明缺陷失败”的独立运行证据。最终 green 不应倒推补齐这段历史。

### 建议

在现有 TDD 的 red 门槛处增加一个简短、可判定的证据格式，而不是再写一遍完整流程：

> 行为 red：记录实际诊断及其与目标违例的对应关系。若修正过依赖或 fixture，使用修正后的场景重新建立 red，再进入生产修改。

配套改善命令测试支持代码：进程启动、输出解析、业务断言分层报告；失败信息携带退出状态、stdout 和 stderr。对**预期合法**的声明 fixture，复用含完整 authoring 必需结构的构造方式，并增加合法性自检，避免每个测试重新手写字符串结构。

**完成判据：**缺少 `create` 或命令启动失败时，报告明确归为 setup/fixture failure；修正后，目标场景仍在未修复行为上失败，才计为 red。

## 2. 高：在 worktree 交付前完成锁定依赖准备

### 事实

本 worktree 没有 `node_modules`。`package.json` 将 `typescript-compiler` 声明为 `npm:typescript@5.9.3`，但当时 Bun 实际解析到了缓存中的同名 `typescript-compiler@1.4.1`，其导出不是预期 TypeScript API，导致 `ts.SyntaxKind.EqualsToken` 访问失败。执行 `bun install --frozen-lockfile` 后安装了正确依赖，后续命令恢复。

### 建议

将锁定依赖安装放到 worktree 启动器的准备步骤，而不是让各 ticket 的首个测试承担环境探测：

1. 在新 worktree 中执行锁定安装。
2. 将安装失败归类为环境准备失败，保留原始输出。
3. 准备成功后再将 worktree 交给实现代理。

这是可自动化的环境条件，优先放在启动器中，不扩充全局 `AGENTS.md`。若已有准备入口，应补齐其覆盖，而非另建一套。

**完成判据：**新 worktree 首次执行命令时即可解析到项目声明的 compiler alias；依赖缺失会在准备阶段暴露，不表现为 JSON 解析错误或业务 red。

**未验证：**日志只证明该 worktree 当时缺少本地依赖，未证明所有 ticket 启动路径都有同一缺陷。

## 3. 中：让独立审查检查“支持边界”是否被测试布局替代

### 事实

执行者选择按静态 import/export 依赖闭包归属角色源码，并在实现前通知主代理采用独立声明模块和角色装配，避免在同一源码文件混放两个 ID 的装配。新增合法样例也采用该布局。随后，为无法归属的 authored implementation 增加了明确失败诊断，修复了静默漏检风险。

### 推断与风险

票据要求处理“同业务目录内两个独立声明”，但未在票据中固定这套模块布局。依赖闭包是合理的内部方案，却也可能影响检查器接受哪些原本合法的源码组织。仅凭本次样例通过，尚不能证明这些边界均与承诺一致。

### 建议

将这类问题交给独立 reviewer 做判断性审查，而非制定机械的文件名规则：

> 当静态分析器新增源码归属规则时，对照契约检查其支持边界；区分内部实现选择与新增的调用者组织约束。

审查应重点核对独立声明、共享实现依赖及汇总装配之间的关系。对声称支持的组织形式，使用真实命令给出独立样例；对无法确定的形式，明确诊断与文档边界，并核对其是否需要接受方确认。

**完成判据：**合法组织集合有明确依据，测试覆盖的是这个集合，而不只是实现算法最容易识别的一种布局。

**未验证：**本复盘没有运行其他布局，也没有独立 review 结果；这里是边界审查建议，不是已确认的产品缺陷或 reviewer 漏检。
