# Contract — manager-chat 与 node-chat 自动角色扩展

Source: [Spec](spec.md)
Acceptance mode: Rapid iteration
Approval: approved

## Approval and inheritance

用户依序明确批准：三个 seams 与非运行审查例外；六类表面审查方向及必要推论；Rapid iteration 与所提一项人工最终使用判断。前两关均以“同意”确认，第三关选择“Rapid iteration”。这表示契约获批，不表示产品实现、自动检查或人工验收已经完成。

继承 spec 的 Implementation Decisions、Out of Scope、领域词汇和相关 ADR：仅开发 toolkit；两个独立 omp auto 角色扩展；后端实际协议与运行事实为权威；公共 Session、Prompt、HTTP 与稳定配置；不复制后端状态机、不自主重试、不增加手动模式或 pi 角色扩展。已批准事实不重新决策。

**Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

## Promises

Source 中 story 编号均指 [spec 的 User Stories](spec.md#user-stories)。除 Coverage 明确保留的人工最终判断 H1 外，检查与证据准备均由 Agent 负责。H1 是一项跨指引、实际运行与使用说明的整体使用判断，分别在 P26、P28、P29 标明其相关部分，不是三项独立例外。

预期结果来自已批准承诺、独立字面样例、人工推导的小图和后端契约，不通过被测实现重算。受控响应可验证确定性错误处理，但不能证明真实宿主生命周期或真实模型行为。完成状态由交付工作和全部指定检查推导，不维护 promise 状态列；后续 /to-tickets 以 P 编号建立交付映射。

### 非运行审查例外与拒绝理由

- P5 依赖方向和职责分工需要架构/依赖审查，不能以运行输出证明。
- P29 的纯文档完整性需要内容与链接审查；实际指引注入和演练仍由 S1 承担。
- 用户已批准上述例外。不将文档或私有模块硬凑成第四个 seam，也不因此免除检查。
- 拒绝“仅 S1”：它不能同时证明公共 HTTP 其他消费者兼容，以及静态检查未漏检。
- 不另设后端 seam：本次不修改后端；它作为 S1 的 Remote but owned 依赖供真实对接观察，不据此承接后端全部内部验收。

### Dependencies and implementation freedom

- **In-process**：角色动作选择、参数整理与结果呈现；通过调用者 interface 观察，不发布私有测试入口。
- **Local-substitutable**：配置与隔离文件、可控本机 HTTP 故障条件；用于稳定构造失败和传输时序，不替代真实宿主事实。
- **Remote but owned**：herdr-bot 的 HTTP interface。通过已有公共传输使用真实对接与受控响应两种条件，不复制后端业务规则或另建无必要的业务 port。
- **True external**：实际宿主和模型提供方的不受本扩展控制行为。受控 dock/provider 可验证确定性接入，不能冒充真实模型的工作结果。

三个 seams 均复用既有 interface 位置，新增角色工具、多声明处理和调用方取消不是新建私有 seams 的理由。公共 HTTP 调用方取消是必要的 interface 扩展，其所有受影响公开消费者须同步适配；不预先规定内部算法。若实施证据推翻 seam 假设，先修订本契约再调整票据；只有出现难逆、无上下文令人意外且确有真实取舍的决定才另评估 ADR。

## Not yet specified

- **阻塞批准的决定：无。** 三个 gates 均已获得明确确认。
- **后续实施精度：** 配置键名、公共取消类型的具体拼写、检查命令针对双声明的精确选择形式及最终测试命令/宿主版本，沿现有机制整理。必须在相关调用者交付前一致，不得改变本契约保证；若发现新行为或兼容冲突，先修订契约。
- **未来 seam 未知项：无已识别项。** 不预先为未批准的宿主、身份重绑定或平台能力切片。
